# 流程配置

`workflows/china-indonesia.json` 是默认演示清单。服务启动会读取并校验它；格式不合法时明确报错，不会静默套用另一份流程。可通过根目录 `.env` 的 `TEA_TEMPLATE_FILE` 指定其他 JSON 文件，修改文件后重启服务。

法务人员也可以直接在页面的“法务工作台”中导入文件、修改表单、调试并发布。发布版本在当前账号下保存；该账号后续的新业务优先使用已发布版本。已有业务始终使用创建时的快照。文件修改不会覆盖已发布版本。

- `modes` 定义模式名称与说明；模式 A/B 尚待业务确认。
- `stages` 按顺序执行，每项以 `actor` 指定面向主体；`tasks` 可并行办理。
- `fields` 定义资料字段，`required`、数值 `min`、`require_document` 与 `require_confirmation` 定义完成条件。
- 文稿 `output_template` 使用双花括号，例如 `{{product_name}}`，读取当前业务的字段值。
- `agent` 配置输出语言、指导要求、检索数量及启用的助手步骤。界面展示的是操作摘要与证据，不是模型内部推理。

示例任务仅用于验证系统交互；正式法务手续、面向的机构、两种模式的差异应由实际业务清单替换。
