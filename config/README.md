# 仓库配置

此目录保存随 Git 管理的业务配置默认值：`workflows/` 为办理流程，`collection-plans/` 为版本化法律采集要求，`collection-sources/` 为热更新来源清单，`collection-selections/` 为有界采集范围，`collection-proxy.json` 为采集代理的精确域名白名单，`verification/` 为验证规则。私有代理凭据保存在实例的 `data/config/application.env`，不写入本目录。新增或更换采集来源时，同步核对代理白名单；未允许的域名会失败，不会直连。MinerU 返回的解析结果由 `cdn-mineru.openxlab.org.cn` 提供，该域名也必须保留在白名单中。

`TEA_CONFIG_DIR` 可指定唯一活动配置根；完整实例恢复默认使用其 `data/config/catalogs/` 快照。修改前运行 `make instance-paths` 查看生效位置，详见 [实例管理](../docs/INSTANCE_MANAGEMENT.md)。

`legal-source-metadata.json` 保存已核对原文的资料身份修正及跨法域版本关系，按国家和资料包文献标识匹配，可用原件哈希限定修正范围。每项关系保留原文记录、条号、日期和哈希；不记录问答结论，也不改变资料审核状态。资料包索引与该文件共同决定运行时的来源身份及适用时期，验收指纹需包含两者。

管理员可在“系统管理 → API 配置”（`/tea/admin/api`）维护实例的模型与解析凭据，保存、生效与覆盖规则见 [后台 API 配置](../docs/INSTANCE_MANAGEMENT.md#后台-api-配置)。本目录不保存这些私有值。

## Agent 调度与记忆

节点会话使用一个主 Agent，直接取证、分析并回答，常用工具参数直接提供，短方法文档按需读取。普通聊天移除强制 Task Brief、法律子报告和第二次润色。`agent-skills/<id>/SKILL.md` 保存方法，`agent_skills.py` 登记简介与关联工具。`AGENT_MODEL` 示例为 `Nemotron-3.5`，地址和密钥可继承 `LLM_*`。调用预算、证据快照、MCP、记忆和 `TEA_BACKGROUND_WORKERS=external` 独立后台进程统一维护在 [Agent 运行机制](../docs/AGENT_RUNTIME.md)。识图的 Sub2API 配置和额度见 [文档处理](../docs/INGESTION.md)。

合同审查使用 [`contract_review`](agent-skills/contract_review/SKILL.md) 技能，按用户立场提供条款风险、替换文字和谈判备选方案。技能由主 Agent 按需加载，资料读取、法律取证和文稿保存复用现有工具，调用与权限说明见 [Agent 运行机制](../docs/AGENT_RUNTIME.md#法律证据操作与按需方法)。

[`draft`](agent-skills/draft/SKILL.md) 技能采用用户提供的 /legal-writing 方法，支持完整文书起草、原稿改写、写作反馈和依据核对，保留原文稿入口。技能全文按需加载，正文交付与在工作台保存分别处理，详细规则见同一运行机制文档。

## 流程配置

`workflows/liubao-export.json` 提供印尼／新加坡 × 线上／线下四条六堡茶路线，复用 58 项任务定义。新建业务及后台默认选择印尼线上路线，详情见 [六堡茶流程说明](../docs/LIUBAO_WORKFLOWS.md)。服务启动读取并校验配置，格式不合法时明确报错。`TEA_TEMPLATE_FILE` 可指定后台导出的单条模板，覆盖四条路线中的同编号配置；留空加载内置配置，修改后重启服务。旧 `.env` 中指向已删除的 `config/workflows/china-indonesia.json` 会按明确的退役兼容规则使用六堡茶默认路线，不恢复旧模板。

法务人员也可以直接在页面的“管理后台”中导入文件、修改表单、调试并发布。发布版本在当前账号下保存；该账号后续的新业务优先使用已发布版本。已有业务始终使用创建时的快照。文件修改不会覆盖已发布版本。

后台的“办理流程”和“节点分析”使用同一份草稿：前者配置阶段、任务与完成条件，后者配置进入每个阶段时执行的分析步骤。保存草稿可以保留未填完的内容，发布前必须校验通过；保存和发布均检查修订号，过期页面不能覆盖较新的配置。

- `modes` 定义模式名称与说明，按线上或线下渠道命名。具体销售／进口分支通过路线卡和适用性核验确定。
- `stages` 按顺序执行，每项以 `actor` 指定面向主体；`tasks` 可并行办理。
- `tasks[].blocks_next_stage` 默认 `true`。设为 `false` 的必办任务允许与后续阶段并行，未完成时该阶段显示“待收尾”，整项业务仍不能结案。六堡茶线下的 E08 展品核销采用此设置；不是跳过核验或变为选办。
- `fields` 定义资料字段，`required`、数值 `min`、`require_document` 与 `require_confirmation` 定义完成条件。
- 单选字段 `type: "select"` 的 `options` 是可保存选项，`accepted_values` 是可通过核验的子集；设置通过值的字段必须必填。等待、待核验或异常状态不会因填入文本而通过。
- 文稿 `output_template` 使用双花括号，例如 `{{product_name}}`，读取当前业务的字段值。
- `agent` 配置输出语言、指导要求、检索数量及启用的助手步骤。界面展示的是操作摘要与证据，不是模型内部推理。
- `stages[].analysis` 为节点单独配置分析步骤；不填写或设为 `null` 时继承 `agent`。步骤编号在各自工作流中不可重复，至少启用一个步骤。
- `steps[].instructions` 为可选步骤说明。查找资料步骤将它作为检索关注点，生成指导步骤将它交给已配置的模型；字段检查仍执行服务端规则，文字说明不会自动增加核验规则。未配置模型时明确使用规则演示。
- 分析按步骤顺序执行：指导只能使用前面已经检查或检索到的结果。调试时可填写当前节点各任务的样例字段，并指定运行到某一步；这不会修改实际业务。起草、核验步骤提示实际操作入口，不会自动确认办理完成。

进入已解锁节点时，系统保存针对当前资料的分析结果。同一份资料重访时复用结果；材料、事实、审核状态等变化后重新分析。分析期间资料变化会要求重新运行；模型失败会展示错误并提供重试，不影响任务进度。

六堡茶路线是按手册形成的业务配置，所涉法规适用与办理证据仍需实质核验。旧 `china-indonesia-demo` 模板、草稿与业务已从可办理入口下线，旧编号不可重新发布；原始数据库记录和文件不在启动时清空。其他账号已发布版本与业务快照继续保留。
