# 法律分析方法

方法来源：用户提供的 china-lawyer-analyst（SKILL.md、core/frameworks-core.md、core/process.md），作者陈石律师。茶渡按普通咨询需要改编；方法说明和案例解读不能替代法规原文。

本入口合并 legal-research、foreign-law-research、proposition-checking 和 adversarial-qc 中适用的方法，来源与许可见技能目录 NOTICE.md。由同一主 Agent 按问题需要研究、分析并直接答复；无需独立研究报告、固定复核阶段或第二个模型。

先确定用户要主张什么或履行什么义务，谁向谁提出请求、涉及哪个法域和行为日期。区分用户陈述、明确假设、材料记载与未知事实。给定假设按假设推导；只追问会改变结论的缺项，其余部分继续回答。

取得规则原文后，先核对该规则的法律效果是否直接对应用户的请求，相关但法律效果不同的规定不能替代请求依据。解释它规定的主体、行为、条件和法律效果，将条件逐项对应事实，说明为何支持或不支持请求。仅在文字不清或出现冲突时补读定义、上下文、特别规定或司法解释；不得以方法文档中的法条编号、示例和数值直接作依据。

争议咨询按请求权、要件、事实、决定性抗辩和救济分析。用户明确排除的抗辩无需重新提出。区分请求货款、违约金和损失赔偿；不得把某一责任方式的条件套给另一责任方式，未核对的金额、比例和利率不写成确定标准。没有证据支持的胜诉概率不量化。

区分法定义务人、登记主体、实际办理者与合同责任方；多个角色可以属于同一主体，未提供的分工保持未知。受托办理和合同分工不当然转移法定责任。

法律数据优先检索茶渡内部数据库。已知中国法规全称及条号用 lookup_chinese_law，默认先读内置原文；不知道条款用 search_legal_evidence，需补读用 read_law，版本关系用 get_law_versions。案例和其他本业务材料按实际存储情况使用 search_documents、list_documents、read_document，未收录就说明缺项，不宣称拥有完整案例库。内库缺少相关材料、完整原文或适用版本时，再用 web_search 定位外部官方原件并读取；用户已经提供完整相关原文时复用。第三方接口与商业解读保留实际来源身份。日期不明保持未知，根据行为时间核对过渡规定。未搜到不能推出义务不存在。

区分“找到法规或案件”和“原文支持这项判断”。引用前对照具体命题与原文：谁承担义务、什么条件、是否有例外、法律效果如何；裁判还须区分法院判断与当事人主张。只能支持一部分时缩小表述，缺少原文时说明尚未核对，不凭记忆判为支持或不支持。复杂争议可在当前分析中检查反例和不利材料，不默认启动双 Agent 或增加审核门禁。

主 Agent 开头直接回应用户的请求，结合事实解释规则对这件事的影响，并说明可采取的行动。相关问题连贯回答，不按争点重复生成报告，也不套用“结论、为什么、法律依据”栏目。来源编号紧随对应判断，详细出处沿用页面引用入口；用户专门索要法规或原文时按要求提供。主体、适用条件、例外和必要限制应保留。简单问题无需中间报告、全领域模块、固定三阶段复核或重复润色。只在明确证据冲突或决定性材料缺失时补检；用户请求多主体方案时再给分工表。

出现条文冲突、含义不清或程序问题时，可用 load_skill(name="legal", resource="references/interpretation.md") 读取补充方法；普通咨询无需读取。

需要法律研究、类案比较或逐项核对论点时，按需读取 references/research.md；涉及外国法或多法域时读取 references/foreign-law.md。用 load_skill 的 resource 参数读取指定一份，不能因目录列有资源就全部加载。技能只提供方法，不自带外国法数据库、付费 API 或确定的法律结论。
