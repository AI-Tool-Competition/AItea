## 条目结构

- `chapters` 保留原章号、章名和治理规则；`items` 保留原项号。1.11、2.5、3.5、4.8、5.5 是章末检索规则，已并入章说明，不另计采集任务。
- `entries` 区分目录、详情、原件及参考用途。印尼共 36 个原文链接，其中 1.7 的第 3 个、1.9 的第 2 个、4.7 的第 2 个是示范详情，标为 `reference`，不得自动作为执行种子。其余 33 个均是目录或导航入口，不能作为法规正文入库。
- `scope_include`、`scope_exclude`、`steps`、`fields`、`version_rules`、`relation_rules`、`acceptance` 是从原要求整理的工作边界。`verbatim_requirements` 保留本项原始文字，供复核和修订时回查。
- `tags` 使用稳定的国家、条目、文种和主题标记，例如 `country:ID`、`checklist:ID-3.3`、`kind:case`、`topic:MA HUM`。标签不决定法律效力，也不能代替法规的国家隔离。
- `priority` 是执行顺序，不代表法律位阶或一二级资料等级。`limits` 描述业务范围，单批并发和队列上限由采集服务控制；达到单批上限不表示全量采集完成。

## 执行和核验边界

预置方案提供采集范围和可审查的发现入口。`adapter` 选择目录发现方式，不能证明某站当前可访问，也不能把 URL 匹配结果视为内容或法效审核通过。动态页面、登录、人机验证、访问限制、解析失败、附件缺失和无可用链接都应显示明确缺口。不得保存错误页、拒绝页、验证页或空框架冒充法律正文。

候选文件须核对文书身份、内容范围、原件、适用期间及法律状态后再作为依据。章号和法律效力不决定一级／二级：指定主资料为一级，其有原文证据的引用或关联资料为二级。`relation_rules` 只是待核映射要求，不能自动创建不存在的父资料或断定修订、失效。引用关系、法规生命周期关系、条约批准／实施关系须分别保留。

国家边界使用 `country:ID`；计划标识和章节只用于该国家内的任务管理。新增国家应使用独立 `country` 和独立方案，并通过后端隔离规则限制目录、资料、关系和检索，不能仅靠来源标签混用法域。

目录发现、详情登记、原件取得、附件齐全、正文解析、范围审核、效力核验和索引分别验收。默认来源和法规状态均待核；全量目录不等于全量正文，更不等于全部已核有效法规。新版本追加保存，不能覆盖旧版；同一原件跨任务去重并保留各入口与来源关系。
