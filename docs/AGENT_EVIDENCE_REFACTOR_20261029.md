## 实现与边界

普通会话由一个主模型读取事实和证据，完成分析并直接生成答复。法律工具保留 `search_legal_evidence`、`read_law`、`get_law_versions`，不再调用法律子模型生成完整报告。常用证据与业务工具直接提供，技能方法和长尾工具按需读取。强制 Task Brief、专业报告路由、报告转换及常规第二次润色退出普通问答。历史报告读取、节点分析及人工研究入口保留原协议。

代码规模以本轮开始时的工作树备份比较，未使用 HEAD 总差异：

| 文件 | 本轮开始 | 当前 | 变化 |
| --- | ---: | ---: | ---: |
| `agent_loop.py` | 1073行 | 605行 | 减少468行 |
| `agent_tools.py` | 1108行 | 980行 | 减少128行 |
| `execution_plan.py` | 312行 | 40行 | 减少272行 |

另删除普通会话的343行 Task Brief 模块。新增原文引用呈现、版本读取及独立 worker 入口，未删除历史研究引擎。以上行数仅描述实现规模，不代表准确率提升。

执行器以两次模型调用为普通题设计目标，允许一轮有理由的补检及一次输出格式修复。独立只读工具最多四项并发；有效输入相同的请求复用收据。业务归属、修订检查、材料核对、文稿与记忆提交继续复用原确定性服务和事务。模型临时主体推断及分析计划不升级为业务事实。

证据结果保留原文、出处、定位、版本日期及已知替代关系。未知日期保持未知。相关原文附带同文档、同法域、同内容版本的相邻单元，保留例外；超出预算时省略完整单元并提供收据回查，不保留截断条文作为摘要。底层长文读取仍有长度限制，`context_complete=false` 继续表示未取得完整正文。网站标题、规范名称及草案识别仍有数据质量缺陷，不能因工具返回成功推定材料适用。

`agent_runs` 与工具收据保存本次输入、实际送入模型的证据、正文及引用关联、调用、耗时、错误和用量。取消或超时前已取得的证据与已报告的用量也保存；供应商未报告的用量保持未知。程序检查空输出、引用编号和未执行工具协议文本，最多请求一次格式修复；没有通过时返回 `execution_failed`。程序没有新增法律审核模型，也不自动改写法律含义。

聊天 API 默认使用 `TEA_BACKGROUND_WORKERS=external`。下载、解析、向量化及官方导入可由 `scripts/run_workers.py` 独立运行，复用持久队列、租约和并发限制。当前没有启动真实采集及导入 worker；已有索引继续可读。配置、预算、启动命令及 MCP 边界统一见 [Agent 运行说明](AGENT_RUNTIME.md)。

## 真实模型结果
