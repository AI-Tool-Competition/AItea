## 已实现的行为

`execution_plan.py` 复用现有 Task Brief，生成校验后的执行计划。程序校验任务类型、交付目标、必需能力、法域、编号与依赖；法律判断不能按 `general` 执行。初始模型请求仅开放并指定 `update_task_brief`。规划阶段的正文和未经校验的专业调用均不能交付。规划阶段耗时到限或两次失败时，使用原请求和用户历史生成保守计划，并保存回退记录。

能力映射直接执行法律分析、法律资料检索及业务检索。法规查询依据真实检索记录继续读取原文；法律判断直接调用 `analyze_legal`，无须模型猜测工具名称。每次工具调用保存实际参数、执行状态、错误和新增来源数量。工具发现与 SOP 加载不计业务进展；发现默认最多两次，空发现不能推动交付。马来西亚等暂未覆盖法域保留实际国家代码，不能替换为业务模板中的中国或印尼；缺少法域时记录需补充信息，独立商业调研仍可完成。

`agent_loop.py` 通过唯一 `finalize_answer` 出口保存正文。最终整理使用实际工具结果、来源与失败记录；规划正文不能绕过整合，未知来源编号不能被接受。法律服务返回失败及部分材料时，将调用记录为失败；已完成且有引用的局部判断继续保留。服务保存并向内部适配器传递安全的失败类型及 HTTP 状态，不传递异常原文、供应商响应正文或请求凭据。缺少具体失败类型时使用 `analysis_incomplete`。公开法律分析接口继续采用原有失败响应。

交付状态区分 `answered`、`partially_answered`、`needs_user_input`、`execution_failed` 和 `unsupported_jurisdiction`。模型返回正文、工具完成或 SSE 返回 `done` 都不能单独证明任务完成。整合失败且没有可交付内容时记录执行失败；法律子任务失败时，可保留有材料支持的独立商业答复。失败交付不提交暂存文稿或记忆。界面展示状态并支持对已保存失败结果重新请求，保留输入草稿；Agent 整合正文优先于旧引导报告快照。

预算默认值为整轮 90 秒、规划 8 秒、普通请求 15 秒、最终预留 15 秒、法律工具 60 秒、额外重试最多一次。每次请求取配置上限与实际剩余时间的较小值，后续规划请求另受规划阶段剩余时间限制。HTTP 传输执行实际截止时间。502、503、504 及可确认的连接建立失败可有界重试，429 遵守服务端等待时间；等待超过剩余预算便停止。权限、参数及输出已开始后的未知请求不自动重发。权威配置说明见 [Agent 运行机制](AGENT_RUNTIME.md#执行边界与持久记录)。

法律条件沿用原有事实与义务记录，增加事实原话来源和依据、事实状态。生产工厂身份不能自动证明从事种植；合同责任方需有来源支持的约定关系；办理人和法定义务人继续分别记录。未获得依据不能推导制度不存在。主 Agent 读取既有义务的只读主张投影，没有新增独立主张数据库或人工审核门禁。这些检查只能验证来源对应、事实引用和部分主体关系，不能代替法律解释质量评阅。

这轮还暴露一个时限边界：D01、D03 的法律服务已保存 `analysis_budget` 原因，外层工具在接收失败结果后再次检查本工具截止时间，将其覆盖成普通 `timeout`，使部分失败详情没有进入主 Agent 收据。后续只修正这一边界及失败文案：明确返回失败及部分结果时，保留原始失败收据，继续检查用户取消与整轮时限；晚到的成功结果仍按超时拒绝。没有延长法律预算或将失败改为成功。相应受控回归覆盖这两种情况。

最后针对这一边界单独真实复测 D03，耗时 83.232 秒，最终仍为 `execution_failed`。主 Agent 的失败收据已保留法律服务实际返回的 `failure={code:timeout,http_status:null}`、12 条新增来源的计数和失败材料；调用状态为 `failed`，没有再次丢失返回详情。该复测验证失败收据保留，未通过法律问答验收。没有继续重复运行相同的六题。
