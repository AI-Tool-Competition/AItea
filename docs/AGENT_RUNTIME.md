# Agent 问答、证据与业务服务

带 `conversation_id` 的在线节点聊天使用一个主 Agent：理解当前问题，读取事实和法律原文，完成分析并直接生成答复。法律证据工具不调用法律子模型，不生成独立报告。普通会话没有强制 Task Brief、确定性专业报告路由或最终润色模型。历史法律报告、节点分析和人工研究入口保持原协议；旧报告结构停止扩展。

## 问答执行

常用工具直接提供参数定义：`update_business_card`、`lookup_chinese_law`、`search_legal_evidence`、`read_law`、`get_law_versions`、`search_documents`、`list_documents`、`read_document`、`check_materials`、`web_search`、`draft_document`、`load_skill`、`tool_search`、`read_tool_result`。当前节点指导、交接、显式记忆、识图及操作计划按需发现。`load_skill` 按需读取方法文档，发现结果只表示加载能力，不表示查过资料。`update_plan` 只记录操作步骤，不改变业务任务。

普通咨询以两次主模型调用为目标：第一轮请求资料，下一轮根据原文直接回答。完整原文已在用户消息中时允许一次回答。主模型可针对决定性缺项或证据冲突补充一轮取证；两轮实际成功执行的工具请求后停止搜索。参数错误有单独的两轮修正上限，不消耗有效取证次数。搜索成功但无结果仍计一次，可补检；两轮后尚有未读的搜索摘要时，仅允许再用 `read_law` 或 `read_tool_result` 读取已找到的原文。工具发现不计为取证，有独立次数限制；已复用的相同结果不算新增进展。循环至多六轮，均受总预算约束。文稿等业务操作按依赖顺序执行，独立只读请求最多四项并发。

工具调用轮次中的正文只保留在当前执行上下文；无工具请求的模型正文直接经过机械检查和引用呈现后保存。没有常规第二次整理或运行时法律审核门禁。空输出、未执行的工具协议文本或供应商确认的长度截断允许一次有限修复，保留已有证据；未知网络结果不作为可重放生成。修复仍失败就保留输入、证据和错误，返回明确失败。未知引用编号只在对应位置显示缺少原文链接，并将交付记为部分完成，不触发再次生成或丢弃整份正文。正文中的工具协议不能触发工具执行。程序不自动修改法律结论、主体、例外或适用条件。

主 Agent 按用户的实际问题组织正文。开头直接给整体判断或推荐，多个相关问题合并说明，覆盖用户的各项请求；后文按经营选择、关联事项或办理顺序展开，在对应内容里解释理由和行动。自然段为常用形式，比较、分工和顺序需要时使用表格、列表或简短标题，不要求固定段数、字数或“结论、为什么、法律依据”栏目。主体、条件、例外及未查明事项应保留；来源编号放在对应判断旁，详细出处沿用消息末尾的引用入口，正文不重复依据清单。用户专门请求法规、完整原文或官方出处时，直接交付所要资料。这些要求作用于同一主模型，无新增润色调用或自动删改正文。

主模型读取当前问题、服务端业务事实、相关用户笔记及有来源的近期讨论。普通问答不恢复上一轮完整工具会话和供应商思考签名，不保存临时主体图、法律草稿或任务计划为长期业务事实。历史上下文表保留读取兼容，不删除既有记录。

## 法律证据操作与按需方法

`lookup_chinese_law` 接收法规标准全称、最多四个条号及可选 `source=auto|api`，直接取得同名同条正文。默认先读内置中国法库，只对缺项访问用户提供的 chinese-law-verifier 公益接口；不调用向量或重排序模型。阿拉伯条号转换为中文条号，新增“之一”等条号保持独立身份，不误读基础条款。指定 `source=api` 时明确核对第三方接口，失败仍保留内置原文。外部请求最多四项并发，共用六秒截止时间；只发送法规名称与条号，不发送当事人或交易事实。接口文本标明第三方身份，未提供的效力日期和修订关系保持未知。来源、改编方法及真实验证见 [中国法技能接入记录](CHINESE_LAW_INTEGRATION_20261029.md)。

`search_legal_evidence` 按法域、问题和可选 `as_of` 日期查询已有索引，复用精确法名、条号、版本排序及语义召回。取得本地记录后读取可用完整单元，附带有限的明确援引条款。其职责是返回材料，不判断当事人必须办理什么。没有命中时主 Agent 可用 `web_search` 定位官方原文，再用 `read_law` 读取。

检索命中的完整条文按原排序先返回，再附援引与相邻条文；补充上下文不能覆盖直接命中记录的身份。原文所属编、章、节以 `locator.headings` 提供，附原件内标题记录编号，不根据模型推测补写。重排序输入也保留这些标题；补读完整原文保留实际召回方式。部分条款索引的使用和排序限制见[资料库说明](COUNTRY_LEGAL_LIBRARY.md)，诊断与法律解释评阅分别记录，见[研究及复测](LEGAL_RETRIEVAL_RESEARCH_20261029.md)。

`read_law` 接收真实 `record_id` 或官方 HTTPS 地址，返回原文、中文整理身份、出处、条款位置、不可变版本和可取得的适用时间信息。保留来源中的定义、范围和例外；`context_complete=false` 表示原文单元尚未完整提供。工具结果超出上下文预算时按完整记录省略，使用 `read_tool_result` 分页读取已有收据，不在条文中间截字后当成完整依据。网络页面继续复用公网地址、重定向、体积和截止时间限制；官方 PDF 未解析时报告具体缺口。

`get_law_versions` 按已返回的法域及记录编号读取已有公布、修订、施行、失效日期和修改替代关系。未查明日期为 `null`，空关系不证明不存在后续修法。入库状态、引用编号存在和来源链接可打开，都不能单独证明条文支持某项判断或现行有效。

工具受当前账号、业务与允许法域约束。没有本地法域能力时不会替换为模板国家；可使用公开搜索取得线索，具体能力限制由答复说明。搜索摘要保持线索身份。主模型依据已取得原文进行规范解释、事实对应和法律效果分析，法律质量通过独立题集评阅。

`legal` 技能吸收 china-lawyer-analyst 的规则解释、请求权及事实对应方法，保持简短且按需读取。用户的明确假设直接用于推导，材料能否证明与法律上能否主张分开。法定义务主体、实际办理者、登记主体和合同分工分别判断。方法文档中的法条及数值示例不能作为法律依据；不默认加载全领域模块、三阶段报告或第二个法律模型。

`contract_review` 是合同审查技能，改编自用户提供的 contract-review 1.0.0，入口为 [技能文档](../config/agent-skills/contract_review/SKILL.md)。主 Agent 平时只取得技能简介，调用 `load_skill(name="contract_review")` 后读取全文及可用的关联工具。该技能按用户立场和已有谈判底线审查合同，检查条款联动、主体分工和风险，提供可替换条文、备选方案及谈判理由；履行争议沿用请求权与事实对应方法。未提供的合同约定保持未知，示例比例和外国法要求不作通用标准。合同、附件和相关法律原文由现有资料与证据工具读取，审查后由同一主 Agent 直接回答；用户要求保存文稿时使用既有 `draft_document`。MCP 加载仅返回其已开放的关联工具，不新增文稿写入权限。

`draft` 技能吸收用户提供的 /legal-writing，扩充为 [法律文书起草与改写](../config/agent-skills/draft/SKILL.md)，保留原调用标识和现有文稿接口。主 Agent 按需加载方法，区分完整起草、原稿改写、写作反馈与为文书开展的依据核对；仅咨询法律结论和合同风险审查时分别使用已有 `legal`、`contract_review` 方法。正文由同一主 Agent 生成，资料和法规通过现有工具读取；用户要求成稿时交付完整正文，缺项和实质变动在稿外说明，不读取学生档案或保存学习记录，也不新增报告、审核或润色模型。要求在工作台保存时使用 `draft_document` 及真实节点任务编号，仍受现有授权、长度和事务限制；仅加载技能不创建文稿，MCP 不开放文稿写入。

模型投影视图保留完整条文，去除索引统计等操作元数据，同版本日期、修改关系与发布机关等重复信息仅提供一次，其他条款关联首条版本信息。完整证据快照和原收据继续保存。网页搜索的编号、引用与搜索摘要身份贯通模型输入及链接展示。

## 保存、预算与业务事务

`agent_runs` 与 `agent_tool_receipts` 复用现有 SQLite 请求领取、租约和幂等约束。保存原问题与业务事实来源、实际进入模型的证据快照、最终正文与所选引用关联，以及工具输入、耗时、错误、用量和请求编号。候选材料留在工具收据中；未被答复选用的候选不自动附为答复依据。临时计划不成为业务记录。模型请求和工具原始结果在业务写事务外执行。

`_task_state.executor=evidence_qa` 标识当前执行器，记录真实调用和 `model_calls`。`answered` 表示模型正文生成并通过输出完整性等机械检查；它不证明答复完整、法律解释正确或通过业务验收。`partially_answered` 表示本轮出现工具失败、空检索、缺失引用或仅保留了可用来源。模型后续生成失败且已经取得可用链接时，程序直接交付来源和具体失败说明，清空尚未提交的文稿、记忆和业务卡更新，不追加模型调用。没有可用结果的模型或输出完整性失败记录 `execution_failed`，HTTP/SSE 返回失败事件；`done` 仅表示答复保存结束。已有历史状态仍可读取。

默认预算基于此前 Nemotron/high 在 8 秒规划和 15 秒整理中连续超时的记录调整，用于测量精简执行器，并非演示速度承诺：

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `AGENT_BUDGET_TOTAL` | 180 秒 | 整轮截止时间 |
| `AGENT_BUDGET_MODEL` | 75 秒 | 每次主模型请求（含允许的重试） |
| `AGENT_BUDGET_EVIDENCE` | 45 秒 | 单项工具执行上限，另受实际剩余时间约束 |
| `AGENT_BUDGET_ANSWER_RESERVE` | 60 秒 | 取证时为答复保留的时间 |
| `AGENT_BUDGET_RETRIES` | 1 | 暂时性供应商错误最多重试一次 |
| `AGENT_BUDGET_DISCOVERY` | 2 | 按需加载或发现的次数上限 |

两轮取证及一次有限修复都受总预算约束。普通取证轮的模型请求也扣除答复预留时间，最终答复请求受单次和总时间上限约束。30 秒后每 15 秒提供进度。HTTP 请求执行实际超时；502、503、504、可确认连接失败，以及尚未返回正文或工具请求片段的明确供应商流式失败，最多退避重试一次。空的 `error` 字段不算供应商失败。模型进度不表示正文已经返回，不阻止上述有限重试；实际正文、工具请求片段、权限或参数错误及结果未知的超时不重试。429 遵守 `Retry-After`；流式错误未提供重试时间时直接记录限流。达到预算时保留收据、证据和已报告用量，不用无来源结论补充失败结果。协议错误只保存受控原因编号，不记录供应商错误正文或凭据。

当前主 Agent 每次最多生成4000个 token。答复范围、引用编号与表达说明和咨询设定一起放在首条系统消息中，随每轮上下文保留；不在用户消息或工具结果后追加常规表达说明，不增加整理模型或法律审核模型。2026-10-29本地简单咨询曾使用 Nemotron-3.5 的 low 思考强度作耗时比较，随后恢复 high；实验结果见 [咨询与业务卡记录](CONSULTATION_CARDS_20261029.md)。实例实际配置与单次记录共同确定测试范围，思考强度和请求成功均不表示法律准确率已经通过。

2026-10-29，广州茶博会网址故障修复后，在当前 Nemotron-3.5/high 实例新建测试会话，真实请求“给我广州茶博会的网址，我要报名”：HTTP 200，交付状态 `answered`，端到端64.875秒。两次主模型请求分别约23.23秒和40.20秒，实际 `web_search` 约1.29秒，返回官网与参展申请网址。执行编号为 `f5ae6dee19d0496b818172d8460f1520`，脱敏结果在本实例忽略目录 `.dev/exhibition-url-smoke-20261029.json`。相关173项测试通过；单次真实请求仅验证本题能够交付，未证明连续运行稳定性或达到60秒目标。原失败记录停在流式错误解析，零工具调用，未运行法律审核；原始错误帧未保留，无法追认是明确供应商失败还是空错误字段被旧解析器误判。

业务归属、文档版本、节点门禁、资料核对、授权和文稿事务继续由现有服务处理。主 Agent 持续采用茶商咨询助手的设定：先解释眼下能做的事，说明由谁办理及所需材料；信息缺失时每轮只问一两个会改变建议的问题，复用已知事实和明确假设。此要求在稳定系统说明和每轮交付说明中保留，不依赖可选技能加载。

`update_business_card` 是直接提供的常用工具。主 Agent 遇到明确业务信息时可批量暂存当前业务已解锁卡片的字段，无需额外保存口令；未知项留空，假设、举例、模型建议和核验结果不得写入。程序自动关联当前问题或本业务用户消息，明确更正也由程序依据本轮原话判断，无需模型复制引文、填写消息编号或声明授权。服务逐字段核对实际用户原话，来源只能为当前问题或同业务用户消息，不能引用助手发言或其他业务资料。已有值冲突时保留原值，用户明确更正才允许替换。来源保存原话、消息编号、Agent 执行编号和时间。

消息事务提交前重验业务修订；卡片更新通过现有任务服务与本轮消息共同提交，复用字段校验、版本冲突和旧确认失效规则。取消、失败及修订冲突不提交这些写入。填写后的字段仍待核对，不确认材料、完成任务或解锁阶段；茶商可手工修改和提交核验。手工更改某字段后清除该字段的 Agent 来源，其他字段来源保留。前端在流式 `done` 返回后刷新卡片，保留茶商尚未保存的本地输入并显示版本冲突。

文稿及偏好记忆继续仅在用户请求时暂存。模型无权从聊天确认材料、完成节点或改变账号归属。

## 后台任务与 MCP

`TEA_BACKGROUND_WORKERS=external` 为聊天 API 的默认值，不在 API 进程启动采集、解析、向量索引队列及官方导入器。独立进程继续使用原持久队列、租约、恢复记录和容量限制：

```sh
uv run --project backend --locked python scripts/run_workers.py \
  --data-dir .dev/real-user/data --env-file .dev/real-user/demo.env
```

独立 worker 默认下载并发 2、解析并发 1、向量并发 1；已有环境配置可以覆盖。退出响应 SIGINT/SIGTERM，依次停止导入器、定时采集和队列执行器。启动 worker 会处理原队列中的真实任务，须核对实例及既有处理范围。聊天 API 仅读取已完成索引；查询向量仍属于交互检索。`TEA_BACKGROUND_WORKERS=internal` 保留原单进程运行方式。原 `TEA_SHARED_LIBRARY_WORKERS=external` 只排除系统共享库，仍处理私有任务，其语义保持不变。

MCP 入口使用现有账号认证与业务范围，共用证据和只读业务工具，包括 `lookup_chinese_law` 与 `get_law_versions`；普通目录移除 `analyze_legal`。历史人工研究继续经法律 API 使用。协议、错误、源站和权限边界见 [API 契约](API_CONTRACT.md#agent-目录与用户记忆)。

用户记忆继续采用来源、归属和修订校验：显式保存的偏好与业务笔记分别管理，历史消息作为讨论来源，聊天推断不升级为确认事实。管理接口与历史版本不受本次问答精简影响。
