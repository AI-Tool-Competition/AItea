# Tea API v1 (implementation contract)

Base `/api/tea`. Same-origin HTTP-only cookie session. JSON objects snake_case. Errors `{error:{code,message,request_id?}}`; 401 unauthenticated, 404 non-owned resources, 409 stale revisions/locked stage, 422 validation. All returned dates ISO UTC. API owns all state; no browser-only business data. List endpoints return `{items:[],total:number}` with bounded limit/offset. `GET /bootstrap` supplies `{user,templates:Template[],cases:CaseSummary[],capabilities}`.

## Authentication
- POST `/auth/demo` {} creates/reuses the current demo session (isolated per browser, seed an illustrative case); returns User.
- POST `/auth/register` {name,email,password}; POST `/auth/login` {email,password}; GET `/auth/me`; responses User `{id,name,email,is_demo}`.
- POST `/auth/logout` -> 204. GET `/health` -> `{status,version,assistant_mode,retrieval_mode,parser,collector:{status,last_error_at}}` no secrets. Collector status is stopped/running/recovering/draining; a live HTTP server alone does not establish queue health.
- capabilities `{assistant_mode:'demo'|'live',retrieval_mode:'lexical'|'hybrid',parser:string}`.

## Template format
Template = `{id,version,title,description,origin,destination,is_demo,modes:Mode[],stages:StageDefinition[],agent:AgentConfig}`.
Mode = `{id,name,description,enabled}`. Demo modes use 模式 A / 模式 B (待配置), not invented trade modes.
StageDefinition = `{id,name,actor,description,tasks:TaskDefinition[],analysis?:AgentConfig|null}`. Missing/null `analysis` inherits `Template.agent`; an explicit configuration replaces it for this stage. Demo names can be 业务资料 / 对接准备 / 材料交付; they are illustrative preparation phases, not claimed legal requirements. actor names 企业 / 对接主体 / 接收主体, configurable.
TaskDefinition = `{id,title,description,required:boolean,fields:FieldDefinition[],require_document:boolean,require_confirmation:boolean,output_template?:string}`.
FieldDefinition = `{key,label,type:'text'|'number'|'textarea',required:boolean,min?:number,placeholder?:string}`.
AgentConfig = `{language:string,instructions:string,retrieval_limit:number,steps:{id,type:'retrieve'|'check'|'guide'|'draft'|'verify',label,enabled:boolean,instructions?:string}[]}`. Steps have unique IDs within their workflow and at least one enabled step; per-step instructions default to `""` and are limited to 3000 characters.
- GET `/templates` -> list; GET `/templates/{id}` -> latest Template.
- POST `/templates/validate` {template:object} -> `{valid:boolean,errors:{path,message}[],preview:{stages,tasks}}`. Incomplete configuration is accepted for structured validation; the request wrapper itself rejects unknown fields.
- GET `/templates/drafts?limit=50&offset=0` -> `{items:{id,title,revision,updated_at}[],total:number}`. Lists all saved drafts for the current account, including unpublished IDs; does not return template bodies. Titles are at most 200 characters, with the ID as a fallback for absent, non-text or blank titles. Pagination is bounded to 200, ordered by update time descending, then ID descending. Fetch a selected draft through `/templates/{id}/draft`.
- GET `/templates/{id}/draft` -> `{template:object|null,revision:number,updated_at:string|null}`. A known template without a draft returns null/revision 0; an unknown ID returns 404.
- PUT `/templates/{id}/draft` {template:object,expected_revision:number} -> same draft shape. Supports incomplete forms and new IDs, requires the payload ID to match the route, and caps the JSON template at 512 KB. Owner-scoped revisions start at 1; an outdated revision returns 409 `stale_draft`. A new unpublished draft is retrievable by ID but is not added to the published `/templates` list.
- POST `/templates/publish` {template:Template,expected_draft_revision?:number} -> Template with a new immutable version. `template.version` must match the latest published version (or 1 for a new ID); otherwise returns 409 `stale_template`. When `expected_draft_revision` is supplied, publishing checks the saved draft revision, replaces its contents with the published template and increments its revision in the same transaction. Existing callers can omit it. New IDs publish as version 1. Owner scoped; existing cases keep their frozen configuration. Unsupported fields/rules are rejected.
- POST `/templates/debug` accepts `DebugRequest` and returns `DebugRun`; old callers can keep sending only template/input/stage/task values/stop point. Defaults to the first stage and empty input/values. All tasks in the selected stage use the same validation/check rules as task editing, with empty task evidence and confirmation. Unknown stages/tasks/fields/steps and invalid numbers return 422. A stop point runs through that step and marks later steps skipped. Debug writes only isolated sample/run records, never cases, tasks, documents, messages, published configurations or editor drafts.

### Saved samples and workflow debugging

`DebugRequest` = `{template:Template,input?:string,stage_id?:string,task_values?:Record<task_id,Record<field_key,string|number>>,document_ids?:string[]|null,expectations?:DebugExpectation[],client_id?:string,sample_id?:string,sample_revision?:number,source_run_id?:string,start_step_id?:string,stop_after_step_id?:string}`. Input is capped at 20,000 characters; task values total 64 KiB; complete configuration/sample request is capped at 512 KiB. At most 200 documents and 50 expectations are accepted. Null/omitted document IDs resolve to the current account's shared, ready primary library; `[]` means no retrieval. Selection filters retrieval before ranking and retains review, current-version and applicability rules. Case documents, other users' documents and attachments are rejected. A snapshot's aggregate parsed indexes must fit the 64 MiB retrieval budget. Saved requests contain resolved sorted IDs, so the history describes the actual scope.

`DebugExpectation` = `{id,kind:'contains'|'not_contains'|'check'|'citation'|'manual',text?:string|null,task_id?:string|null,check_id?:string|null,status?:'passed'|'missing'|'conflict'|null,document_id?:string|null}`. Text expectations and manual review require text; checks require a known check ID and expected status (task ID can disambiguate repeated fields); citations require a document ID. IDs are unique within the sample. Exact text, rule status and actual citation IDs are checked deterministically, never with a second model. Manual expectations remain explicitly `manual`. Text expectations without a completed/cached valid guide answer (including failed, cancelled and context-invalidated runs) also remain `manual` with a not-evaluated explanation; absence of generated text is never a passing guardrail. Citation expectations describe retrieved evidence when no guide ran and supporting answer citations after guidance. Execution completion does not imply business correctness.

`DebugRun` extends the previous `{output,trace,checks,citations,stage_id,assistant_mode,retrieval_mode}` response with `{id,created_at,status:'completed'|'paused'|'failed'|'cancelled',request:DebugRequest,sample_id:string|null,source_run_id:string|null,document_versions:{document_id,version,metadata_revision}[],evaluations:{id,label,status:'passed'|'failed'|'manual',actual}[],error?:{code,message}}`. Failed model/retrieval steps are persisted with the partial trace and a public error. A repeated owner/client ID with the same request returns its stored result; different input returns 409 `idempotency_conflict`. Omit the ID only for legacy callers. A new ID deliberately invokes a new run, including nondeterministic model generation. GET `/templates/debug/runs/{id}` returns an owned run; an active run returns 409 `debug_in_progress`.

- PUT `/templates/{template_id}/debug-samples/{sample_id}` `{template,name,stage_id?,input?,task_values?,document_ids?,expectations?,expected_revision}` -> `DebugSample`: `{id,name,template_id,template,stage_id,input,task_values,document_ids:string[],expectations,revision,updated_at,document_versions}`. Creation requires revision 0, updates require the latest revision, and IDs must match the route. A conflict returns 409 `stale_sample` without overwriting input. Saving resolves null scope to fixed IDs and binds immutable file versions, metadata revisions, actual parsed/index content, family supersession, primary classification and current applicability. It does not copy/reclassify a document or turn an unapproved source into evidence.
- GET `/templates/{template_id}/debug-samples?stage_id=&limit=50&offset=0` -> `{items:{id,name,stage_id,revision,updated_at}[],total}`; GET `/templates/{template_id}/debug-samples/{sample_id}` -> full `DebugSample`. Lists contain no configuration bodies. DELETE `/templates/{template_id}/debug-samples/{sample_id}?expected_revision=N` -> 204; stale revision returns 409. All methods enforce account ownership. Each account may store at most 100 samples; deleting a sample keeps historical runs.
- GET `/templates/{template_id}/debug-runs?stage_id=&limit=50&offset=0` -> `{items:{id,created_at,status,stage_id,sample_id,evaluation_status:'passed'|'failed'|'manual'|'none'}[],total}`. Only finalized runs are listed. Both sample and run lists use descending timestamp/ID order with a maximum page size of 100. Run history retains at most 100 finalized runs or 64 MiB per account, whichever is reached first; oldest finalized runs are removed. Individual run/checkpoint snapshots are bounded at 16 MiB. Idempotency and checkpoint recovery apply while a run remains retained.

Supplying `sample_id` requires its positive `sample_revision`. The request's stage, question, task values, resolved document IDs and expectations must match that saved sample, and its document snapshot must still match current evidence; otherwise 409 `stale_sample`. Active configuration can change to compare versions, but incompatible task/field/check references return 422. To try unsaved input edits, omit the sample reference while retaining any intended explicit document selection. Saving again deliberately refreshes the sample's bound document snapshot.

`start_step_id` requires an owned `source_run_id`; setting start and stop to the same ID tests only that step. The backend restores trusted intermediate state from that run, never client-supplied output. Every preceding step must have a complete checkpoint and the same cumulative execution signature: input/task definitions and values, workflow order/relevant upstream configuration, scope/content/version/review/index metadata, effective date, provider identity and runner version. Changes only to the selected/later steps are allowed. Previously completed steps in a valid prefix are reported as `cached` with zero new execution time; disabled and prompt-only skipped steps keep `skipped` and their original reason; missing/stale prefix returns 409 `stale_checkpoint`. In particular changing guide instructions can reuse retrieval/check results. Resume after cancellation/failure is possible only from successfully completed upstream checkpoints. There is no arbitrary branch/DAG evaluator or silent rerun of cached external calls.

POST `/templates/debug/stream` accepts the same request/authentication and uses `text/event-stream` with proxy buffering disabled. Events are:

- `run`: `{id}` after the persisted claim, for later history recovery.
- `status`: `{label,step_id?}`; `step`: a public `TraceStep` when starting and after completion, failure or skip.
- `delta`: `{text,step_id?}` for genuine provider output; demo rules send their already available text without simulated timing.
- `done`: the final `DebugRun`, including failed runs; `error`: `{code,message}` for rejected requests/transport failures. EOF without `done` is interruption.

Debug trace steps preserve `{id,label,status,detail,input?,output?}` and add `{type,duration_ms,input_data:object,output_data:object}`. Status may be `running`, `completed`, `skipped`, `failed`, `cached` or `cancelled`. Retrieval inputs include actual query, selected IDs and limit; outputs contain retrieved citations/mode. Check inputs expose actual field definitions/values, evidence flags, question and citations; outputs contain actual server checks. Guide inputs share the exact public provider payload (including explicit context/check/previous-output limits), configured language/instructions and whether instructions were applied; output contains the full bounded answer and its citations. Short `input`/`output` summaries remain backward compatible. No credentials or private model reasoning are returned.

The stream reuses the bounded queue/cancellation transport of stage chat, emits heartbeat comments every 10 seconds, and respects the existing 45-second provider timeout. A disconnect cancels a waiting model read; synchronous retrieval stops at its next checkpoint. Finished checkpoints are saved before completion events. Each account permits one active debug run, with eight active runs globally and the existing four provider-call slots. Expired 20-minute claims are marked cancelled on the account's next debug/history request and keep completed checkpoints. Cancellation can race with normal completion, so history is the durable source. This provides recovery of recorded steps, not automatic replay of unfinished provider calls.

Debug, proactive analysis and stage chat share the same ordered runner. A guide step sees only results produced by preceding steps. Final citations belong to the last executed guide step; a later retrieval is visible in its trace but cannot retroactively support that guidance. If no guide executed, citations contain the actual retrieved results. Retrieve-step instructions provide a search focus; guide-step instructions enter the configured model request. Check steps execute server rules; their free-text instructions do not create new rules. Draft/verify steps explicitly skip actual mutations and point to the dedicated task actions. Without a model, guide steps run the labelled rule-only demo; free-text writing instructions are not represented as model execution. Provider calls are bounded in time, response size and concurrency; a failed step is visible and stops later steps.

## Cases / tasks
CaseSummary = `{id,title,company,product,mode_id,template_version,created_at,updated_at,completed_tasks,total_tasks,current_stage_id}`.
CaseDetail extends CaseSummary with `{template:Template,revision:number,stages:StageState[],facts:Fact[],documents:Document[],artifacts:Artifact[],events:AuditEvent[]}`.
StageState = `{id,name,actor,description,status:'locked'|'active'|'completed',tasks:TaskState[]}`.
TaskState = TaskDefinition + `{status:'pending'|'in_progress'|'needs_input'|'completed',needs_review:boolean,revision:number,values:Record<string,string|number>,evidence_ids:string[],confirmed:boolean,verification:Verification|null}`.
Fact = `{key,label,value:string|number,source:string,confirmed:boolean,updated_at}`.
Check = `{id,label,status:'passed'|'missing'|'conflict',reason:string,evidence_refs:string[],task_id?:string,task_title?:string}`. Stage workflow results identify the checked task when applicable; cross-document reported conflicts can omit it.
Verification = `{id,status:'passed'|'needs_input',checks:Check[],created_at,task_revision:number}`.
AuditEvent = `{id,type,title,detail,created_at}`.
- GET `/cases` -> summaries list. POST `/cases` {title,company,product,mode_id,template_id} -> CaseDetail.
- GET `/cases/{id}` -> CaseDetail; all mutations below return updated CaseDetail unless noted.
- PATCH `/cases/{id}/tasks/{task_id}` {values:Record<string,string|number>,evidence_ids?:string[],expected_revision:number}.
- POST `/cases/{id}/tasks/{task_id}/verify` {expected_revision:number,confirm:boolean}. Gate must examine current facts/documents, nonempty fields and evidence validity; required predecessors must pass; facts/evidence edit invalidates old confirmation. Non-required tasks do not gate unless configured.
- GET `/cases/{id}/events` -> list audit events.
- POST `/cases/{id}/stages/{stage_id}/analysis` {expected_revision:number,retry?:boolean} -> `{id,stage_id,case_revision,status:'completed'|'failed',output,trace:TraceStep[],checks:Check[],citations:Citation[],created_at,assistant_mode:'demo'|'live',retrieval_mode?:'lexical'|'hybrid'}`. Called when entering an unlocked stage. Requires the current case revision; locked stages return 409 `stage_locked`, stale revisions 409 `stale_revision`, and unowned resources 404. Analysis never changes task state, facts, messages or case revision.

Analysis is persisted per case/stage/input fingerprint: frozen configuration, task/confirmed facts, applicable document versions/review revisions, artifacts, provider configuration and applicability date. Repeated calls return the stored result (including its original `case_revision`); chat-only revision changes do not trigger another analysis. Failed results require explicit `retry:true` to execute again. Concurrent requests return 409 `analysis_in_progress`; an abandoned claim expires after 30 minutes. Retrieval and generation execute outside write transactions. If relevant inputs change before completion, no stale result is published and the request returns 409 `analysis_stale`.

## Conversation
Message = `{id,role:'user'|'assistant',content,stage_id,task_id:string|null,created_at,citations:Citation[],trace:TraceStep[]}`.
Citation = `{document_id,title,excerpt,locator:object,source_url?:string,document_version?:number}`.
TraceStep = `{id,label,status:'completed'|'skipped'|'failed'|'running'|'cached'|'cancelled',detail:string,input?:string,output?:string,type?:string,duration_ms?:number,input_data?:object,output_data?:object}`. Input/output strings are bounded public operation summaries, not private model reasoning. Detailed data/timing and live/cached/cancelled statuses are used by the debugger; normal chat/proactive analyses keep the lightweight trace. Skipped operations are never labelled completed.
- GET `/cases/{id}/messages?stage_id=...` -> list.
- POST `/cases/{id}/messages` {stage_id,task_id?:string,content,client_message_id:string} -> `{messages:Message[],case:CaseDetail}`. Message ID makes retries idempotent. Include relevant case facts and retrieved citations; demo assistant clearly labeled in capabilities and trace. Do not pretend to invoke a model when unconfigured. Grounded factual conflict handling and progress reporting should trigger questions, never trust free text as completed state. A live provider is optional via server environment, errors visible.
- POST `/cases/{id}/messages/stream` accepts the same input and cookie authentication, and returns `text/event-stream` with `X-Accel-Buffering: no` and `Cache-Control: no-store, no-transform`. The common response middleware preserves `no-transform` so the Next proxy does not buffer small frames in gzip compression. Ownership, stage/task and completed-request conflicts are checked before streaming headers. Each SSE frame has an `event:` name and one JSON `data:` value:
  - `status`: `{label,step_id?}` describes the current public operation; the first frame acknowledges the request immediately.
  - `start`: `{step_id}` replaces the provisional answer when a guide step begins. Multiple guide steps do not concatenate unrelated answers.
  - `delta`: `{text}` appends text from the configured provider's actual incremental response. Rule-only demo guidance arrives when ready, without simulated token delays.
  - `done`: `{messages:Message[],case:CaseDetail}` is the authoritative, persisted result, including citations, traces and any concurrent-data-change warning. Replace provisional text and deduplicate by message ID. Replaying a completed `client_message_id` returns the stored messages without calling the provider again.
  - `error`: `{code,message}` terminates an unsuccessful stream. An EOF without `done` is an interruption, never a successful reply. Before headers, errors use the ordinary HTTP/JSON envelope.

Both message endpoints share a per-process limit of four generating conversations and one active request per case (`chat_busy` / `message_in_progress`). Streaming errors, cancellation before commit, and incomplete upstream streams do not persist a partial message pair. Disconnect cancels the upstream async model read, including while waiting for its first byte; synchronous retrieval stops at its next workflow checkpoint. A stop racing with a successful commit may leave a complete stored result; retry the same message ID to recover it. No automatic retries or cross-process run recovery are provided. Completed turns retain the existing transactional idempotency guarantee. Streaming uses a bounded queue, heartbeat comments during quiet work, the existing 45-second/1-MB provider bounds and a 20,000-character answer limit. The browser retains provisional text on interruption, offers explicit retry with the original ID, and times out after 60 seconds with no frames.

## Documents / library
Document = `{id,title,filename,role:'primary'|'secondary',status:'ready'|'failed'|'stored'|'processing',mime_type,size,version,case_id:string|null,parent_id:string|null,tags:string[],created_at,source_url:string|null,error:string|null,chunk_count:number,family_id:string,content_hash:string,legal_level:'primary'|'secondary'|'attachment',classifications:Classification[]}`.
- GET `/documents?case_id=...&role=primary|secondary&legal_level=primary|secondary|attachment&collection=...&parent_id=...&q=...&limit=100&offset=0` -> owned list. Omit case_id = library; omit the new filters to preserve the existing list. `q` matches literal title/filename text (max 200 characters). A parent must be an owned primary in the same scope; its children are secondary only. Pagination is bounded to 200 and ordered by creation time descending, then ID descending. Lists load summaries without text/vectors; classifications/review data are read in batches.
- POST `/documents` multipart file + optional case_id, role(default primary), parent_id, tags(JSON array) -> Document. Max 20 MB; safe filenames; secondary requires valid parent in same owner/scope and must never parse/index. Uploaded HTML download as attachment only.
- GET `/documents/{id}?element_offset=0&chunk_offset=0&limit=100` -> `{document:Document,elements:object[],chunks:object[],element_total:number,chunk_total:number,element_offset:number,chunk_offset:number,limit:number,parser:string|null,warnings:string[]}`. Element and chunk offsets are independent; limit is 1–200. Chunk embeddings are never returned. Secondary attachments have no parsed elements/chunks and a null parser; their original remains downloadable.
- GET `/documents/{id}/download` -> original bytes (authenticated).
- POST `/search` {query,case_id?:string,collection?:string,as_of?:date,limit?:number} -> `{items:Citation[],mode:'lexical'|'hybrid',warning?:string}`. Case queries only case docs + explicit library docs owned by same account, never other cases.

## Artifacts
Artifact = `{id,case_id,task_id,title,content,version:number,confirmed:boolean,created_at,updated_at}`.
- POST `/cases/{id}/artifacts` {task_id,title?:string} -> Artifact (draft generated from configured template + facts with missing info placeholders).
- PATCH `/artifacts/{id}` {title,content,expected_version:number} -> Artifact new revision; editing invalidates confirmation and dependent completion.
- POST `/artifacts/{id}/confirm` {expected_version:number} -> Artifact.
- GET `/artifacts/{id}/versions` -> list Artifact snapshots; GET `/artifacts/{id}/download` -> UTF8 Markdown attachment.

## Legal versions, classifications and relations
`role` describes a file, not its legal tier: a parsed regulation uses file role `primary`, including a regulation that is secondary legal material. Ordinary attachments use file role `secondary`, `parent_id` and `legal_level=attachment`; they remain original-only.

Classification = `{collection:string,level:'primary'|'secondary',tags:string[],revision:number}`. Collection names are account-scoped; a version can be primary in one collection and secondary in another. Up to 20 collections per version, 20 tags of 1–80 characters per collection. `legal_level` is primary if any classification is primary (or no classification exists), secondary if all are secondary, and attachment for ordinary attachments.
- PATCH `/documents/{id}/classification` `{collection,level,tags,expected_revision}` -> Document. Revision 0 creates membership; stale revision returns 409. Changes have audit history. Attachments return 422. Primary eligibility queues any required indexing; secondary-only documents are excluded from retrieval even if a prior primary classification left stored vectors.
- GET `/documents/{id}/versions?limit=20&offset=0` -> owned Document list, same stable family, version descending. Originals and IDs remain immutable; A→B→A is three versions sharing two original blobs.
- GET `/documents/{id}/relations?limit=20&offset=0` -> owned list, both directions.
- POST `/documents/{primary_id}/relations` `{collection,target_document_id,relation:'cites'|'related',locator:string}` -> 201 LawRelation. Exact repeats return the same relation. Both versions must be owned, parsed-file records in the same scope, and the target must belong to the collection. Selecting an unclassified primary anchor explicitly joins it to that collection; conflicting secondary membership is rejected. No relation is automatically retargeted to a newer document version.
LawRelation = `{id,collection,source_document_id,target_document_id,relation,locator,created_at,source_title,target_title,source_version,target_version}`. `related` is an explicit association, not a claim that a citation was extracted. A single secondary version can link to several primary versions.

## Source collection
Source = `{id,name,url,enabled,interval_hours,tags,last_fetched_at,status,last_error,revision,plan:CollectionPlan,latest_run:CollectionRun|null}`.
CollectionPlan = `{collection:'default',level:'primary'|'secondary',seed_urls:[],primary_document_ids:[],discover_attachments:true,max_items:200}` (defaults shown). Up to 200 extra seed URLs, max_items 1–500. Secondary plans require 1–20 owned public-library primary IDs; primary plans have no parent IDs. Seed URLs are explicit documents; automatic same-origin direct-file links are ordinary attachments, never inferred legal citations.
- GET `/sources?limit=100&offset=0` -> owned paginated list (max 200); GET `/sources/{id}` -> Source.
- POST `/sources` `{name,url,enabled,interval_hours,tags,plan?}` -> 201 Source.
- PATCH `/sources/{id}` `{expected_revision,...optional source fields}` -> Source. Revision is **required**; stale update returns 409. Running tasks retain their source-plan snapshot.
- POST `/sources/{id}/runs` `{client_request_id,entries?:[{url,identity_key?:string}]}` -> **202 CollectionRun** immediately. Without entries, uses source URL plus seed_urls. With entries, replaces seeds for this run (1–200). An official stable identity_key groups revisions published at different URLs; absent this, URL identifies the family. Same account/request ID returns the same job; reusing it with different source/entries returns 409. Network calls do not run inside this request.
- POST `/sources/{id}/fetch` -> **202 CollectionRun** as a compatibility alias to the same queue, replacing the old synchronous `{source,documents}` response. Accepts the same optional body; without one, generates a new request ID. Clients needing retry idempotency must pass client_request_id.
- GET `/sources/{id}/runs?limit=20&offset=0` -> job history; GET `/collection-runs/{id}?limit=50&offset=0` -> `{run,items:CollectionItem[],total}`.
- POST `/collection-runs/{id}/cancel` or `/retry` `{expected_revision}` -> CollectionRun. Cancel stops unfinished downloads from committing; saved originals and independent processing remain. Retry requeues failed/cancelled downloads and failed processing only. No retryable item returns 409; queue saturation returns 429 without mutations. Revision advances on control commands only; progress updates change `updated_at`, allowing cancellation while work progresses. A stale command from before a cancel/retry returns 409.
CollectionRun = `{id,source_id,status:'queued'|'running'|'completed'|'partial'|'cancelled',revision,created_at,updated_at,error,total,stored,failed,pending,processing,processed,processing_failed}`. `stored` counts durable original references, including deduplicated content; completed means this bounded plan finished, not an entire website or legal checklist.
CollectionItem = `{id,url,level:'primary'|'secondary'|'attachment',status:'queued'|'fetching'|'stored'|'failed'|'cancelled',attempts,document_id,error,final_url,fetched_at,processing_status,processing_error}`. Items are ordered by creation and ID. Ordinary lists never return file bytes.

All job, source, version, relation and original routes enforce account ownership. Limits, retries, storage layout, interruption recovery and operational boundaries: [INGESTION.md](INGESTION.md).

## Parser service contract (pure Python, no DB)
`app.ingestion.parse_file(filename: str, content: bytes, mime_type: str = '', *, role: str='primary', parser: str='basic') -> dict` returns `{parser,elements:[{element_key,kind,content_text,section_path,locator}],chunks:[{id,text,section_path,locator}],warnings:[]}`. Secondary raises ValueError (backend stores without calling). Defaults basic TXT/MD/HTML/DOCX/PDF; Docling explicitly optional. Bounded size/decompression/page limits. Extract actual original parser into `app/vendor/geo_parser` with provenance and relative import.
`app.ingestion.lexical_search(query: str, chunks: list[dict], limit: int=5) -> list[dict]`: chunks include text + metadata; returns hits with score, preserves metadata; irrelevant query no arbitrary hits.
`app.ingestion.embed_texts(texts:list[str]) -> list[list[float]] | None`: env configured OpenAI-compatible provider, no fake vector fallbacks; explicit errors and dimension validation.
`app.ingestion.fetch_source(url: str, *, max_attachments:int=5) -> dict`: `{url,filename,mime_type,content:bytes,attachments:[{url,filename,mime_type,content:bytes}],fetched_at}` HTTPS/public address pinned connection, safe redirects, size/time limits, same-origin direct recognized-file links only. Legacy pure-library helper only; application entry points use streaming `_download(consume=...)` and durable jobs, not this all-results helper.

## Document review and applicability

Document responses also include `metadata`, `metadata_revision` and `reviewed_at`. Metadata is `{kind:'law'|'guidance'|'case'|'business'|'demo',jurisdiction,language,published_at:date|null,effective_from:date|null,effective_to:date|null,review_status:'draft'|'published'}`. These are classification/review data, never claims that a source is legally authoritative.

`PATCH /documents/{id}/metadata` takes `expected_revision` and any metadata fields, returns the updated Document. Stale revisions return 409; inverted date ranges and secondary attachments return 422. Changes are audit-versioned. Editing applicability without explicit renewed approval resets it to draft; associated case tasks and downstream confirmations require review.

`POST /search` accepts `as_of` and `collection`. Default retrieval selects the latest immutable family version before applying readiness, review and primary eligibility; a pending/failed/secondary latest version cannot silently fall back to an old primary. An explicit historical date can select a reviewed older law with a known start and end period. An old law with an unknown end cannot establish historical applicability after a replacement; legal metadata must be reviewed. In a specified collection, only primary membership in that collection is retrieved. Without a collection, secondary-only versions and attachments are excluded.

Search citations carry immutable document/version IDs, locators, metadata and metadata_revision. Fetched laws begin draft. Ordinary uploads begin business/published, not legal authority. The current local retrieval engine reads at most 500 selected documents / 64 MiB of manifests per query; exceeding this returns a visible warning to narrow the collection, not a claim of full-corpus coverage. This is separate from the durable collection queue and is not a distributed vector database.

## Local configuration

The validated startup JSON file defaults to `config/workflows/china-indonesia.json` and is overridable via `TEA_TEMPLATE_FILE`. A user's published versions take priority for that user's new cases; frozen case snapshots remain unchanged. File changes are loaded on service restart.
