# Tea API v1 (implementation contract)

Current ingestion and retrieval use MinerU precise cloud parsing and local RAGFlow. New retrieval results report `mode:'ragflow'|'unavailable'`; historical `lexical`/`hybrid` values remain readable in saved analyses. Missing configuration or provider failures are explicit and never select the old local retrieval path. PDF/Office/image parsing is asynchronous: saving an original does not imply text or index completion. Schema 20 persists MinerU tasks; schema 21 persists RAGFlow generations and chunk receipts; schema 22 stores immutable, source-page-hash-bound Setneg metadata for discovery candidates; schema 23 records automatic official-source version imports. Source/account/review/version eligibility is checked before retrieval and after remote results, with citations derived from trusted local chunks. See [pipeline and operations](MINERU_RAGFLOW.md).

Base `/api/tea`. Same-origin HTTP-only cookie session. JSON objects snake_case. Errors `{error:{code,message,request_id?}}`; 401 unauthenticated, 404 non-owned resources, 409 stale revisions/locked stage, 422 validation. All returned dates ISO UTC. API owns all state; no browser-only business data. List endpoints return `{items:[],total:number}` with bounded limit/offset. `GET /bootstrap` supplies `{user,templates:Template[],cases:CaseSummary[],capabilities}`.

Initialized storage that disappears, has an empty database file, or is replaced is unavailable: database-backed operations return HTTP 503 `database_unavailable` without recreating an empty store or exposing filesystem paths. `GET /health` also checks storage identity and the base schema tables and marker before reporting `status:ok`; this bounded readiness check does not validate every original or certify corpus completeness. Deployments with existing data can require it at startup using `TEA_REQUIRE_EXISTING_DATA=true`; after a verified restore replaces the store, restart the service. See [storage operations](STORAGE.md).

## Authentication
- POST `/auth/demo` {} creates/reuses the current demo session (isolated per browser, seeds a Liubao Indonesia online case for a new session); returns User.
- POST `/auth/register` `{name,email,password,bootstrap_token?}`; POST `/auth/login` `{email,password}` where the login identity may be an email or the reserved username `admin`; GET `/auth/me`; responses User `{id,name,email,is_demo,can_login,is_admin}`. Normal deployments create the initial `admin` account with password `admin123` if that reserved account is absent; an existing account is never reset. New registrations are pending (`can_login=false`) unless a valid initial-admin token is supplied. A pending response does not create a session. Login to a pending or disabled account returns 403 `account_not_allowed`.
- POST `/auth/logout` -> 204. GET `/health` -> `{status,version,assistant_mode,retrieval_mode,parser,collector:{status,last_error_at,shared_library_workers:'internal'|'external',official_source_import:{status,last_cycle_at,last_cycle_counts:{stored,skipped,blocked,deferred},last_error_at}}}` no secrets. Collector status is stopped/running/recovering/draining; a live HTTP server alone does not establish queue health. `shared_library_workers` reports the main application's configured background scope: `internal` (default) includes system documents; `external` leaves their fetch/processing/recovery/scheduling to dedicated workers while private work continues. It does not report whether an external runner is currently running and does not change shared read access or legal eligibility. `official_source_import` reports the background reader that converts verified ID/SG content-version receipts into versioned parse jobs; `stored` means queued for parsing, not approved or RAG-published.
- `GET /bootstrap` also returns `admin_setup_required`. The first administrator can be initialized by `POST /admin/bootstrap` `{bootstrap_token}` with a logged-in non-demo account, or during registration. The token is configured only on the backend as `TEA_ADMIN_BOOTSTRAP_TOKEN`; initialization is atomic and only succeeds while no active administrator exists.
- Admin-only `GET /admin/users?limit=50&offset=0&q=` returns `{items:[{id,name,email,created_at,can_login,is_admin,revision}],total}`; limit is 1–100 and ordering is stable by creation time then ID. `PATCH /admin/users/{id}` accepts `{expected_revision,can_login?,is_admin?}` and returns the updated row. Stale changes return 409 `stale_account`; a request that would remove the last active administrator returns 409 `last_admin`. Disabling an account removes its sessions. Template studio, debugging, sources and collection-management endpoints also require an administrator; account-owned workspace, document and case endpoints remain available to allowed users.
- capabilities `{assistant_mode:'demo'|'live',retrieval_mode:'lexical'|'hybrid',parser:string}`.

## Template format
Template = `{id,version,title,description,origin,destination,is_demo,modes:Mode[],stages:StageDefinition[],agent:AgentConfig}`.
Mode = `{id,name,description,enabled}`. Each built-in handbook route defines its online or offline acquisition mode. Actual import and sales paths are recorded in route facts and applicability checks.
StageDefinition = `{id,name,actor,description,tasks:TaskDefinition[],analysis?:AgentConfig|null}`. Missing/null `analysis` inherits `Template.agent`; an explicit configuration replaces it for this stage. `actor` identifies the responsible parties; stage names and descriptions remain configurable.
TaskDefinition = `{id,title,description,required:boolean,blocks_next_stage?:boolean,fields:FieldDefinition[],require_document:boolean,require_confirmation:boolean,output_template?:string}`. `blocks_next_stage` defaults to true. A required task with false can remain open while later stages proceed; it remains required for business completion, keeps evidence/revision checks, and is not editable until its own stage unlocks. Its changes reopen that task without invalidating unrelated later tasks; changes to evidence shared with other tasks still invalidate those consumers.
FieldDefinition = `{key,label,type:'text'|'number'|'textarea'|'select',required:boolean,min?:number,placeholder?:string,options?:string[]|null,accepted_values?:string[]|null}`.
AgentConfig = `{language:string,instructions:string,retrieval_limit:number,steps:{id,type:'retrieve'|'check'|'guide'|'draft'|'verify',label,enabled:boolean,instructions?:string}[]}`. Steps have unique IDs within their workflow and at least one enabled step; per-step instructions default to `""` and are limited to 3000 characters.
- Select fields require 1–50 unique nonempty options (each at most 100 characters). Optional `accepted_values` must be a nonempty unique subset of options and requires `required:true`; other field types cannot define either list. Invalid nonempty choices return 422 `invalid_option` on task save/debug; valid waiting/blocked choices are saved but fail verification until an accepted value is selected. Evidence and confirmation checks remain independent. Old fields omit these properties or use null.
- Built-in templates contain four `liubao-{id|sg}-{online|offline}` handbook routes; the legacy demo is retired. Account publications override the corresponding built-in ID; their version remains the publish baseline even if a later bundle raises its built-in version. Existing cases keep frozen snapshots.
- GET `/templates` -> list; GET `/templates/{id}` -> latest Template.
- POST `/templates/validate` {template:object} -> `{valid:boolean,errors:{path,message}[],preview:{stages,tasks}}`. Incomplete configuration is accepted for structured validation; the request wrapper itself rejects unknown fields.
- GET `/templates/drafts?limit=50&offset=0` -> `{items:{id,title,revision,updated_at}[],total:number}`. Lists all saved drafts for the current account, including unpublished IDs; does not return template bodies. Titles are at most 200 characters, with the ID as a fallback for absent, non-text or blank titles. Pagination is bounded to 200, ordered by update time descending, then ID descending. Fetch a selected draft through `/templates/{id}/draft`.
- GET `/templates/{id}/draft` -> `{template:object|null,revision:number,updated_at:string|null}`. A known template without a draft returns null/revision 0; an unknown ID returns 404.
- PUT `/templates/{id}/draft` {template:object,expected_revision:number} -> same draft shape. Supports incomplete forms and new IDs, requires the payload ID to match the route, and caps the JSON template at 512 KB. Owner-scoped revisions start at 1; an outdated revision returns 409 `stale_draft`. A new unpublished draft is retrievable by ID but is not added to the published `/templates` list.
- POST `/templates/publish` {template:Template,expected_draft_revision?:number} -> Template with a new immutable version. `template.version` must match the latest published version (or 1 for a new ID); otherwise returns 409 `stale_template`. When `expected_draft_revision` is supplied, publishing checks the saved draft revision, replaces its contents with the published template and increments its revision in the same transaction. Existing callers can omit it. New IDs publish as version 1. Owner scoped; existing cases keep their frozen configuration. Unsupported fields/rules are rejected.
- POST `/templates/debug` accepts `DebugRequest` and returns `DebugRun`; old callers can keep sending only template/input/stage/task values/stop point. Defaults to the first stage and empty input/values. All tasks in the selected stage use the same validation/check rules as task editing, with empty task evidence and confirmation. Unknown stages/tasks/fields/steps and invalid numbers return 422. A stop point runs through that step and marks later steps skipped. Debug writes only isolated sample/run records, never cases, tasks, documents, messages, published configurations or editor drafts.

### Saved samples and workflow debugging

`DebugRequest` = `{template:Template,input?:string,stage_id?:string,task_values?:Record<task_id,Record<field_key,string|number>>,document_ids?:string[]|null,expectations?:DebugExpectation[],client_id?:string,sample_id?:string,sample_revision?:number,source_run_id?:string,start_step_id?:string,stop_after_step_id?:string}`. Input is capped at 20,000 characters; task values total 64 KiB; complete configuration/sample request is capped at 512 KiB. At most 200 documents and 50 expectations are accepted. Null/omitted document IDs resolve to the current account's shared, ready primary library for `template.destination`; `[]` means no retrieval. The server uses the same `resolve_country` as production search: a recognized destination fixes the national boundary; unknown destinations allow only unassigned material. Explicit selections from a conflicting country (including unassigned material for a recognized destination) return 422 `country_mismatch`, and foreign/private case files return 404. Clients cannot override the country independently of the configuration. Selection filters retrieval before ranking and retains review, current-version and applicability rules. Case documents, other users' documents and attachments are rejected. A snapshot's aggregate parsed indexes must fit the 64 MiB retrieval budget. Saved requests contain resolved sorted IDs, so the history describes the actual scope.

`DebugExpectation` = `{id,kind:'contains'|'not_contains'|'check'|'citation'|'manual',text?:string|null,task_id?:string|null,check_id?:string|null,status?:'passed'|'missing'|'conflict'|null,document_id?:string|null}`. Text expectations and manual review require text; checks require a known check ID and expected status (task ID can disambiguate repeated fields); citations require a document ID. IDs are unique within the sample. Exact text, rule status and actual citation IDs are checked deterministically, never with a second model. Manual expectations remain explicitly `manual`. Text expectations without a completed/cached valid guide answer (including failed, cancelled and context-invalidated runs) also remain `manual` with a not-evaluated explanation; absence of generated text is never a passing guardrail. Citation expectations describe retrieved evidence when no guide ran and supporting answer citations after guidance. Execution completion does not imply business correctness.

`DebugRun` extends the previous `{output,trace,checks,citations,stage_id,assistant_mode,retrieval_mode}` response with `{id,created_at,status:'completed'|'paused'|'failed'|'cancelled',request:DebugRequest,sample_id:string|null,source_run_id:string|null,country?:string|null,document_versions:{document_id,version,metadata_revision}[],evaluations:{id,label,status:'passed'|'failed'|'manual',actual}[],error?:{code,message}}`. Failed model/retrieval steps are persisted with the partial trace and a public error. A repeated owner/client ID with the same request returns its stored result; different input returns 409 `idempotency_conflict`. Omit the ID only for legacy callers. A new ID deliberately invokes a new run, including nondeterministic model generation. GET `/templates/debug/runs/{id}` returns an owned run; an active run returns 409 `debug_in_progress`.

- GET `/templates/debug/documents?destination=<configured destination>&limit=50&offset=0` -> `{items:Document[],total,country:string|null}`. Uses the server's destination aliases and the existing owned shared-library listing (`role=primary`), with a maximum page size of 200 and stable creation/ID order. No private case files or other countries are included. Unknown destinations return unassigned documents and null country. This read-only endpoint is the debugger's document picker; readiness, review and retrieval eligibility are still enforced when running.
- PUT `/templates/{template_id}/debug-samples/{sample_id}` `{template,name,stage_id?,input?,task_values?,document_ids?,expectations?,expected_revision}` -> `DebugSample`: `{id,name,template_id,template,stage_id,input,task_values,document_ids:string[],expectations,revision,updated_at,document_versions,country?:string|null}`. Creation requires revision 0, updates require the latest revision, and IDs must match the route. A conflict returns 409 `stale_sample` without overwriting input. Saving resolves null scope to fixed IDs and binds immutable file versions, metadata revisions, actual parsed/index content, family supersession, immutable country assignment, primary classification and current applicability. It does not copy/reclassify a document or turn an unapproved source into evidence.
- GET `/templates/{template_id}/debug-samples?stage_id=&limit=50&offset=0` -> `{items:{id,name,stage_id,revision,updated_at}[],total}`; GET `/templates/{template_id}/debug-samples/{sample_id}` -> full `DebugSample`. Lists contain no configuration bodies. DELETE `/templates/{template_id}/debug-samples/{sample_id}?expected_revision=N` -> 204; stale revision returns 409. All methods enforce account ownership. Each account may store at most 100 samples; deleting a sample keeps historical runs.
- GET `/templates/{template_id}/debug-runs?stage_id=&limit=50&offset=0` -> `{items:{id,created_at,status,stage_id,sample_id,evaluation_status:'passed'|'failed'|'manual'|'none'}[],total}`. Only finalized runs are listed. Both sample and run lists use descending timestamp/ID order with a maximum page size of 100. Run history retains at most 100 finalized runs or 64 MiB per account, whichever is reached first; oldest finalized runs are removed. Individual run/checkpoint snapshots are bounded at 16 MiB. Idempotency and checkpoint recovery apply while a run remains retained.

Supplying `sample_id` requires its positive `sample_revision`. The request's stage, question, task values, resolved document IDs and expectations must match that saved sample, and its document snapshot must still match current evidence; otherwise 409 `stale_sample`. Active configuration can change to compare versions, but incompatible task/field/check references return 422. To try unsaved input edits, omit the sample reference while retaining any intended explicit document selection. Saving again deliberately refreshes the sample's bound document snapshot.

`start_step_id` requires an owned `source_run_id`; setting start and stop to the same ID tests only that step. The backend restores trusted intermediate state from that run, never client-supplied output. Every preceding step must have a complete checkpoint and the same cumulative execution signature: input/task definitions and values, workflow order/relevant upstream configuration, scope/content/version/review/index metadata, effective date, provider identity and runner version. Changes only to the selected/later steps are allowed. Previously completed steps in a valid prefix are reported as `cached` with zero new execution time; disabled and prompt-only skipped steps keep `skipped` and their original reason; missing/stale prefix returns 409 `stale_checkpoint`. In particular changing guide instructions can reuse retrieval/check results. Resume after cancellation/failure is possible only from successfully completed upstream checkpoints. There is no arbitrary branch/DAG evaluator or silent rerun of cached external calls.

POST `/templates/debug/stream` accepts the same request/authentication and uses `text/event-stream` with proxy buffering disabled. Events are:

- `run`: `{id}` after the persisted claim, for later history recovery.
- `status`: `{label,step_id?}`; `step`: a public `TraceStep` when starting and after completion, failure or skip.
- `delta`: `{text,step_id?}` for genuine provider output; demo rules send their already available text without simulated timing.
- `done`: the final `DebugRun`, including failed runs; `error`: `{code,message}` for rejected requests/transport failures. EOF without `done` is interruption.

Debug trace steps preserve `{id,label,status,detail,input?,output?}` and add `{type,duration_ms,input_data:object,output_data:object}`. Status may be `running`, `completed`, `skipped`, `failed`, `cached` or `cancelled`. Retrieval inputs include actual query, selected IDs and limit; outputs contain retrieved citations/mode. Check inputs expose actual field definitions/values, evidence flags, question and citations; outputs contain actual server checks. Guide inputs share the exact public provider payload (including explicit context/check/previous-output limits), configured language/instructions and whether instructions were applied; output contains the full bounded answer and its citations. Short `input`/`output` summaries remain backward compatible. No credentials or private model reasoning are returned. Retrieval inputs also include the resolved `country`; new sample/run snapshots expose it for review while existing historical snapshots may omit it.

The stream reuses the bounded queue/cancellation transport of stage chat, emits heartbeat comments every 10 seconds, and respects the existing 45-second provider timeout. A disconnect cancels a waiting model read; synchronous retrieval stops at its next checkpoint. Finished checkpoints are saved before completion events. Each account permits one active debug run, with eight active runs globally and the existing four provider-call slots. Expired 20-minute claims are marked cancelled on the account's next debug/history request and keep completed checkpoints. Cancellation can race with normal completion, so history is the durable source. This provides recovery of recorded steps, not automatic replay of unfinished provider calls.

Debugger persistence uses schema migration 8; collection/country tables retain migration 7. Existing deployed country-v7 databases gain only the debugger tables. An unpublished debugger-v7 database is recognized only when both debugger tables exist and country/checklist tables and columns are absent: its debugger data is preserved, the migration marker is moved to 8, and the real collection migration 7 then runs. Ambiguous partial schemas are rejected without rewriting data. Historical samples/runs remain readable; the updated execution fingerprint rejects old checkpoints until a fresh run.

Debug, proactive analysis and stage chat share the same ordered runner and template-derived country boundary. Proactive-analysis fingerprints also bind country assignments and classification revisions, so a document becoming a secondary national reference invalidates cached results. A guide step sees only results produced by preceding steps. Final citations belong to the last executed guide step; a later retrieval is visible in its trace but cannot retroactively support that guidance. If no guide executed, citations contain the actual retrieved results. Retrieve-step instructions provide a search focus; guide-step instructions enter the configured model request. Check steps execute server rules; their free-text instructions do not create new rules. Draft/verify steps explicitly skip actual mutations and point to the dedicated task actions. Without a model, guide steps run the labelled rule-only demo; free-text writing instructions are not represented as model execution. Provider calls are bounded in time, response size and concurrency; a failed step is visible and stops later steps.

## Cases / tasks
CaseSummary = `{id,title,company,product,mode_id,template_version,created_at,updated_at,completed_tasks,total_tasks,current_stage_id}`.
CaseDetail extends CaseSummary with `{template:Template,revision:number,stages:StageState[],facts:Fact[],documents:Document[],artifacts:Artifact[],events:AuditEvent[]}`.
StageState = `{id,name,actor,description,status:'locked'|'active'|'follow_up'|'completed',tasks:TaskState[]}`. `follow_up` means the stage's blocking tasks are complete but required closeout tasks remain; the UI displays 待收尾 and later stages can proceed. A stage becomes completed only after all required tasks pass. Once the main path completes, `current_stage_id` returns the earliest follow-up stage while progress still counts outstanding closeout tasks.
TaskState = TaskDefinition + `{status:'pending'|'in_progress'|'needs_input'|'completed',needs_review:boolean,revision:number,values:Record<string,string|number>,evidence_ids:string[],confirmed:boolean,verification:Verification|null}`.
Fact = `{key,label,value:string|number,source:string,confirmed:boolean,updated_at}`.
Check = `{id,label,status:'passed'|'missing'|'conflict',reason:string,evidence_refs:string[],task_id?:string,task_title?:string}`. Stage workflow results identify the checked task when applicable; cross-document reported conflicts can omit it.
Verification = `{id,status:'passed'|'needs_input',checks:Check[],created_at,task_revision:number}`.
AuditEvent = `{id,type,title,detail,created_at}`.
- GET `/cases` -> summaries list. POST `/cases` {title,company,product,mode_id,template_id} -> CaseDetail.
- GET `/cases/{id}` -> CaseDetail; all mutations below return updated CaseDetail unless noted.
- PATCH `/cases/{id}/tasks/{task_id}` {values:Record<string,string|number>,evidence_ids?:string[],expected_revision:number}.
- POST `/cases/{id}/tasks/{task_id}/verify` {expected_revision:number,confirm:boolean}. Gate must examine current facts/documents, nonempty fields and evidence validity; required predecessors must pass; facts/evidence edit invalidates old confirmation. Non-required tasks do not gate unless configured.
- GET `/cases/{id}/events` -> list audit events.
- POST `/cases/{id}/stages/{stage_id}/analysis` {expected_revision:number,retry?:boolean} -> `{id,case_id,stage_id,legal_analysis_id,legal_revision,case_revision,status:'completed'|'failed',output,trace:TraceStep[],checks:Check[],citations:Citation[],created_at,assistant_mode:'demo'|'live',retrieval_mode?:'lexical'|'hybrid'}`. Called when entering an unlocked stage. Requires the current case revision; locked stages return 409 `stage_locked`, stale revisions 409 `stale_revision`, and unowned resources 404. Entry always executes QA-01 through QA-06 with the node legal policy (or defaults), persists an editable legal report and may save unconfirmed fact proposals; it never verifies/completes tasks or changes messages or case revision. `legal_analysis_id` identifies the node report and `legal_revision` its latest revision; material changes refresh that report while retaining manual sections.

Analysis is persisted per case/stage/input fingerprint: frozen configuration, task/confirmed facts, applicable document versions/review revisions, artifacts, provider configuration and applicability date. Repeated calls return the stored result (including its original `case_revision`); chat-only revision changes do not trigger another analysis. Failed results require explicit `retry:true` to execute again. Concurrent requests return 409 `analysis_in_progress`; an abandoned claim expires after 30 minutes. Retrieval and generation execute outside write transactions. If relevant inputs change before completion, no stale result is published and the request returns 409 `analysis_stale`.

Stage analysis, legal requests and new debugger runs prepare legacy indexes before capturing their input snapshot. Preparation shares a limit of 20 documents across the actual allowed country scopes. If work remains, the request returns 409 `index_preparing` before any generation call; retry advances the next batch. A completed idempotent response remains replayable. Index revision and reranker configuration and credential changes invalidate relevant analysis caches.

If the linked editable report is being refreshed, node reads return `analysis_in_progress` without replacing the stored node record. After refresh, reads reuse the updated report without another execution. Expired legal reservations are recovered before checking the linked report revision, allowing explicit retries to resume an interrupted refresh.

- POST `/cases/{id}/stages/{stage_id}/analysis/stream` accepts the same body and gates as the JSON endpoint. SSE emits `status`, `start` (legal report ID), actual `step` progress and `done` with `{analysis: StageAnalysis}`. A persisted failed run returns `done` with `analysis.status=failed`; request/context failures emit `error`. A valid cached result emits `done` without fabricated step events. Responses disable buffering/cache. Disconnect or cancellation releases the node claim and keeps the legal record/checkpoint; a later request resumes it. Legal fact snapshots also invalidate cached entries; manual paragraph edits alone do not trigger generation.

## Conversation
Message = `{id,role:'user'|'assistant',content,stage_id,task_id:string|null,created_at,citations:Citation[],trace:TraceStep[]}`.
Citation = `{document_id,title,excerpt,locator:object,source_url?:string,document_version?:number,chunk_id?:string,chunk_hash?:string,source_scope?:'personal'|'system'}`. New retrieval hits bind both the immutable original version and the exact text chunk; legacy stored citations can omit chunk and scope fields.
TraceStep = `{id,label,status:'completed'|'skipped'|'failed'|'running'|'cached'|'cancelled',detail:string,input?:string,output?:string,type?:string,duration_ms?:number,input_data?:object,output_data?:object}`. Input/output strings are bounded public operation summaries, not private model reasoning. Detailed data/timing and live/cached/cancelled statuses are used by the debugger; normal chat/proactive analyses keep the lightweight trace. Skipped operations are never labelled completed.
- GET `/cases/{id}/messages?stage_id=...` -> list.
- POST `/cases/{id}/messages` {stage_id,task_id?:string,content,client_message_id:string} -> `{messages:Message[],case:CaseDetail}`. Message ID makes retries idempotent. Include relevant case facts and retrieved citations; demo assistant clearly labeled in capabilities and trace. Do not pretend to invoke a model when unconfigured. Grounded factual conflict handling and progress reporting should trigger questions, never trust free text as completed state. A live provider is optional via server environment, errors visible.
- POST `/cases/{id}/messages/stream` accepts the same input and cookie authentication, and returns `text/event-stream` with `X-Accel-Buffering: no` and `Cache-Control: no-store, no-transform`. The common response middleware preserves `no-transform` so the Next proxy does not buffer small frames in gzip compression. Ownership, stage/task and completed-request conflicts are checked before streaming headers. Each SSE frame has an `event:` name and one JSON `data:` value:
  - `status`: `{label,step_id?}` describes the current public operation; the first frame acknowledges the request immediately.
  - `start`: `{step_id}` replaces the provisional answer when a guide step begins. Multiple guide steps do not concatenate unrelated answers.
  - `delta`: `{text}` appends text from the configured provider's actual incremental response. Rule-only demo guidance arrives when ready, without simulated token delays.
  - `done`: `{messages:Message[],case:CaseDetail}` is the authoritative, persisted result, including citations, traces and any concurrent-data-change warning. Replace provisional text and deduplicate by message ID. Replaying a completed `client_message_id` returns the stored messages without calling the provider again.
  - `error`: `{code,message}` terminates an unsuccessful stream. An EOF without `done` is an interruption, never a successful reply. Before headers, errors use the ordinary HTTP/JSON envelope.

Both message endpoints share a per-process limit of four generating conversations and one active request per case (`chat_busy` / `message_in_progress`). Streaming errors, cancellation before commit, and incomplete upstream streams do not persist a partial message pair. Disconnect cancels the upstream async model read, including while waiting for its first byte; synchronous retrieval stops at its next workflow checkpoint. A stop racing with a successful commit may leave a complete stored result; retry the same message ID to recover it. No automatic retries or cross-process run recovery are provided. Completed turns retain the existing transactional idempotency guarantee. Streaming uses a bounded queue, heartbeat comments during quiet work, the existing 45-second/1-MB provider bounds and a 20,000-character answer limit. The browser retains provisional text on interruption, offers explicit retry with the original ID, and times out after 60 seconds with no frames.

## Documents / library

- GET `/library/countries` -> `{items:[{country:"ID"},{country:"SG"}],total}`. Available to every authenticated account, including demo accounts; anonymous access returns 401. The directory contains only distinct, sorted country codes from the configured collection definitions (at most 676 two-letter codes). It exposes no plan definitions, collection jobs or private document metadata and performs no collection/configuration writes. Administrative `/collection-plans` routes retain their existing permission checks.
Document = `{id,title,filename,role:'primary'|'secondary',status:'ready'|'failed'|'stored'|'processing',mime_type,size,version,case_id:string|null,parent_id:string|null,tags:string[],created_at,source_url:string|null,error:string|null,chunk_count:number,family_id:string,content_hash:string,country:string|null,legal_level:'primary'|'secondary'|'attachment',classifications:Classification[],source_scope:'personal'|'system'}`. `country` is the immutable country assignment, distinct from editable descriptive metadata and tags. `source_scope=system` identifies a read-only original in the shared official legal library.
- Read-only `processing_detail:{state:'running'|'queued'|'ocr_disabled'|'needs_review'|'failed'|'complete'|'stored'|'incomplete',phase:string|null,retry_after_seconds:number|null}` summarizes task activity and saved text-quality flags. Only a nonexpired processing lease produces `running`; persisted document `processing`, queued jobs and expired leases do not prove execution. A queued embedding phase retains existing readable text. `ocr_disabled` means text verification awaits image recognition that is currently disabled/unconfigured; it does not identify a scanned physical source. `complete` is not legal approval or RAG eligibility. Summaries do not expose request credentials/lease tokens or grant permission to start/retry model work; queued retry timing is null if there is no processing job. Lists batch this read without loading text/vectors.
- GET `/documents?case_id=...&source_scope=personal|system&library_only=true&role=primary|secondary&legal_level=primary|secondary|attachment&country=ID&collection=...&parent_id=...&q=...&limit=100&offset=0` -> allowed personal/shared list. Explicit `source_scope=personal` without `case_id` is the account's upload inventory, including its case files; omitted country lists all assigned countries and unassigned uploads. With explicit `case_id`, personal results remain limited to that case. `library_only=true` explicitly restricts results to `case_id IS NULL` for attachment/relation/collection pickers, so case uploads cannot occupy their pages; combining it with a nonempty `case_id` returns 422 `invalid_document_scope`. ## Legal versions, classifications and relations
`role` describes a file, not its legal tier: a parsed regulation uses file role `primary`, including a regulation that is secondary legal material. Ordinary attachments use file role `secondary`, `parent_id` and `legal_level=attachment`; they remain original-only.

`country:<ISO2>` is a reserved collection namespace. `app.contexts.documents.infrastructure.providers.mineru` owns API parsing for PDF/Office and supported images. Uploads preserve the original and return a processing state; durable workers retain provider receipts, exact source hashes and physical-page bindings. No local OCR completion or ready vector index is implied by a successful upload. `app.contexts.documents.infrastructure.providers.ragflow` owns remote indexing and retrieval, with local ownership, version, country and applicability checks before and after each query.

`app.contexts.documents.infrastructure.parsers.native_parser.parse_file(...)` and the bounded parsing worker handle text/Markdown/HTML. Structured results preserve elements, chunks, locators, source hashes and completeness warnings. Historical PDF checkpoints and their explicit recovery adapters remain under the same infrastructure package for existing evidence and previews; they are not the new-document parsing route.

Pure text helpers live in `app.contexts.documents.domain.text`; legacy embedding adapters are in `app.contexts.documents.infrastructure.providers.embedding`. These internal compatibility helpers do not provide a fallback public vector-search mode. Missing RAGFlow configuration returns `mode: unavailable` and a truthful warning.

Source downloads use `app.shared.infrastructure.http.download`, preserving HTTPS/public-IP validation, pinned destinations, bounded redirects, timeouts, response sizes and streaming original storage. HTTP routes call application services; their URLs and request/response schemas are unchanged by the DDD restructuring.

## Document review and applicability

Document responses also include `metadata`, `metadata_revision` and `reviewed_at`. Metadata is `{kind:'law'|'guidance'|'case'|'business'|'demo',jurisdiction,language,published_at:date|null,effective_from:date|null,effective_to:date|null,review_status:'draft'|'published'}`. These are classification/review data, never claims that a source is legally authoritative.

`PATCH /documents/{id}/metadata` takes `expected_revision` and any metadata fields, returns the updated Document. Stale revisions return 409; inverted date ranges and secondary attachments return 422. Changes are audit-versioned. Editing applicability without explicit renewed approval resets it to draft; associated case tasks and downstream confirmations require review.

`POST /search` accepts `as_of`, `collection` and `country`. A case's frozen template destination determines its country when the configured destination can be resolved; a conflicting explicit country or national collection returns 422 `country_mismatch`. Without a resolvable case country, explicit country and a `country:<ISO2>` collection must agree. For searches without a resolved case country, omitting both selectors or using `country=unassigned` restricts retrieval to unassigned material; national laws are never silently mixed. Unknown destination names are not guessed. Eligible case business materials remain in the case scope.

Within that country boundary, default retrieval selects the latest immutable family version before applying readiness, review and primary eligibility; a pending/failed/secondary latest version cannot silently fall back to an old primary. An explicit historical date can select a reviewed older law with a known start and end period. An old law with an unknown end cannot establish historical applicability after a replacement; legal metadata must be reviewed. In a specified collection, only primary membership in that collection is retrieved. Secondary-only versions and attachments are excluded; a national secondary cannot gain eligibility through an unrelated primary collection.

Search citations carry immutable document/version and chunk/hash IDs, locators, metadata and metadata_revision. Fetched laws begin draft. Ordinary uploads begin business/published, not legal authority. Schema 10 persists chunks, FTS5 terms and float32 vector BLOBs separately from document manifests. Queries apply the same eligibility scope to lexical/vector retrieval, scan vectors in batches of 256, and materialize at most 48 candidates. Old indexes are backfilled within the query scope, at most 20 documents per request, with a visible warning when preparation remains. External embedding/reranking is followed by current eligibility and chunk-version revalidation. This remains a single-host SQLite index, not a distributed vector database.

Schema 11 stores immutable official directory API request evidence separately from the existing checklist page rows. Requests are derived only from trusted, frozen official adapters; their method, parameters, pagination offset and returned source total are included in private archive inventory exports. Public collection response shapes are unchanged. Source totals and completed batches are never claims of whole-country completeness.

Schema 12 adds `collection_transfers` and `collection_transfer_parts` for slow originals with a strong ETag and verified range support. Parts bind the account, item, final URL, ETag, total length and byte offset; each part is published to account-scoped CAS before its checkpoint. Restart reuses saved parts only after path, size and hash checks. A source-version change starts a separate transfer; incompatible parts are never assembled. Completed contiguous parts are verified and atomically assembled before creating a legal-document version. Range progress does not consume the ordinary failure-attempt budget; real failures retain bounded retries. Fast originals remain single streamed downloads. Private inventory format 4 supports schema 7–13 and adds `ocr-regions.jsonl` provenance without transcription, vectors or credentials.

Schema 13 marks existing derived indexes dirty once so the current PDF completeness rules are reapplied in bounded, account-scoped batches. Missing decoded characters, incomplete OCR and independent review warnings remain ineligible. Immutable originals, stored text, review history and current valid vectors are retained; the public response shape is unchanged. Private inventory format 4 supports schemas 7–13.

Schema 16 adds `user_access` for account login permission, administrator role and optimistic revision. Existing accounts retain login access during upgrade; new registrations wait for approval. Role changes and session revocation use explicit transactions. Full backups and private archive inventory accept schema 16. A normal deployment provisions `admin` / `admin123` if that account is absent; `/tea/admin` is the direct login route and `/tea` has no link to it.

## Local configuration

The startup catalog `config/workflows/liubao-export.json` supplies exactly four built-in country/channel routes. `TEA_TEMPLATE_FILE` may override one of these IDs with an exported template. Empty settings load the built-ins; the retired default path `config/workflows/china-indonesia.json` is explicitly treated as the new default for existing `.env` compatibility. Other invalid files or unknown override IDs fail startup. A user's published versions take priority for that user's new cases; frozen case snapshots remain unchanged. File changes are loaded on service restart. The retired `china-indonesia-demo` ID is excluded from template, draft and case lists (including pagination totals), cannot be republished or saved as a draft, and returns 404 on direct template/draft/case access. No automatic deletion of underlying records or files occurs.


## 节点会话与引导报告

- `GET /cases/{case_id}/conversations?stage_id=&limit=100&offset=0`：账号内业务的会话元数据，稳定按创建时间、ID 排序，limit 最大 200；可按节点过滤。
- `POST /cases/{case_id}/stages/{stage_id}/conversations`：`{client_request_id, title?}`，幂等创建真实会话；每节点最多 100 个会话，未解锁节点拒绝创建。返回含 `id, stage_id, title, kind, created_at, updated_at`。
- `POST /cases/{case_id}/stages/{stage_id}/guide-conversation`：确保节点唯一引导会话与首次提问消息，重复调用不重复提问；返回 `kind=guide`。
- `GET /cases/{case_id}/messages` 新增可选 `conversation_id`；提供时只读取该会话，校验其业务与节点归属。未提供时保留旧版节点历史行为。
- 消息 JSON 与流式接口新增可选 `conversation_id`、`mode: auto|legal`、`skills: (guidance|materials|legal|draft|handoff)[]`。流式事件新增 `step`，数据为实际 TraceStep；最终响应格式不变，消息可含 `conversation_id`，引导报告消息附带 `guide_result` 快照（步骤仍由 `trace` 提供）。文稿起草与消息使用同一幂等请求保存，重复提交不重复创建文稿。
- `GET /cases/{case_id}/stages/{stage_id}/guides?limit=20&offset=0`：不可变分析快照列表，最新优先，limit 最大 100，含状态、真实步骤、结果及失败原因。
- `POST /cases/{case_id}/stages/{stage_id}/guides/{guide_id}/retry`：`{client_request_id}`，新建重试记录并返回 `{id}`，保留旧记录。

任务通过核验后登记去重的自动分析任务，后台追加报告；读取会话及引导记录会恢复待执行任务。未配置模型时保持演示说明。完整边界见 [节点工作区](NODE_WORKSPACE.md)。

### 工具过程快照

聊天、调试、法律分析与节点分析沿用 `step` SSE 事件，`TraceStep` 新增可选字段：

- `run_id: string`：本次执行标识；`sequence: integer`：本次执行内严格递增的步骤快照序号。
- `tools: ToolCall[]`：按首次调用顺序排列，最多 128 项；未提供时兼容历史记录。
- `ToolCall = {id,name,label,position,status,attempt,max_attempts,detail,duration_ms,error_code?}`。
- `name` 为 `search_documents | check_materials | search_legal_evidence | generate_guidance`。
- `status` 为 `running | retrying | completed | failed | cancelled`；`attempt` 为当前尝试次数，`max_attempts` 最大为 2，`duration_ms` 含重试等待。
- 重试保持同一工具 `id`。每个 `step` 是完整快照；客户端在原位置更新，同一 `run_id` 下忽略小于等于已接收 `sequence` 的快照。
- 普通聊天也推送实际步骤的开始、工具进度和结束；最终消息 `trace` 保存相同公开记录。工具成功不等于业务任务完成。
- 模型被截断、协议异常或工作流失败时，JSON 和 SSE 聊天都不保存未完成回复；SSE 发送 `error`，不发送 `done`。重试继续使用原 `client_message_id` 的持久化幂等规则。

执行预算、取消与安全重试边界见 [AGENT_TOOLS.md](AGENT_TOOLS.md)。
