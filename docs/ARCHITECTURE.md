# 茶渡系统架构

本说明对应从 origin/main@40e10705d07ef7b4e2775f960e2dce789d8df469 重建的系统。普通问答由一个主 Agent 读取证据、分析并生成答复；业务办理状态由服务端规则和事务处理；采集、解析和索引使用独立后台进程。该说明描述已经实现的组成和边界，不表示真实法律质量验收已经通过。迁移和检查结果见 [重建记录](SYSTEM_REBUILD_20261029.md)，问答运行细节统一维护在 [Agent 运行说明](AGENT_RUNTIME.md)。

## 系统组成与部署

茶渡采用同仓模块化单体。Next.js App Router、React 19 和 TypeScript 负责工作台；FastAPI 负责鉴权、业务服务、对话执行和持久化。SQLite WAL 保存业务记录、版本、执行收据及任务队列；账号隔离的内容寻址存储保存原件。现有单机部署继续使用这些组件，不增加消息中间件、第二套业务数据库或独立法律报告服务。

~~~mermaid
flowchart TD
    U[用户] --> W[Next.js 茶渡工作台]
    W -->|同源 HTTP / SSE| API[FastAPI 鉴权与请求边界]
    API --> A[主 Agent：读取、分析、直接答复]
    A --> E[证据服务：搜索、原文、版本]
    A --> B[业务服务：核对、草稿、授权记忆]
    API --> B
    E --> C[国别原文与语义索引]
    E --> R[RAGFlow 合格资料检索]
    E --> O[受限官方网页读取]
    B --> DB[(SQLite：事实、状态、版本、收据)]
    A --> DB
    P[独立后台进程] --> Q[持久下载与处理队列]
    Q --> F[原件、MinerU 解析、索引代次]
    F --> C
    F --> R
    F --> DB
~~~

前端沿用 DeerFlow 的 UI 和对话组件，茶业务入口为 /tea，管理员入口为 /tea/admin。茶业务只经 frontend/src/core/tea/api.ts 访问同源 /api/tea，由 Next.js 转发到服务端 TEA_API_URL。保留的上游 Gateway、LangGraph 和工作区页面不属于茶渡运行依赖。公共组件、AI 交互组件和茶业务组件分别维护，业务权限与接口调用保留在茶业务模块。

后端装配入口为 app/bootstrap.py，HTTP 应用由 app/interfaces/http/factory.py 创建。模块职责如下：

| 模块 | 对象与职责 |
| --- | --- |
| accounts、administration | 账号会话、访问许可、管理员权限与后端模型配置 |
| workflows | 流程发布、业务快照、节点和任务、材料核验、配置调试 |
| conversations | 对话、主 Agent、工具执行、证据引用、运行收据及显式记忆 |
| documents | 原件与不可变版本、解析结果、国别资料、检索和来源元数据 |
| ingestion | 官方来源适配、发现、下载、导入及持久后台队列 |
| legal_analysis | 法律证据适配，以及保留的人工研究、历史报告和编辑接口 |
| drafting | 文稿与修订历史 |
| shared、configuration | 通用值、存储、HTTP、运维，以及唯一配置和实例位置入口 |

各模块依实际需要设置领域、应用和基础设施代码。领域规则不依赖 HTTP、SQLite、文件系统或模型；应用服务负责权限、事务和版本；基础设施对接来源和供应商。路由只处理请求边界，跨模块协作通过装配后的服务完成。目录和依赖约束由 backend/tests/test_architecture.py 检查，文件说明见 [后端目录](../backend/README.md)。

## 普通问答与工具

在线节点聊天进入 conversations/application/agent_loop.py。主 Agent 读取本轮问题、服务端事实、相关用户笔记和有来源的近期讨论，按需获取证据，随后直接交付正文。普通咨询以两次主模型调用为目标：一次提出取证请求，一次结合原文分析回答；完整原文已提供时可以直接回答。决定性证据冲突或材料缺失允许一轮补检，输出格式损坏允许一次有限修复，均受截止时间约束。两次调用是设计目标，实际次数与完成情况需要测量。

普通问答已移除强制 Task Brief、法律子模型完整报告、报告转换和常规第二次润色。临时主体判断、争点和计划保留在当前上下文，不默认生成长期主体图或义务清单。用户要求多主体交易方案时，主 Agent 按交付需要生成分工与行动表。模型仍须区分法定义务主体、实际办理者、申请人和合同责任方；这一专业判断的准确性通过法律评测检验，字段校验不能替代。

工具注册表同时服务普通 Agent 与 MCP。常用证据、业务资料、材料核对和起草工具直接提供参数定义；技能目录只提供简介，load_skill 按需读取方法。识图等长尾能力可经 tool_search 发现。工具发现不计为取得资料，重复有效参数复用收据，独立只读工具有界并发，业务写入按依赖顺序处理。技能方法保存在 config/agent-skills/，不会替代服务端授权。

法律证据服务向普通问答提供以下操作：

| 操作 | 返回内容 | 使用限制 |
| --- | --- | --- |
| lookup_chinese_law | 中国法规全称与条号精确匹配的原文、位置和出处 | 内置优先，缺项访问第三方公益API，六秒截止时间；接口成功不证明现行有效 |
| search_legal_evidence | 候选原文、规范名称、位置、出处、版本和检索模式 | 按本轮法域与日期检索，候选命中不证明规则适用 |
| read_law | 指定记录或官方地址的相关原文及上下文 | 保留定义、适用范围和例外，未读全时明确标记 |
| get_law_versions | 已记录的公布、施行、修订、失效及替代关系 | 未知日期返回空值，空关系不证明没有后续修法 |

国别资料读取复用精确法名、条号、全文候选、语义召回和排序，引用保留不可变内容版本。相关相邻原文必须属于同一国家、文档和内容版本。上下文超出预算时省略完整单元并保留回读收据，不将截断条文当作完整规则。联网搜索摘要只提供线索，官方原文经受限读取后可参与分析。资料入库、来源真实和编号有效，都不足以单独证明法律结论正确。

中国法精确查询改编自用户提供的 chinese-law-verifier；按需法律方法吸收 china-lawyer-analyst 的规则解释、请求权与事实对应方法。普通问答仍由主 Agent 直接分析和回答，不加载其完整多阶段报告程序。接口边界统一见 [Agent运行说明](AGENT_RUNTIME.md)，接入及实测见 [中国法技能接入记录](CHINESE_LAW_INTEGRATION_20261029.md)。

MCP 入口为 /api/tea/cases/{case_id}/stages/{stage_id}/mcp，使用现有账号会话和业务、节点范围，共用工具定义和执行收据。它提供证据与只读业务能力，普通目录已移除独立报告生成工具。MCP 不接受任意 SQL 或本地文件位置，也不扩大资料权限；协议及响应见 [API 契约](API_CONTRACT.md)。

## 业务状态、数据与证据

一次出口业务包含冻结的流程配置、节点、任务、共享事实、材料和文稿版本。现有六堡茶赴印尼与新加坡的线上、线下手册继续由配置展开为模板。材料已上传、模型建议办理、用户口述完成和服务端核验通过分别记录。任务完成和节点解锁由规则及事务决定，模型文本不能直接修改这些状态。允许并行的收尾任务沿用 blocks_next_stage: false 及 follow_up 语义，业务范围见 [手册流程](LIUBAO_WORKFLOWS.md)。

账号会话使用服务端记录和 HTTP-only cookie。业务、对话、文稿、原件及下载都检查账号和必要的业务归属。公开系统法规库是受限的共享只读资料，账号之间的私有文件继续隔离。国别由不可变国家记录和受控分类约束，自由标签不能改变检索范围。新增字段和结构必须经现有显式数据库升级入口处理，不能在路由或启动时清空数据。

普通问答保存四类内容：本轮问题与事实来源，实际进入模型的证据快照，最终正文与所选引用关联，以及调用、耗时、错误、用量和请求编号。工具候选保存在收据中，未采用的材料不自动成为答复依据。取消或失败时保留已取得的证据和已报告用量，未知用量保持未知。显式用户记忆、编辑过的文稿、业务事实和任务继续使用各自版本管理。

模型、检索和文件处理在业务写事务外运行。消息、获授权的草稿和原话记忆提交前重新检查业务修订；失败、取消和版本冲突不提交这些写入。网络响应正文中的工具协议不能获得执行权限。程序只进行可确定的完整性、编号、日期、归属与授权检查，不自动补写法律条件或修正权利义务。

answered 表示正文通过生成与机械检查，partially_answered 表示存在工具失败或资料缺口但仍有可交付内容；模型、协议或输出损坏记录为 execution_failed。这些是执行状态，均不能替代业务评阅。来源编号有效也不代表条文支持相邻结论。

## 采集、解析、索引与资源控制

采集、OCR、解析、嵌入和官方版本导入由 scripts/run_workers.py 独立运行。聊天 API 默认 TEA_BACKGROUND_WORKERS=external，不会自行启动后台队列；TEA_SHARED_LIBRARY_WORKERS 继续控制队列是否覆盖系统库，不能与前一个配置混用。worker 复用原持久队列、租约、检查点、限流和退避，退出时停止所属执行器。单机可以分别限制和重启聊天进程与后台进程，具体命令、并发和预算见 [Agent 运行说明](AGENT_RUNTIME.md)。

原件下载通过既有 HTTPS、公网地址、重定向、大小和超时限制，来源适配器只解析允许的目录与详情。PDF、Office 和图片正文走 MinerU 云端解析；HTML 与文本走现有结构化入口。解析记录与不可变原件绑定，二级引用法规和普通附件保持各自角色。供应商失败不触发未授权的 OCR，也不伪造解析完成。

合格资料全文检索继续使用 RAGFlow，文档资格、账号、国别、版本和适用期过滤在外调前后检查。独立国别资料包使用自身 SQLite、文档简介向量和条款向量，明确返回 local_pack 或 local_pack_vector，不伪装为 RAGFlow。资料包覆盖、版本及索引状态见 [国别资料库](COUNTRY_LEGAL_LIBRARY.md)。

没有配置 RAGFlow 时，通用检索继续报告 unavailable，国别资料包可以单独可用。向量化未完成时如实提供覆盖率；索引完成、资料效力、规范名称准确和法律适用是不同事项。后台原件与解析、索引代次保留历史，重试遵守原有结果未知和付费请求恢复规则。详细资料管线见 [解析与检索](MINERU_RAGFLOW.md)及[采集运维](INGESTION.md)。

## 界面、恢复与保留入口

stage-chat.tsx 与 use-stage-chat.ts 继续处理节点隔离、输入草稿、流式回复、停止和原请求编号重试。SSE 使用有界队列和取消机制；切换业务、节点或账号后，旧响应不能覆盖当前页面，退出清除私有缓存。正文展示业务建议及必要来源，执行记录在独立位置保留。当前输出是否仍含内部字段或重复文字需要实际评阅，不能因渲染成功即视为合格。

历史法律报告、可编辑段落、节点分析和配置调试继续保留原接口和版本，普通聊天不会调用这些报告执行器。它们用于历史读取或显式研究，停止扩展旧复杂结果结构。重新生成保护人工段落，资料或事实变化后检查原结果有效性；完整边界见 [法律研究入口](LEGAL_AGENT.md)。配置调试保持隔离样例、修订号和服务端检查点，不改变真实业务状态，详见 [调试契约](API_CONTRACT.md)。

macOS 与 Linux 启动器均核验所管理进程的身份和所属工作树。实例配置统一经 configuration/environment.py 与 configuration/paths.py 加载，密钥仅在后端私有文件中保存。启动、停止和构建使用仓库管理命令；生产构建前停止所属开发实例。完整备份与恢复保持数据库、原件和配置的一致性，见 [实例管理](INSTANCE_MANAGEMENT.md)及[数据备份](DATA_BACKUP.md)。

工程检查覆盖权限、版本冲突、事务、工具协议、取消、恢复、引用关联和界面交互。真实法律验收另行检查条件保留、主体责任、规范版本、条文支持及用户请求覆盖，不能由单元测试或构建通过推导法律正确。此前72格矩阵及补测仍有重大法律错误与模型执行失败，见 [精简重构验收记录](AGENT_EVIDENCE_REFACTOR_20261029.md)。重建工作树不会抹除这些问题，当前系统仍处于研发验收阶段。
