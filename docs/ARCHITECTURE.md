# 茶渡架构与实现边界

## 系统上下文

一次出口业务拥有配置快照、串行主体阶段、并行任务、子对话、共享事实、材料版本与文稿版本。模型输出是带证据的建议；业务状态由服务器规则和事务控制。当前内置六堡茶赴印度尼西亚／新加坡的线上、线下四条手册路线，旧演示流程及业务入口已下线。`workflow_catalog.py` 将共享任务展开为现有模板，沿用发布与快照机制；单选办理结果由服务端检查通过值，等待或异常不能自动完成。`blocks_next_stage: false` 允许必办收尾任务与后续阶段并行，此时阶段为 `follow_up`，全部必办任务通过后才完成；线下 E08 核销采用此规则。手册保留来源指纹及待复核状态，不冒充已审核法规；范围及人工核验边界见 [LIUBAO_WORKFLOWS.md](LIUBAO_WORKFLOWS.md)。

## 前端来源与边界

当前全栈采用 Next.js App Router / React 19 与独立 FastAPI 服务：前者负责页面与交互，后者承载 Python 文档解析、持久化和受控业务接口。解析与采集依赖 Python 生态，故保持同仓模块化单体和类型化 HTTP 边界，不为追求单一运行时引入第二套业务后端。前端组件按共享 UI、AI 交互元素、茶业务组件和页面编排分层；`components/ai-elements` 是本仓维护的可复用交互组件目录，茶业务复用其中的对话滚动、Markdown、执行步骤和任务状态，不直接耦合 DeerFlow Gateway。

后端采用同仓模块化单体，按业务上下文分层。入口 `app/main.py` 创建 ASGI 应用，`app/bootstrap.py` 是服务装配和既有内部调用的显式门面。顶层不再放置业务模块，也不通过动态导入别名维持旧目录。

```text
backend/app/
├── main.py / bootstrap.py / paths.py
├── interfaces/http/           # 应用工厂、请求边界、按业务分组的路由
├── contexts/
│   ├── identity/              # 账号、会话、访问权限
│   ├── workspace/             # 流程配置、业务、任务核验、调试
│   ├── conversation/          # 对话、节点记忆、工具执行
│   ├── knowledge/             # 原件版本、结构化解析、审核、检索
│   ├── collection/            # 来源清单、发现、采集、导入
│   ├── legal/                 # 法律事实、分析、人工修订
│   └── drafting/              # 文稿及其历史版本
└── shared/
    ├── domain/                # 错误、时间/标识、国别及通用值约束
    ├── application/           # 公共契约导出、流式事件
    └── infrastructure/        # SQLite、原件存储、受限 HTTP、运维和 vendor
```

上下文内部按实际职责设置 `domain`、`application`、`infrastructure`，不创建空目录凑层数。领域层保存纯规则和类型，禁止依赖 HTTP、SQLite、文件或模型服务；应用层组织用例、事务、版本和权限核验；基础设施负责供应商、解析器、来源适配和存储。现有 SQLite 查询投影与事务编排继续保留在所属应用服务中，不在本次目录重构中替换数据库或增设 ORM。跨上下文操作经装配后的显式服务协作，冻结快照与原事务边界保持一致。

`Service` 原有用例已分别归入模板配置、业务任务、资料库、对话、文稿、来源服务。输入输出类型定义在各上下文的 `application/contracts.py`；`shared/application/models.py` 仅显式汇总公共 HTTP 契约。路由按相同业务边界分组，只执行输入校验、鉴权、调用和响应；下载、元数据更新、文稿历史和来源详情的数据库读取由应用服务处理。

原混合解析模块已拆为文本/HTML 与历史 PDF 清单处理、纯文本评分、受限 HTTPS 下载、供应商适配。新资料仍走 MinerU 云端精准解析和 RAGFlow；历史解析器与检查点适配器只为既有证据、预览和明确的恢复操作保留。模型 HTTP 流和密码散列也归入各自基础设施。

`test_architecture.py` 用三个边界检查约束领域依赖、HTTP 持久化访问和顶层模块布局。测试范围与精简原则见 [TESTING.md](TESTING.md)。

参考组件和架构时遵循原仓库许可证和模块边界。`tmp/ZCode` 仅作参考，不作为运行依赖；vendor 的源码、许可和来源说明随目录完整保留。

### 前端组件路线

- `components/ui` 管通用视觉基础，`components/ai-elements` 管流式对话、提示输入和工具状态等 AI 交互原语；跨业务组件从其 `index.ts` 公共导出进入，`components/tea` 管茶业务视图，页面负责组合而不复制 API、权限或状态规则。
- 复用组件通过明确 props / 类型暴露能力；业务特化包在外层组合，不向通用组件注入业务服务。
- 保留已有 AI Elements 实现并按实际用户旅程优化；不重复安装第二套组件库，也不为套用参考项目而替换已验证的输入、取消、草稿和流式行为。

用户指定 `tmp/deer-flow` 为前端基础。其 frontend 完整复制至本项目 frontend/，保留许可和现有源码，新增 /tea 页面及 components/tea、core/tea 模块，实际复用 DeerFlow UI 与会话组件。原 /workspace 认证和 LangGraph 运行时依赖另一套 Gateway；已评估原扩展入口，它也依赖此 Gateway 认证，故茶业务以独立页面/API边界接入，不修改原 Agent loop。

这是 DeerFlow 前端上的业务工作台，不是 Vite 重写或另一个无关模板。原上游页面保留为参考，茶渡导航只指向已接入页面。

茶业务沿用原版的单条可折叠侧栏、48px 顶栏和可调宽度的右侧面板，直接组合保留的 `SidebarProvider`、`Sidebar`、`SidebarInset` 与 `ResizablePanelGroup`。侧栏按业务分组，当前业务默认展开，组内包含各节点对话与独立资料库；资料页的范围绑定所选业务，按账号和业务重新挂载，切换时取消旧读取与检索。公共资料库、法务与来源管理收进账号菜单。默认只展示业务目录、对话和输入框，任务与文稿等详情按需展开。全局主题是配色和控件样式的来源，业务样式仅补充布局与状态反馈；具体界面保持简洁商务，覆盖桌面及手机。侧栏接入茶业务回调，不依赖上游 Gateway 的导航或账号提供器。

主对话由 `components/tea/stage-chat.tsx` 展示，复用原版 `Conversation` 的跟随/脱离底部行为和安全 Markdown 渲染；用户发送后立即显示消息，输入框清空后可继续编辑下一条。`core/tea/use-stage-chat.ts` 管理加载、临时回复、停止和原编号重试，草稿按账号、业务、节点隔离；离开节点取消当前连接，保留未完成请求的恢复入口，退出/会话过期时清理聊天缓存。流式传输统一经 `core/tea/api.ts`，不使用上游 LangGraph/Gateway。

`app/shared/application/streaming.py` 把现有同步工作流的公开进度、真实模型文本增量转成 SSE，通过有界队列控制缓冲并响应断连。`assistant.py` 仍拥有步骤顺序及引用边界，`tool_runtime.py` 为实际检索、检查和模型调用统一严格入参、预算、取消、安全重试及公开执行记录；聊天、调试与法律工作流共用这层执行边界（见 [AGENT_TOOLS.md](AGENT_TOOLS.md)）。多个指导步骤重置临时正文；最终结果按原消息服务事务保存，未完成回复不写入消息表。JSON 与流式入口共用归属检查、生成并发限制及持久化幂等规则；不增加数据表、消息中间件或独立代理循环。演示模式直接返回已生成的规则指导，不伪造逐词生成。

对话请求按稳定前缀优先组织提示。Aerisun `deepseek-v4.1-flash` 将系统指导和案情上下文放在变化的历史消息与本轮输入之前，使用网关自动前缀缓存；流式请求显式索取 usage，并记录供应商提供的缓存命中、未命中和写入 token 数，不记录对话正文。调用 OpenAI 官方端点时，聊天附带按账号、业务和节点稳定生成的匿名 `prompt_cache_key`。其他自定义 OpenAI 兼容端点不接收 OpenAI 专属缓存字段。实际缓存仍取决于模型支持、提示长度及平台命中情况。

## 业务服务

- FastAPI 只暴露经过验证的输入；所有私有资源查询包含账户归属。
- SQLite WAL 为单机演示提供真实持久化，事务保护门禁、版本和幂等；数据库迁移带版本记录。
- 配置发布生成不可变版本；运行中业务使用冻结快照。
- 后台流程配置与节点分析编辑共用账户内的版本化草稿；保存允许尚未完成的表单，校验/发布仍要求完整有效配置。发布同时检查模板版本与可选草稿修订，避免覆盖他人的修改。
- 资料和规则变动不会抹掉历史完成事实，而会使相关有效性需要复核。
- 文稿保存采用乐观版本控制，避免覆盖用户改动。
- 账户会话为服务端记录与 HTTP-only cookie；原文件下载同样鉴权。

## 节点分析与配置调试

每个阶段可通过 `analysis` 定义独立工作流，未配置时继承模板 `agent`。进入已解锁节点时，`app/contexts/workspace/application/studio.py` 自动调用持久化的六步法律分析，将执行进度与可编辑结果放在主对话开头。节点聊天与样例调试根据 `legal.enabled` 选择六步引擎或 `app/contexts/conversation/application/assistant.py` 的顺序执行器；配置决定指导可使用哪些检查和引用。未执行、停用或仅提供业务入口的步骤明确标为跳过。步骤摘要展示实际输入/输出，不展示内部思考，也不把起草或核验建议写成已办理。

分析过程把已保存的业务字段整理为中文摘要、问题清单、事实记录、适用范围与待补事项，长列表按需展开。原始输入输出与运行说明保留在默认收起的“技术记录”中；旧记录复用可读数据组件。步骤执行完成、依据缺失、结论待核实和服务失败分别展示，呈现层不推断或改变业务状态。

`app/contexts/workspace/application/debugger.py` 管理持久化样例、运行历史、预期评估和服务端检查点；结构版本 8 在事务中加入 `debug_samples`、`debug_runs` 及其分页索引，保留已有数据。样例保存完整配置快照、测试输入和资料版本，更新使用修订号。所有读取、执行、恢复和删除都校验账号归属；资料范围由服务端按配置目的地解析国家，只包含当前账号该国家的共享一级资料，未知目的地仅使用未分国资料。候选列表、样例保存和运行使用同一规则，不把其他国家或其他业务的私有文件带入调试。

完整运行、运行到步骤、单步重跑与从步骤继续都调用同一执行器。恢复前验证上游前缀指纹，覆盖输入、步骤配置、资料内容及审核/索引状态、适用日期和模型环境；不能由客户端构造检查点，也不能复用过期结果。调试记录保留实际步骤输入输出与耗时，普通聊天继续只保存紧凑摘要。流式调试复用有界 SSE 传输、超时和取消机制；外部调用在写事务之外，停止后保存已完成的检查点。资料选择不等于任务材料关联，调试不产生业务状态变更。

前端 `use-workflow-debugger.ts` 按账号、配置和节点隔离临时状态，退出清理私有缓存；记录与样例均分页读取，历史有容量上限。取消后通过服务端记录编号恢复检查点，旧请求不能覆盖新页面。右侧编辑栏共用配置与调试入口，结果、对比和记录按需展示。执行完成与预期通过分别记录；没有有效生成结果时回答预期不评为通过，人工要求不冒充自动评估。

`app/contexts/workspace/application/studio.py` 保存草稿及主动分析。结构版本 3 在显式事务中添加 `template_drafts`、`stage_analyses` 和资料筛选索引，保留已有业务。主动分析绑定冻结配置、任务/事实、资料与审核版本、文稿及适用日期；页面重访复用结果。执行前占用带期限的分析记录，外部检索/模型调用在写事务结束后进行，完成时重新核对数据指纹。并发重复执行返回“正在分析”，资料中途变化拒绝旧结果；失败结果可明确重试，不改变业务修订或任务状态。

## 可编辑法律 Agent 初版

法律工作台由 `legal_models.py` 定义规则与结果，`legal_engine.py` 协调 QA-01 至 QA-06，`legal.py` 处理账号隔离、版本、幂等和报告编辑。六个模块共享事实、争点和引用，公开记录实际输入输出与检查结果。模型只提出建议；引用范围、事实状态、期限计算、版本冲突及业务任务门禁由程序控制。

`AgentConfig.legal` 是可选规则配置；节点开始固定执行六步，未配置时使用默认规则。`legal.enabled` 决定普通聊天与样例调试是否使用六步引擎。节点分析不另设面板：主对话展示步骤状态、结论和下一步，事实、依据与报告按需展开编辑。`stage_analyses.payload` 关联该节点的 `legal_analysis_id` 与修订号；资料变化沿用同一报告重跑并保护人工段落，缓存同时检查业务指纹和法律事实快照。普通聊天仅接收仍有效的报告摘要与人工修订，失效时仅提示更新，不引用旧结论。SSE 复用有界传输与取消检查点；前端运行按账号、业务、节点共享进行中的请求，切换或退出取消旧请求，返回节点从服务端读取。规则卡保留适用领域/法域、条件、必要事实、执行要求、人工处理和输出要求等编辑点；固定程序检查不能通过卡片停用。配置继续使用已有草稿、校验、发布和业务快照。

结构版本 9 在单个事务内添加 `legal_facts`、`legal_fact_versions`、`legal_analyses`、`legal_analysis_versions`、`legal_requests`，保留旧库数据。任务事实同步为有修订号的分析事实；用户确认、提取确信度、证据核验分别保存，冲突处理保留历史来源。事实核验使用固定版本的主文件；审核撤回、适用期或资料版本改变会使旧核验需要检查。分析不会自动核验或完成业务任务。

分析占用持久请求标识和有期限的运行资格，模型/检索在写事务之外执行。完成时重验事实、配置、来源审核/版本、适用日期与模型环境；过期结果不能覆盖当前报告。取消/失败保留检查点，只有上下文与资料仍有效时才复用。事实变更沿争点依赖传播；资料或配置改变、映射不明确时采用保守重跑。历史分析与段落编辑使用修订号，旧窗口保存返回 409。

重新生成保留人工正文，并单独提供更新建议。若重新分类改变了同编号争点的含义，原人工段落保留在原标题下，需人工核对关联。界面把事实、争点结论与可编辑报告分开；缓存按账号、业务、阶段隔离，退出清理私有草稿。详细入口、上限和初版边界见 [LEGAL_AGENT.md](LEGAL_AGENT.md)。

法律检索使用配置允许的来源国、目的国及附加法域，逐国复用已有审核、版本、权限与正文资格过滤。原 `/search` 目的国限制保持原语义。它只检索已有合格资料，不自动宣称已完成互联网法律调查；资料未命中、关联检索不完整、未配置模型和轮次耗尽均保留可见缺口。

## 资料与检索

当前正文管线由 MinerU 云端精准解析和本机 RAGFlow 承担，部署、回执、结构版本 20/21、索引代次和并发规则见 [MINERU_RAGFLOW.md](MINERU_RAGFLOW.md)。历史原生解析和 OCR 检查点继续保留供追溯。

GEO-System/原 Admin-System 文档解析器抽取到独立 vendor 包，保留来源记录。法规正文结构化、切片；一级法规建立检索，二级引用法规保留文本和版本关联。普通附件独立使用文件 role/parent_id，仅保留原件。一级/二级是采集组中的法律分类，一份法规可属于多个组。

资料库支持按主文件、关联附件和文件名检索；附件查询仍校验父文件账户和业务范围。结构详情分别分页读取解析元素与检索切片，并返回总数、解析器和提示。接口不返回向量，普通附件详情仅展示原件元数据。版本和双向法规关系可分别分页查看，标签/分级编辑使用修订号。

法规的国家边界由 `document_countries` 与 `country:<ISO2>` 分类共同约束，不由自由标签或可编辑法域说明推断。国别确定后不可改绑另一国家；一级／二级锚点与关系须在同一国家。检索优先服从业务快照中的明确目的国，冲突的显式国家被拒绝；未指定国家时仅查未分国资料。各国家的原件可以在账号内容存储中复用相同字节，法规家族、版本、分类与检索范围仍独立。

用户明确指定的系统法规总库由 `app/contexts/knowledge/application/system_library.py` 提供共享只读边界，使用同一实例数据库与不可变原件结构，不引入新的表或结构版本。官方原件由不可登录的固定内部身份持有；明确的国家政府域和计划中固定国际文件域通过服务端校验，不能通过用户标签或网页扩大受信范围。登录用户在相应国家资料列表中读取总库原件、正文、下载、历史及关系；所有修改仍要求原 owner，其他账号的私有资料继续隔离。`source_scope=system` 让界面关闭原件编辑与附件写入操作。

共享 RAG 合并用户私有合格资料与允许国家的总库一级资料，继续核对国家、不可变版本、完整当前索引和适用期。总库还要求已发布审核、真实非体验审核人员及审核时间、已核定生效起日；草稿和未知效力原件只能展示采集状态。普通附件只保存原件，独立二级法规可文本化但没有向量资格。法律分析快照包含相关国家总库的原件、审核、分类和索引修订，变化后需要复核；既有私有资料资格不附加这一总库审核门禁。运营导入和权限细节见 [SYSTEM_LIBRARY.md](SYSTEM_LIBRARY.md)。

资料目录显式区分总库与个人上传：个人目录可按账号汇总各业务、各国和未分国资料，业务视图继续限定业务。全文检索仍保持国家边界，来源范围在索引回填、词项与向量候选以及外部重排回流后统一校验。编辑候选器使用 `library_only` 保持库外资料的准确分页。数据分层和迁移升级见 [DATA_PLATFORM.md](DATA_PLATFORM.md)，全账号实例备份、校验与新目录恢复见 [DATA_BACKUP.md](DATA_BACKUP.md)。

无生成模型凭据时使用明确标记的演示助手；缺少 RAGFlow 配置时明确显示检索未就绪。真实生成和 embedding 仍使用后端云端凭据。来源采集仅允许受限 HTTPS 公网地址，校验每次解析及重定向，限制时间、体积和直接附件数量。

`app/contexts/knowledge/application/archive.py` 管理不可变版本家族、分类历史及固定版本的多对多关系；`app/contexts/collection/application/collection.py` 管理持久下载和处理队列。`app/shared/infrastructure/blob_store.py` 以账号隔离的内容寻址对象保存字节，下载流写入后先原子发布，再事务提交引用。结构版本 4–6 显式升级旧库。网络、解析和模型调用在事务外执行，提交验证租约，重启从数据库恢复。每域真实连接限流覆盖重定向和取消，向量按 64 段保存进度。运行参数和容量边界见 [INGESTION.md](INGESTION.md)。

`app/contexts/collection/application/checklists.py` 加载 `config/collection-plans/*.json`，目前只有印尼 5 章 29 项；后续国家沿用同一格式，保留各自国别、版本和来源文档指纹。结构版本 7 增加账号内计划绑定、发现队列、目录证据、正文候选与不可变国别。`app/contexts/collection/infrastructure/discovery/discovery.py` 负责受限链接发现，复用现有下载队列；每批最多 40 页，未处理入口持久保存，下批继续。目录字节保存在内容存储中供追溯，不进入正文解析或 RAG。选择候选后另建原件采集任务，明确分级并保持默认待审核。

结构版本 16 在独立 `user_access` 表保存账号的登录许可、管理员角色及修订号，升级时保留已有账号的登录权限，新注册账号默认待开放。管理员后台路由与账号权限 API 在服务端校验角色；权限更新采用修订号与事务，停用账号会删除其会话，最后一位可登录管理员不能被停用或降级。正式部署在保留账号缺失时幂等创建 `admin` / `admin123` 初始账号，不会重置已有账号；管理台直接从 `/tea/admin` 进入，茶业务页不提供管理台入口。

后台按章节显示进度，原始要求在详情折叠展开。链接适配不替代法律语义筛选：印尼普通案例的涉企范围、裁判日滚动五年及法规效力仍需核验，当前未自动判断这些条件。29 项配置齐全与全部网站正文取得分别验收；403、动态内容、缺附件及适配不足均保留可见缺口。

## 故障语义

401 引导登录；404 同时用于不存在或无权访问的资源；409 表示版本过期或阶段锁定；422 显示字段或配置错误。解析/检索/模型故障必须可见，不以空成功或伪造答案掩盖。加载、重试、保留输入和版本冲突都属于界面行为。

## 部署范围

当前交付是单机可运行的 Demo 与模块化基础，数据库、原始文件需成套备份。多人正式生产部署前应完成真实法务清单与来源审核、真实模型检索评测、负载容量验证，以及组织角色/数据留存策略。SQLite 单写者约束需要在规模触发时迁移，不能仅增加 API 副本共享文件数据库。

## 验证

业务测试覆盖隔离、配置版本、串行门禁、缺项与冲突、附件分流、旧版本核验、文稿版本、重启恢复。浏览器检查覆盖桌面/手机布局、真实 API 操作、错误展示和完整核验路径；上游 DeerFlow 未接入功能不在本次功能验收范围。
