# 分页原生证据恢复

`scripts/recover_archive_native_pages.py` 将已经取得的完整 PDF 分页证据接回原文档的解析、OCR 和索引流程。它适用于单次原生解析窗口失败、但小窗口提取成功，且整篇仍符合现有聚合限制的文件。恢复本身不下载、不调用模型、不改变法规审核结果。

原件、账号、文档 ID、不可变版本、当前 manifest 摘要和分片根摘要必须全部匹配。入口只接受独立采集库里的草稿法规，不接管正在处理的租约，也不直接修改项目默认业务数据库。先使用只读模式核对，再加 `--apply` 应用同一冻结输入：

```sh
uv run --project backend python scripts/recover_archive_native_pages.py \
  --data-dir /absolute/collection-data \
  --owner collection-owner \
  --document-id immutable-document-id \
  --source-hash ORIGINAL_SHA256 --version 1 \
  --expected-manifest-sha256 CURRENT_MANIFEST_SHA256 \
  --shards-dir /absolute/native-page-shards \
  --expected-root-sha256 ROOT_SHA256
```

恢复会重新核验真实 PDF 页数、原件哈希、每个分片和物理页的摘要、完整有序覆盖及既有页证据。已有非占位页必须逐字段一致；新增页只允许原生提取证据，不能夹带识别结果或冒充付费请求。整篇元素和分块仍由受限工作进程统一重建，因此跨分片的 Pasal、正文与 PENJELASAN 上下文保持连续，分块标识不会按窗口重新从零开始。

原有 manifest、冻结根、所有分片和它们的依赖先写入原账号的不可变 CAS，使用相对路径引用，再进行短事务提交。提交前再次检查版本、manifest、原件元数据和任务租约。原文版本、来源、国家、家族、分级和关系保留；扫描页继续等待 OCR，正文完整性门禁继续决定检索资格。入口不批准法规，也不凭分片齐全将正文设为完整。

重复执行须使用最新 manifest 摘要。全部页已相同时返回 `unchanged`、零数据库写入；使用旧摘要会返回冲突。成功原生恢复不会触发新的识别请求，后续由现有持久任务队列处理缺失正文和向量。

现有 4,000,000 字符、40 MiB 聚合结果和 20,000 个元素的限制保留。超限文件返回明确的分段存储缺口，保留其独立分页证据；此入口没有提供超限全文的流式 OCR、分块、前端预览或索引实现。

## 实际验证

2026-10-19，在独立 Setneg 采集库恢复了 `Lampiran Tarif Chile Versi Bhs. Indonesia.pdf`：原件 26,312,229 字节、191 个物理页、12 个原生分片。正式恢复将 191 页接回文档，原生解析待办为零，全部 191 页仍需 OCR，分块和向量均为零。重复执行零写入、零模型请求；原件 SHA 再次核验通过。原有其余 2,992 份文档逐字段摘要不变，原有文档范围的元数据、历史、分级、关系和向量摘要不变。采集器同期新增了文档，因此对已有固定集合进行比较，不能要求全库行数静止。该文件尚未导入共享总库 D。

另一个 LKPP 5,964 页附件含 12,037,417 字符、48,339,935 字节原生分片，继续保留分段存储缺口；没有提高聚合限制或把它计作可检索全文。

相关回归覆盖跨页法条上下文、来源与版本冲突、活动租约、损坏分片、缺页、旧页保护、伪装 OCR 输入、并发变更、显式应用、扫描件检索门禁及正式备份恢复。独立的 16 项入口测试通过，包含所有证据 CAS 的备份恢复；与原生归档和检查点恢复的关联回归 118 项通过（当时入口测试为 14 项，随后补充上述备份与扫描件两项）。这些检查不代表两国全量已采集或超大附件已经进入 RAG。
