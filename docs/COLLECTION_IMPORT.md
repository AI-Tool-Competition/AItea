# 把服务器采集成果加入应用总库

服务器采集目录中的数据库和账号各自独立。应用默认使用当前工作树的 `data/tea.sqlite3`，不会自动扫描 `data/campaigns/`。采集任务创建的体验账号没有可供用户选择的登录入口。原件、正文和真实向量已经采集成功，也不等于当前应用账号可以访问这些资料。

`scripts/import_collected_resources.py` 提供显式的服务器导入入口，底层模块为 `app.contexts.ingestion.application.collection_import`。它只向已存在的目标归属转移指定来源账号的公共法律资料，不复制用户、会话、登录凭据或业务数据，不切换运行中应用的数据目录。系统总库的外层接线负责创建没有登录凭据、没有会话的内部归属，并显式准入公共法源；本工具不创建这种归属，也不把任意体验账号当作系统总库。通用导入仍可用于有明确授权的既有私人账号，私人资料保持账号边界。

从仓库根目录预检：

```bash
uv run --project backend --locked python scripts/import_collected_resources.py \
  --source-dir data/campaigns/<采集目录> --source-owner <采集账号ID> \
  --target-dir data --target-owner <系统总库已创建的内部归属ID>
```

默认只读。预检显示原件、完整正文、可以复用的向量、已校验账号 CAS 原件和关系数量，以及阻塞原因；不会初始化目标目录、创建归属、发布法律资料或调用模型。目标归属不存在时明确显示 `target_owner_not_found`。由已获授权的系统总库接线指定目标后，在同一命令追加 `--apply` 执行。源新增同版本解析检查点时，必须显式追加 `--refresh`；目标正文、元数据、用途分级已变化或存在活动处理租约时拒绝覆盖。

需要分批迁移已完成资料时，可重复追加 `--document-id <来源文档ID>`，每次选择 1 至 200 个不同的来源账号文档。省略时仍导入该账号的完整范围；预检中的 `selected_document_ids` 列出实际选择。正文、向量和 CAS 校验仅覆盖所选范围，因此其他资料的缺失原件或未完成处理不会阻塞这一批。ID 不存在或不属于来源账号时直接拒绝，不读取其原件。

选择范围必须包含普通附件的父文档，以及所选资料现有法规关系的另一端。缺少关系端点时返回 `selected_relation_dependencies_required` 和应补充的来源 ID；工具不静默丢弃关系，也不自行扩大迁移范围。整套关系登记证据仍校验原件和固定版本。选择单个版本不能绕过家族历史检查：来源家族存在其他版本时仍拒绝，直到支持保留完整版本链的迁移流程。

增量采集发现的新资料可能关联已导入的法规。此时把旧法规的来源 ID 同时列入 `--document-id` 和 `--existing-dependency-id`，后者可重复；总选择范围仍不超过 200，必须另有至少一份非依赖资料，并且不能与 `--refresh` 同用。工具核对旧法规唯一的导入出处、原件字节、账号、家族、版本、来源 URL、国家和所需采集组，仅绑定其既有目标 ID。不会重写旧法规的正文、识别结果、向量、元数据、分类或处理任务，因此允许该依赖正在识别或向量化。预检后在写事务内再次核对身份；依赖缺失、歧义或不一致时拒绝，不临时创建替代资料。

`existing_dependency_documents` 与 `existing_dependency_ids` 单列这些只读依赖，`import_documents` 为其余资料数，`target_writes` 继续表示新建文档数。新关联仍绑定具体原件版本和未审核证据，不改变已有法规的等级或效力。未声明为依赖的旧资料继续执行原有修改冲突和活动租约检查；该选项不能用来刷新或覆盖已完成的 OCR。

选择模式也会从关系 registry 派生所选端点的完整子图，保存 `selection_provenance.source_registry_sha256`、来源关系数和本次关系数。涉及已选端点的边必须完整保留；边的另一端未选择时以 `selected_registry_dependencies_required` 拒绝，不导入其他无关资料的原件、页面图或关系。原 registry 的 CAS 字节与摘要保留，所选子图另存为目标账号的派生证据。

同一批可以包含最多 32 份独立关系 registry，每份不超过 4 MiB，总计不超过 32 MiB。每份各自校验来源归属、摘要和子图，不把独立登记记录混成无法溯源的单一证据。`registry_sha256_by_source` 给出来源摘要到目标派生摘要的映射；只有单份 registry 时兼容字段 `registry_sha256` 才非空。

同一批证据中的路径别名必须唯一对应一个摘要，重复指向同一原件允许复用。不同 registry 或下载收据把相同路径声明为不同内容时，预检以 `ambiguous_blob_alias` 拒绝；相对路径展开及目标 CAS 路径也执行这一检查。可把互不关联的登记证据分批迁移，或先修正来源的路径命名，不能靠后读取的登记记录覆盖已有映射。

目标为系统总库时，预检逐件检查官方来源、国家及无业务归属；主文件和普通附件都必须通过。出现 `system_source_required` 时在复制任何 CAS 文件或初始化目标服务之前拒绝执行，不能先把私人或非官方原件转存到公共归属再拒绝入库。

显式 `--refresh` 会在来源检查点相同的情况下仍重新应用来源映射，可用于修复导入工具生成的派生路径；无活动租约、目标保护摘要和来源元数据/用途一致性条件仍必须通过。不带该选项的同快照请求继续保持幂等；刷新不创建原件新版本，也不覆写已修改或正在处理的目标资料。二次映射优先保留已经校验的目标 CAS 地址，不能把 PNG 路径按其父 PDF 的摘要替换。

首版只导入每个法规家族唯一的版本 1。存在多版本家族时预检显示 `unsupported_multiversion_family`，执行被拒绝，避免重导 A→B→A 时错误地产生新版本。源数据库使用只读事务快照；允许源任务继续处理，导入范围只代表预检所记时间的已保存检查点。普通关联附件仍只保存原件，不解析正文、不创建处理任务或向量。

所有原件和识别图片从源账号 CAS 校验摘要后转存目标账号 CAS。正文保留完整性和待核页；用途分类、法律资料类别、草稿状态和适用日期保留，不能变成普通已发布业务资料。固定版本关系使用新的目标资料标识；关系 registry、双端页面证据与派生映射保存在目标账号 CAS，保留原始资料标识、版本、摘要及派生映射原摘要，避免继续指向另一采集账号或旧服务器目录。同账号 OCR 复用证明不能跨账号宣称，首版拒绝包含这类证明的来源。

来源 `campaign.json` 中与所选文档绑定的目录页、详情页、下载收据及映射原件也纳入迁移。工具读取这些证据声明的摘要，并只从已验证的来源账号 CAS 取得字节；旧路径仅作为别名。目标 manifest 的 `collection_evidence` 固定保存原记录摘要、原件摘要和已重绑定的记录。来源证据变化属于检查点变化，仍须显式刷新；预检先验证证据和整个 manifest 的转换，避免执行到复制原件后才发现未映射的服务器路径。

原生图像的 `mapping_path`、`asset_mapping_path` 可以是固定格式的 JSON pointer，例如 `/html_source/linked_images/0`；这些定位不作为磁盘路径读取。其他绝对路径、越界 pointer、路径穿越及未映射的私有路径继续拒绝。HTML 原图的账号 CAS 路径属于图片输入身份的一部分，因此跨账号迁移会验证旧检查点，保存 `collection_asset_import` 中的原 asset/input 身份及检查点摘要，再计算目标身份、重绑定 OCR 检查点并重建图片文本块。原图和供 OCR 使用的 PNG 都复制到目标账号 CAS；图片文字、来源定位和识别次数保留，不重新调用图片模型。图片块 ID 改变时，只将已验证且输入摘要未变的向量映射到新块，不能仅改路径后继续使用失效的检查点。

只复用完整原文且为一级用途的真实索引向量。源向量必须与当前配置指纹、实际分块输入、维度、有限值和单位长度全部匹配；目标未配置同一 embedding 时不导入向量，保留待建索引状态。正文已经完整、向量仅生成部分时，逐条校验后转移已经保存的真实向量缓存，保留缺失分块，不写整份资料的 `embedding_fingerprint` 完成标记；资料状态保持处理中，任务从 `embed` 阶段继续，复用缓存后只请求缺失输入。即使缓存已覆盖全部分块，来源还没有整份完成标记时，也由后续任务核验完成后写入，导入不抢先宣告完成。预检中的 `reusable_vectors` 包含这些已验证缓存，`partial_vector_cache_documents` 单列仍待结束向量处理的资料数；两者不能替代全文向量完成或正式 RAG 数量。

工具可以继承当前进程模型配置，也可用 `--models-env <私有配置文件>` 加载既有采集配置，不输出密钥、不调用模型。显式刷新时配置不匹配会清除本工具先前导入的向量，避免旧向量被标为当前完成。二级资料保留文本和关系但不导入向量。事务失败回滚资料、分类、关系和索引；已发布的不可变 CAS 文件可能保留为未引用原件，不删除其他数据。

导入已完整正文时不会再排一次解析或 OCR。当前配置下全文向量及完成指纹均通过验证的一级资料、无需向量的二级资料，以及未配置 embedding 的完整资料，处理任务直接记录完成；缺向量或缺完成标记的一级资料只排 `embed`。未配置模型时不写向量完成指纹。未完成的正文仍排解析，失败响应诊断 CAS 作为非检索证据随原件迁移，不能作为正文或绕过完整性检查。

导入后，由应用总库接线提供原件、正文和版本关系的只读访问；通用工具本身不扩大任何用户的读取权限。向量可以提前准备，正式 RAG 仍要求完整正文、一级用途、国家和版本选择以及法律审核。资料保持草稿，因此导入后不会自动出现在回答引用中；通过既有或系统库限定的审核流程核定来源和日期后，才进入相应国家和业务的检索范围。使用同一 embedding 配置才能继续使用已导入的真实向量；没有配置时显示词项检索。
