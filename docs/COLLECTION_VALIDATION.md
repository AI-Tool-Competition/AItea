# 采集可用性与并发验证（2026-10-19）

本轮针对取消后继续采集、限流站点隔离、并发 OCR 检查点、原件及向量持久化开展验证。测试使用项目内独立工作树、数据库和端口；生产总库只读取指定官方原件，没有写入测试账号、演示法规或新的审核结论。临时文件、缓存、日志和截图均位于项目内。

## 行为修复

- 下载重定向到冷却中的域名时，立即将任务持久化延期并释放工作线程；未发出的请求不消耗重试次数，之前真实失败的次数保留。其他健康来源可以继续采集。
- OCR 的一个页面发生异常或取消时，仍在执行的其他页面会在返回前保存完成检查点。重试复用这些成功页；检查点拒写、租约失效仍报错，不伪造完成。
- 取消后仍有未完成项的采集／发现任务显示“继续未完成项”，沿用服务端修订号和重试入口。全部原件已保存时不会显示空的继续操作。
- 真实检索验证报告同时保存重建服务后的查询摘要、重排状态、降级提示与引用标识，便于定位候选集合变化；原有严格验收条件不变。

## 界面与账号隔离

独立实例使用管理员和两个普通测试账号。真实 API 检查覆盖管理员入口、总库只读原件、本人私有原件、他人私有原件和共享资料写入限制。桌面和 390×844 手机浏览器验证取消、继续未完成项、失败重试、刷新和冲突反馈。队列变化与冲突由明确标注的受控 HTTP fixture 提供；真实权限、配置持久化和文件下载使用隔离实例的真实 API。

继续操作仅发出一次请求并携带当前修订号，遇到 409 不自动重复写入；手机页面无横向溢出。相关前端交互 18 项通过。普通用户不能看到管理菜单，访问管理路由显示无权限并可以返回业务工作区。

普通用户的资料入口目前依附于业务工作区，没有独立的总库浏览页面；普通用户读取共享资料的边界已通过真实 API 验证，不能将管理员资料库的浏览器覆盖算成普通用户的独立总库界面验收。无权限页面存在轻微排版问题，未纳入本轮功能改动。

## 保留的异常与外部缺口

1. 首轮 16 并发压力测试曾记录 2 次协调循环异常，任务最终全部完成，但旧日志未捕获异常栈，原因未知。单独复跑及最终双档压力测试均为 0 次；初始观察和日志保留，不能反推为已证明无异常，也不能猜测为数据库锁。
2. 原生基准第一次驱动运行有 1 个子进程计量 JSON 为空，未保留该次 stderr，因此不计成功；后续保留 stderr 的九轮取得 288／288 份有效计量。初始审计仍保留。
3. 新加坡首次真实检索有一次可选重排降级，另一次重建服务后的非目标候选集合变化，3 个目标法规在前后均召回。旧验证没有保存第二次响应，无法确认变化原因。另起进程、复用已存向量追加两轮共 6 次真实 hybrid 检索，目标均召回、无降级提示，文档／切片／向量行哈希保持不变。没有重复 OCR，没有把首次报告改为通过，也不能据此声称外部模型持续稳定。
4. 本轮入口探测仍有 26 次 HTTP 403、10 次连接或超时失败、3 次 HTTP 500、2 次重定向异常、1 次超过配置大小限制。这些是入口响应计数，不能相加当作缺失法规数量。22 个可访问项不等于 22 个已完整采集项；全量原文及版本关系的缺口仍以逐项报告为准。
5. CPU 和内存有余量，但项目所在磁盘可用空间本轮仅约数 GiB且持续波动；测试仅清理本任务已结束的临时产物，保留业务数据、配置和既有备份。增加并发前仍需检查存储余量、原站限流和提供商响应。
6. 正式总库只读盘点仍为 77 份资料、20 条关联、1294 个向量；文档状态为 50 份 `ready`、26 份 `failed`、1 份 `stored`，处理任务仍有 43 项失败。状态计数不等于法律审核或正文完整性结论。本轮真实模型样本位于独立测试库，不计入正式采集成果；既有失败任务仍需另行处理。

工程规则与官方文档核对：SQLite WAL 允许读写并行，但同一时刻只有一个写者且仍可能返回忙碌，因此本轮检查短事务、持久化重试与写锁恢复；参见 [SQLite WAL](https://sqlite.org/wal.html)。连接资源需要有界，参见 [HTTPX resource limits](https://www.python-httpx.org/advanced/resource-limits/)。线程池取消不能中止已运行的任务，所以成功页面应在自身任务内落检查点，参见 [Python Executor.shutdown](https://docs.python.org/3.14/library/concurrent.futures.html#concurrent.futures.Executor.shutdown)。
