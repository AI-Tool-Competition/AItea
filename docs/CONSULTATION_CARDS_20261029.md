# 咨询助手与业务卡联动记录（2026-10-29）

本轮实现咨询助手的持续设定、少量追问和对话信息填写业务卡。主 Agent 根据对话选择已有卡片字段，业务服务检查来源、办理权限和修订，随成功答复共同保存。未引入独立信息抽取模型、强制任务计划或第二次回答润色。

## 已实现行为

系统说明与每轮交付说明持续保留咨询设定：用茶商能理解的话解释下一步、负责的人与材料；已有信息继续使用，给定假设只用于分析；需要追问时先提供可以回答的部分，每轮询问一两个影响建议的问题。新建引导会话采用简短欢迎语，历史消息保持。

`update_business_card` 直接提供给主 Agent，每次批量填写一张卡，输入只有真实卡片编号和字段值的 JSON 对象字符串。模型选择字段及值，程序自动关联本轮或同业务用户发言。用户原话未支持的填写值单独忽略，不连带丢弃其他明确字段；未知空值不生成来源，也不能清空已填内容。假设、举例、助手发言、其他业务消息以及未经提交核验的完成结果不写入。

已有字段发生冲突时保留原值。覆盖时程序检查本轮存在更正用语且填写值出自原话；字段与事实的对应仍由主 Agent 判断。历史发言只能补充空缺，不能回写旧值。字段保存原话、用户消息与 Agent 执行关联；手工修改只清除对应字段的 Agent 来源。业务卡仍需茶商检查和提交核验，填写不会完成任务或解锁阶段。

消息与卡片使用同一事务提交，复用现有任务服务的权限、字段规范化、乐观修订和旧确认失效。取消、模型失败和业务版本冲突均不提交暂存字段。本地填写单独计数，不占法律检索轮次；最后一轮预留正文交付。模型工具参数已从嵌套列表收缩为平面参数，避免本轮实测中的列表字符串化及伪造来源编号。

前端工具事件、解析白名单与显示已同步。答复完成后使用返回的业务数据刷新卡片，字段旁显示“茶渡根据对话填写 · 待核对”，可展开用户原话。茶商正在编辑的未保存内容保留，远端修订更新显示冲突。已保存值可继续手工编辑。引号或代码标记包围的已知内部字段编号在答复中转为实际中文标签，不改写法律结论。

Schema 28 只给 task_states 增加字段来源列，既有值与消息保持。更新备份、清单与资料迁移的兼容范围，覆盖 27→28、重复初始化、已有消息与字段保留。实例升级前已保存当前数据库副本，原件与私有配置保持原位。

## 真实模型结果

同一对问题依次提供“李明、250克盒装六堡茶、200盒、第三方工厂采购”，随后更正为“张三、300盒”，并询问首次出口如何低成本寻找买家。两轮在同一会话中进行；没有使用复杂法律压力题。模型为 Nemotron-3.5。

| 推理设置 | 问题 | HTTP端到端耗时 | 主模型调用次数 | HTTP状态 |
|---|---|---:|---:|---:|
| low | 第1轮 | 34.0 秒 | 2 | 200 |
| low | 第2轮 | 31.2 秒 | 2 | 200 |
| high | 第1轮 | 31.2 秒 | 3 | 200 |
| high | 第2轮 | 20.8 秒 | 2 | 200 |

low 的最后一组实际保存了负责人、产品和库存；第二轮将负责人由李明改为张三、库存由200盒改为300盒，产品保留。两轮卡片均未确认，完成任务数始终为0。更早的一组也曾正确填写货源，结果尚不能证明每轮都完整召回所有应填信息。

恢复此前用户指定的 high 设置后，工具执行与更正仍可完成，答复开始询问国家、渠道及办理角色。但第一轮漏填产品和货源；第二轮只更正库存卡的负责人，业务路线卡中的负责人保持旧值。不同卡片的责任人可能对应不同事项，本轮未以程序推断强行传播更正，这一例仍需主 Agent 判断实际范围或追问。

当前答复质量未通过验收。实测仍出现未提供的产品成分判断、未检索的证照与办理机构说法、英文字词混入、重复段落和过长回答。提高推理设置未消除这些问题。工具调用成功、HTTP200与卡片写入成功均不作为业务咨询质量合格的依据。

high 实测还暴露空值产生来源的缺陷，已补充“空值忽略且不清空旧值”的程序处理和隔离测试；此修复后没有再次运行付费模型测试。原生 Safari 验证了新项目和新欢迎语，自动填写后的界面刷新、来源展示与保留本地编辑由组件测试覆盖；未声称完成原生浏览器的全流程验收。
