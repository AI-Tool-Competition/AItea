## 共享检索入口

主 Agent 的 `search_legal_evidence` 与法律引擎内部检索均调用 `LegalService.search`。该服务先验证账号、业务、法域和所选文档范围，再按单个法域选用本地资料包或现有 RAGFlow 提供方。显式文档列表（包括空列表）不会被扩展为全局资料库。

本地提供方只读实例数据目录的 `legal-library/index.sqlite3`，使用已有索引的 `records`、`record_search` 和 `metadata` 数据表。索引是保留的数据资产；本次未迁入旧索引构建脚本。索引元数据须包含 `fingerprint`、`record_count_ID`、`record_count_SG`。索引更新采用原子替换，指纹进入法律分析快照，使已运行结果能识别资料变化。

返回的证据统一具有文档标识、版本、片段哈希、原始单元位置、来源 URL、法域及来源类型。中文整理与原文保持区分。所有未经单独审核的包资料保留 `draft`，不能因被检索到而取得已发布或现行有效状态。RAGFlow 的云端状态与本地法律资料包状态分别报告，本地词项检索不冒充语义向量检索。

## 对话与法域兼容

法律查询工具显式接收单一 `jurisdiction`。主 Agent 的法律分析工具必须传 `jurisdictions`，服务端只允许当前业务授权范围的子集；该范围进入分析缓存指纹。原有工作台 API 未显式限定时保留团队现有分析行为。

普通最终回答不再写出空 `tool_calls` 数组；供应商请求边界也会规范化既有对话中已经保存的空数组，保留非空工具调用和签名。该处理解决 DeepSeek 拒绝第二轮历史消息的问题。

DeepSeek 的主 Agent 工具历史保留供应商要求回传的 `reasoning_content`，不将其作为用户答案展示。法律引擎的结构化请求在 DeepSeek 官方接口显式使用非思考 JSON 模式，普通对话仍使用实例配置。官方文档说明 `medium` 会映射为 `high`，且思考默认开启，见 [思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。供应商非正常结束的日志保留具体 `finish_reason`。

## 检查范围

专项测试覆盖真实共享服务至法律引擎的同源证据传递、ID/SG 隔离、无权限法域拒绝、显式文档范围、草稿不升级及历史空数组兼容。两国真实索引冒烟输出可保存到当前实例的 `.dev/country-pack-engine-audit.json`。这些检查证明数据接线，法律结论正确性仍需真实模型和法律侧验收。
