# 共享法规与私有资料的数据体系

一个实例使用一个 `TEA_DATA_DIR`：数据库保存身份、分类、版本和索引，原件集中存入不可变内容存储。业务上的“法规总库”是同库中的受控共享范围，普通账号上传属于各自私有范围。界面名称、文件内容或模型输出不能赋予共享权限。

## 归属与查找

| 范围 | 归属 | 登录后的读取 | 写入 |
| --- | --- | --- | --- |
| 法规总库 | 固定、不可登录的系统身份 | 所选国家的官方原件、正文、附件、版本和关系 | 由本机受控导入维护；普通账号只读 |
| 我的资料 | 当前账号 | 本人各业务、各国及未分国的上传；可筛选 | 当前账号上传、编辑和管理 |
| 本业务资料 | 当前账号、指定业务 | 服务端按业务边界筛选 | 当前账号向该业务上传 |
| 其他账号资料 | 其他账号 | 不可读取，包括已知文档 ID、下载地址及检索 | 不可写入 |

`documents.owner_id` 是权限依据，`case_id` 是业务归属，`document_countries` 及采集分类是国家依据。API 的 `source_scope` 由服务端计算，不建立可被客户端改写的第二套公开标志。总库不需要复制到每个用户账号，也不开放系统身份的登录或会话。

资料页明确分开“法规总库”和“我的资料”；业务入口显示“本业务资料”和“对应国家法规”。上传始终归当前账号；在法规页上传后转到私有视图并定位新资料。普通资料页也可查看附件、历史版本及法规关系。总库隐藏修改操作，服务端逐项拒绝越权写入。切换账号、业务或范围时取消旧请求、清空旧详情，防止迟到响应覆盖新范围。

`GET /documents?source_scope=personal` 未指定业务或国家时可整理本人全部上传。目录 `q` 用于查找文件。全文 `POST /search` 使用同一资料范围，但国家仍是法律检索边界：资料页先选国家再全文检索，业务分析遵从已冻结的目的国。省略 `source_scope` 保持原有调用兼容，不能用资料总览扩大分析权限。参数见 [API_CONTRACT.md](API_CONTRACT.md)。

## 数据分层

| 数据 | 持久化位置 | 整理及恢复规则 |
| --- | --- | --- |
| 账号、业务、资料元数据、版本、审核和关系 | `tea.sqlite3` 中各业务表 | 显式事务、修订号及版本化升级，保留历史 |
| 原件、普通附件、目录证据、OCR 页图及裁图 | `files/blobs/<账号哈希>/<分片>/<内容哈希>` | 同账号去重，跨账号隔离；分类只改元数据，不移动哈希文件 |
| 结构化正文、解析定位、OCR 映射和历史 | 文档 manifest 及对应原件对象 | 引用文档、不可变版本、页码/区域和内容哈希 |
| 切片、FTS 和真实向量 | 同库检索表 | 关联输入哈希及模型指纹，接口不返回向量 |
| 发现、下载和识别检查点 | 采集队列、传输表、manifest | 保留重试预算、成功页面和失败暂停状态 |
| 可读目录及历史验收证据 | `catalogs/`、`verification/` 等 | 只作盘点与审计，不能代替数据库和原件备份 |
| 模型凭据与启动参数 | 外部环境或本地私有 `.env` | 不进 Git、普通账号导出或完整数据备份；迁移时单独安全交接 |
| 进程、日志与工具缓存 | 工作树 `.dev/` | 可清理运行残留，不能删除业务数据 |

一级法规建立正文和检索索引；独立二级法规文本化并保留固定版本关系，不建立向量；普通关联附件仅存原件。图片识别先保存原件与页面映射。未审核、未知效力及失效法规保留可见状态，不能因有向量就成为有效法律依据。共享法规 RAG 的审核门禁见 [SYSTEM_LIBRARY.md](SYSTEM_LIBRARY.md)。

服务端在候选查询之前限定账号、业务、国家和来源范围，并在外部向量或重排结果返回后重新校验。正文、原件下载、附件、历史和关系也分别检查归属，不能只依靠页面隐藏或不可猜的文件名。

## 备份、迁移与升级

完整实例备份包含所有账号的数据库、原件、真实向量及历史证据，仅供有服务器访问权的运维人员操作，不向普通账号开放跨用户备份接口。

当前服务器的 `TMPDIR`、`TMP`、`TEMP` 也指向项目内 `.dev/runtime-temp/`，目录权限为 `0700`，原件转换的临时工作文件随任务清理。迁移到另一项目根时，应先创建对应私有目录并更新这三个运行变量；`.env` 通过独立的私有配置渠道交接，不能把旧绝对路径当成新环境配置。

使用 SQLite 在线备份取得含已提交 WAL 的一致数据库快照，再复制已发布对象；原件先发布、后提交引用，备份最终核验文件哈希和数据库引用。未发布暂存文件排除并记录，不自动删除孤立原件。文件清单及 `COMPLETE` 核验成功后才原子发布，失败不留下看似完成的备份。

恢复只发布到不存在的新目录。它重定位明确的运行数据库路径字段，释放旧进程的临时占用，保留版本、向量字节、审核历史、已付费识别检查点和失败暂停。不改写历史证明 JSON 或重算证据哈希。命令、冷归档数据库策略及恢复演练见 [DATA_BACKUP.md](DATA_BACKUP.md)。

备份恢复与结构升级分开：先验证原备份并恢复，再在隔离目录按锁定版本运行现有显式迁移链和业务冒烟，确认后切换正式实例的数据根。保留原备份用于回退；切换前停止所属实例，防止新旧实例同时写同一数据根。备份应复制到独立故障域，本机多个目录不能抵御整机故障。

当前结构版本为 15，本次复用已有结构，不增加冗余权限列。SQLite WAL、事务和账号 CAS 符合当前单机部署；出现多机写入、容量或写入等待的实际瓶颈后，再迁移至服务端数据库和对象存储，保留账号归属、不可变对象标识、版本及输入指纹。不能让多个 API 节点简单共享网络盘上的 SQLite。

## 官方实践依据

于 2026-10-16 查阅以下官方文档，按现有架构落实其原则；没有引入未部署的云服务依赖：

- [AWS 多租户 API 授权](https://docs.aws.amazon.com/prescriptive-guidance/latest/saas-multitenant-api-access-authorization/introduction.html)：身份认证不等于租户隔离，资源访问须绑定租户上下文。这里对应服务端账号归属与逐资源检查。
- [Azure 多租户 RAG 安全](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/secure-multitenant-rag)：检索链条也要实施权限隔离。这里在候选查询及外部结果回流时执行范围校验。
- [SQLite 在线备份](https://www.sqlite.org/backup.html)与 [WAL](https://www.sqlite.org/wal.html)：使用一致快照，不把运行中的数据库主文件复制当成完整备份。

这些是设计依据，不表示已经完成异地灾备、全部生产负载或法规效力审核；交付须另记实际检查、恢复演练和运行环境。
