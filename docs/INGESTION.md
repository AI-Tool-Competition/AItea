# 文档解析、检索与资料采集

## 接入边界

`backend/app/ingestion.py` 是无数据库、无用户状态的同步库。应用服务必须先检查账户和业务归属，再将耗时工作交给受限工作线程或进程。外部上传应通过 `app.parsing.parse_bounded` 进行资源隔离，不应在 API 事件循环或主服务进程内直接调用 `parse_file`。原始文件保存、不可变版本、内容 hash 去重、来源更新时间和引用访问控制由业务服务负责。

- `parse_file(filename, content, mime_type='', role='primary', parser='basic')` 返回结构元素、章节切片、原文 locator、解析版本、SHA-256 和警告。明确拒绝 `secondary`，避免把关联附件意外纳入索引。
- `lexical_search(query, chunks, limit=5)` 使用 BM25 风格词项评分；中文按连续双字匹配，保留传入 chunk 的文档、版本、locator 等元数据。没有重合词项就返回空结果。它不是语义向量检索，也不替代法律适用性判断。
- `embed_texts(texts)` 调用实际配置的 OpenAI 兼容 embedding 服务。没有配置时返回 `None`；部分配置、服务错误、空向量、非有限数值、重复索引或维度不一致会明确失败。不会生成假向量。服务层负责持久化模型、维度、向量与配置指纹，查询时按同一配置向量化，配置变化需要重建索引。
- `fetch_source(url, max_attachments=5)` 返回主文件原始 bytes、同源直接附件 bytes、实际最终 URL、采集时间和附件失败警告。它不解析附件，也不递归抓取。此全结果 helper 保留给库级兼容；业务入口已改为下面的持久队列。

## 基础解析

| 格式 | 提取与定位 | 已知边界 |
|---|---|---|
| TXT / Markdown | 复用原解析器；原始行号、字符位置、标题路径 | UTF-8；正文不能为空 |
| HTML | 标准库解析；标题路径、原始 HTML 行号、元素序号、存在时保留 id | 不执行脚本，不加载外部资源，不伪造提取文本在 HTML 中的字符位置 |
| DOCX | ZIP/XML 提取段落；标题样式、原始段落序号 | 基础模式不恢复复杂表格和图片；拒绝 DTD/实体声明 |
| PDF | pypdf 提取文字；保留原始页码 | 不进行 OCR；全扫描文档明确要求 OCR，部分空页记录警告 |

单文件 20 MB，提取文本最多 400 万字符，结构元素最多 20,000，PDF 最多 300 页。DOCX 解压总量最多 50 MB、正文 XML 最多 16 MB、ZIP 条目最多 2,000。PDF 解压后的页面内容流限制 16 MB；由于解压发生在检查之前，生产入口必须使用进程资源隔离。纯库的大小检查本身不是恶意文件沙箱。

切片直接复用 GEO 的章节与 token 预算逻辑，保持正文、检索上下文与原文定位分离。引用必须同时携带文档 ID、不可变文档版本及 locator；标题或路径本身不能作为引用唯一标识。

## 可选 Docling

显式选择 `parser='docling'`，安装可选依赖，并配置本地 `DOCLING_MODELS_PATH`。基础安装不会隐式拉取模型或载入 Docling。原解析器关闭远程服务与外部插件。尚未进行视觉核验的图片资产不纳入索引，返回警告；原件保持完整。

原代码来自用户提供的 `tmp/GEO-System/services/agent-service/app/`，完整抽取至 `backend/app/vendor/geo_parser/`。本次只对抽取副本作相对导入和 HTML locator 合并兼容修改；图片过滤发生在 facade。没有修改参考项目。

## Embedding 配置

同时设置 `EMBEDDING_BASE_URL`（例如服务的 `/v1` 根地址）、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`。密钥仅来自服务环境。远程服务必须 HTTPS，本地开发只允许 localhost/回环地址使用 HTTP。不跟随重定向，不读取代理环境。每批最多 64 段，单次响应读取上限 16 MB，连接超时 10 秒、读写超时 30 秒。

单次 `/search` 响应中 `mode=hybrid` 的前提是当前文档已经具备与查询一致配置的实际向量，并且确实执行了向量与词项的融合检索。索引失败不能仅因为存在环境变量就将该次检索报告为 hybrid。`bootstrap` / `health` 的 `capabilities.retrieval_mode` 只表示接口配置具备的能力；具体检索是否成功使用向量，以 `/search` 的执行结果为准。

## 抓取约束

- 仅标准端口 HTTPS，无 URL 凭据或控制字符。
- DNS 全部解析结果必须为公网地址；连接固定到已检查 IP，同时使用原域名作 TLS 验证，防止 DNS 重新绑定。
- 最多 3 次重定向，每一跳重复 URL 和公网地址检查。
- 每个文件 20 MB，socket 超时 15 秒、整次采集截止时间 90 秒；超时关闭活动 socket。DNS 等待最多 10 秒、最多 8 个同时存活的守护解析线程，系统 DNS 异常不会无限占用应用工作线程。
- 不使用环境代理，不发送 cookie 或登录凭据；拒绝压缩 HTTP 传输，按实际读取字节校验大小。
- 普通来源的附件发现只读取主 HTML 中同源、具有受支持文件扩展名的直接链接，最多尝试 5 个；附件重定向也必须同源。清单目录发现使用下述独立流程，不能由普通来源任意递归。超过 4 MB 的 HTML 不进行附件发现。
- 次级附件只返回原件，失败记录在 warnings 中；不得静默展示“所有附件已抓取”。

运维需要限制可配置来源的权限、并发任务和保留策略，核对来源使用条件，针对数据规模配置队列、进程隔离及重试。此模块不包含 JavaScript 网站浏览器、验证码绕过、OCR 服务或全网爬虫。

## 流式采集与不可变版本

业务入口统一为 `CollectionService`（`app/collection.py`）。手动、定时及旧 `/fetch` 都提交持久任务，HTTP 返回 202。工作线程逐份下载、逐份落盘和提交记录，后续正文解析、向量化进入独立队列；慢文件或模型请求不会挡住其他下载完成项。每条记录保存来源计划快照、原始/最终 URL、尝试次数和原件版本 ID。

`app/blob_store.py` 边读边计算 SHA-256，原件位于 `data/files/blobs/<账号哈希>/<内容哈希前2位>/<后2位>/<完整哈希>`。文件名只作展示。临时文件在同一文件系统的 `.staging/`，内容 fsync 后通过原子硬链接发布，文件只读，随后事务写入引用。相同账号的相同原件复用字节；不同账号隔离。数据库失败不能 unlink 已发布对象，因为另一条记录可能已引用。旧平铺原件保留原路径，不启动时搬迁。

版本号属于法规家族，不是文件哈希：最新正文 A→B→A 会记录 v1→v2→v3，v1/v3 复用同一份字节。最新版本未变化时直接复用记录和已完成的解析；一级资格或向量配置变化时补索引。跨 URL 的版本须在任务 entries 中提供同一官方 `identity_key`；不凭相似标题自动合并法规。每份版本仍有自己的审核/有效期，新的内容不会继承“已审核”。列表、正文、下载、历史和引用都绑定文档 ID，不使用可变的“当前链接”代替旧引用。

## 按文档执行采集清单

当前预置方案为 [`indonesia-20261003.json`](../config/collection-plans/indonesia-20261003.json)，对应用户文档的 5 章 29 项：法规 10 项、司法解释性材料 4 项、判决 4 项、部门补强 7 项、条约 4 项。章末检索规则不增加任务数；3 个示范详情网址保留参考用途，不作为种子。当前不加载其他国家方案；后续在同目录新增独立 `country` 和版本的配置，由服务启动校验并加载。

每个条目保留入口角色、范围、排除项、字段、步骤、版本及映射规则、验收要求和完整原文，后台详情可折叠展开。配置条目会在当前账号下创建停用的受管来源并冻结版本快照，不自动启动 29 项全量下载。相同账号重复配置幂等；同版本内容发生变化须升版，不能覆盖旧绑定和任务。

目录发现与正文采集分两步。`ChecklistService` 将目录和详情交给已有受限下载队列，`discovery.py` 根据明确的站点规则识别分页、详情和可能的原件。取得的页面以账号隔离的内容寻址文件保存，目录证据表记录原始及最终 URL、内容哈希和提示；这些记录不创建法规正文，不进入解析或向量队列。发现的原件链接单独登记为候选，保留发现出处、状态和排除理由。路径匹配成功不表示材料内容或法律效力已审核。

一次发现最多处理 40 页，未处理入口保存在持久队列中；本批结束后再次发现继续剩余入口。每条目的目录队列及正文候选各有 20,000 项上限，深度最多 30 层，触顶会提示拆分或补充适配。单批结束不代表全目录完成。BPK、MA JDIH及普通链接规则仍受官方站点实际页面、403、动态加载和文件域约束；受信文件域只能由明确配置扩展，不能从任意页面链接自动放宽。

操作者按条目要求筛选候选，再选择一级或二级发起原件采集。二级必须明确选择同账号、同国的一级版本。只有取得符合原件类型的内容后才建法规版本，原件、解析与审核状态分别记录；返回目录或验证页的候选会失败。新资料以 `review_status=draft` 保存，法规性质、适用日期、效力及范围须审核后才能成为有效检索依据。相同原件按既有规则去重，新正文追加版本，旧条文和旧关系保留。

清单中的人工筛选和验收要求不会自动变成代码规则。例如 3.4 的涉企语义、最高法院身份和按裁判日滚动五年仍需核验，当前不自动识别正文中的裁判年份；3.1 PUU、3.3 HUM及官方精选判例不套用此窗口。条约接受、生效、批准及实施关系也须回查原件。29 项配置完成、目录已发现、正文已取得、已解析、已审核及已索引是不同进度；拒绝页、空框架、适配不足或缺附件必须留下缺口，不能显示全量成功。

## 分级、标签与映射

用户指定的“一级/二级”指主法规与其引用/相关法规，与普通文件附件分开建模。一级和二级法规都解析正文；只有在当前采集组作为一级的版本进入 RAG。扫描件仍需 OCR，现有基础解析器不会伪造正文。文件附件继续原件留存。

国家分类使用保留命名空间 `country:<ISO2>`，如 `country:ID`；`document_countries` 保存文档的不可变国别，同一法规家族的版本不得跨国混用。自由标签、法域说明或另建采集组不能改变该边界。标签保存在分类中，修改检查 revision 并追加历史；预置标签如 `country:ID`、`checklist:ID-3.3`、`kind:case`、`topic:MA HUM`。章号和材料类别不代表法源等级、一级／二级、适用期或法律审核。

首次归国会让整个法规家族重新进入审核，保留原审核历史。原先按普通业务文件上传的资料不会沿用默认的已通过状态；新版本也从草稿开始，重复采集相同的已审核版本则保留其审核结果。普通附件展示父资料的国家，继续仅存原件。

关联是独立多对多表：`source_document_id → target_document_id`，带 `cites/related`、采集组及 locator，两端固定版本且国家一致。显式选取的二级来源计划会为每份正文关联所选一级版本；默认类型是 related，不把未核实的关系写成“已抽取引用”。新版本不会重写旧关系。普通来源的额外网址仍是明确种子，同源直接附件每个主 HTML 最多 5 个；清单目录使用独立的有界发现队列。

`Search.country` 可显式指定大写两位国家代码或 `unassigned`。业务快照目的国可明确解析时，以业务国家为准，冲突的国家或国别采集组返回 422；没有业务时使用显式国家或 `country:<ISO2>` 采集组，冲突同样拒绝。两者均未指定时只检索未分国资料，不混入国家法规；未知目的国名称不靠模型推断。审核、适用期、一级资格及版本选择继续生效，国家筛选不能绕过这些门禁。

## 并发、背压与恢复

| 配置/限制 | 默认与边界 |
| --- | --- |
| `TEA_COLLECT_WORKERS` | 8 个下载任务，范围 1–16 |
| `TEA_COLLECT_PER_HOST` | 每域 2 个真实连接，范围 1–4，且不超过下载数 |
| `TEA_PROCESS_WORKERS` | 2 个处理任务，范围 1–2；解析仍经受限子进程 |
| 下载待处理队列 | 全库最多 2000 项、单账号最多 1000 项，提交/重试/附件发现均检查 |
| 解析背压 | 待处理正文达到 200 项时暂停领取下载任务 |
| 单次计划 | 默认最多 200 文件，可配置至 500；触顶会显示未收齐提示 |
| 清单目录发现 | 每批最多 40 页，未处理入口持久保留后续继续；每条目目录队列和候选各最多 20,000 项 |
| 自动重试 | 最多 3 次；指数退避加抖动，429/408/5xx/网络错误可重试 |
| 租约 | 120 秒，运行协调器每 10 秒续约；过期可被新进程认领 |

SQLite `BEGIN IMMEDIATE` 保护领取和状态转移；下载/解析/模型调用不持有写事务。租约 token 加有效期在提交前复核，旧工作线程不能覆盖重新领取、取消或重试后的结果。网络连接另有数据库名额，每一重定向目的域都取得名额；取消领取并不提前释放仍活跃的物理连接。下载受原有 90 秒截止与 socket 限制约束。进程强制终止后，旧租约到期再恢复。

HTTP ETag/Last-Modified 保存在账号内缓存，304 仅复用匹配最终地址且通过哈希校验的原件；转向不同 URL 不转发条件头。Retry-After 按秒数或 HTTP 日期解析，最多 300 秒，并落实同域等待。安全检查失败、非法地址、超限、确定性解析失败不自动反复重试。

正文解析独立提交；向量每批最多 64 段，批次成功即保存检查点。中断后从缺失向量继续，已完成解析不重跑。模型失败保留正文与原件并展示错误；没有 embedding 配置时如实使用词项检索。把已解析二级版本加入一级采集组会补索引，解析途中修改分级也在提交事务内重新核对。任务 revision 只由取消/重试递增，进度使用 updated_at，避免正常处理进度导致无法取消；旧控制命令仍返回冲突。API 返回的 completed 仅表示当前任务范围处理结束，不能当作 29 项采集清单或网站全量完整的证明。

## 运行与恢复操作

数据根布局和按账号、国家、版本导出的文件目录见 [资料存储与盘点](STORAGE.md)。原件与目录证据集中保存；目录快照不复制原件，也不代替备份。

1. 通过 `make dev` 启动本工作树的服务，来源页提交任务并查看逐项进度。`GET /api/tea/health` 的 collector 应为 running；recovering 表示协调循环出错后自动重试，last_error_at 用于定位日志。HTTP 存活不等于队列正在工作。
2. 失败任务按条目查看错误，修正来源/模型后点重试；范围上限导致未发现完整附件时，补充明确种子并创建新任务。不清空队列表来“恢复”。
3. 正常停止不再领取新工作，尽量完成已领取的受限调用；强制中断的任务在租约到期后恢复。已保存原件不丢失。
4. 备份 SQLite（使用 SQLite 在线备份接口或停止服务后备份，不能只复制运行中的主数据库文件）及对应 files 目录，并保留后端 .env 配置；还原必须来自同一备份点。数据库/文件的保留期由业务另行确定。
5. 强制终止可能留下 `.staging` 或未引用 blob。当前不自动清理，以免误删在途任务或历史条文；离线核对引用后再制定保留策略。本地 POSIX 文件系统必须支持硬链接与目录 fsync，不把此布局直接部署到不具备同等语义的网络盘。

结构升级 4–6 在事务中增加家族/分级/关系、队列/条件缓存及网络租约，版本 7 增加清单绑定、目录队列/证据、候选及国别记录，保留既有数据和原件路径，不凭旧标签猜测国别。所有进程需使用同一并发配置；当前仍是单机 SQLite 与文件系统实现，不声称已完成分布式部署验收。未实现全站 JS/验证码处理、任意站点分页适配、自动法律引文确认或 OCR 服务；这些需按站点补充，不能把验证码/错误页面视为已完成法条。
