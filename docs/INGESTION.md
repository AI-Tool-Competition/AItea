# 文档解析、检索与资料采集

> 当前正文处理已改为 MinerU 云端精准解析与本机 RAGFlow，配置、证据、普通用户部署及自动并发探测以 [MINERU_RAGFLOW.md](MINERU_RAGFLOW.md) 为准。下文本地解析、OCR 和自建向量部分描述历史检查点及迁移兼容，不是当前采集队列的执行流程；HTTPS 下载、权限、分级和法规审核边界继续适用。

## 接入边界

`backend/app/ingestion.py` 是无数据库、无用户状态的同步库。应用服务必须先检查账户和业务归属，再将耗时工作交给受限工作线程或进程。外部上传应通过 `app.parsing.parse_bounded` 进行资源隔离，不应在 API 事件循环或主服务进程内直接调用 `parse_file`。原始文件保存、不可变版本、内容 hash 去重、来源更新时间和引用访问控制由业务服务负责。

历史下载复用及 BKPM 表单封装原件的保留与映射规则见 [来源响应凭证](SOURCE_RECEIPTS.md)。

- `parse_file(filename, content, mime_type='', role='primary', parser='basic')` 返回结构元素、章节切片、原文 locator、解析版本、SHA-256 和警告；PDF 另有逐页处理状态与完整性。明确拒绝文件角色 `secondary`（普通附件）；二级法规仍使用可解析的文件角色，是否检索由法规分级决定。
- `lexical_search(query, chunks, limit=5)` 使用 BM25 风格词项评分；中文按连续双字匹配，保留传入 chunk 的文档、版本、locator 等元数据。没有重合词项就返回空结果。它不是语义向量检索，也不替代法律适用性判断。
- `embed_texts(texts)` 调用实际配置的 OpenAI 兼容 embedding 服务。没有配置时返回 `None`；部分配置、服务错误、空向量、非有限数值、重复索引或维度不一致会明确失败。不会生成假向量。服务层负责持久化模型、维度、向量与配置指纹，查询时按同一配置向量化，配置变化需要重建索引。
- `fetch_source(url, max_attachments=5)` 返回主文件原始 bytes、同源直接附件 bytes、实际最终 URL、采集时间和附件失败警告。它不解析附件，也不递归抓取。此全结果 helper 保留给库级兼容；业务入口已改为下面的持久队列。

## 基础解析

| 格式 | 提取与定位 | 已知边界 |
|---|---|---|
| TXT / Markdown | 复用原解析器；原始行号、字符位置、标题路径 | UTF-8；正文不能为空 |
| HTML | 标准库解析；识别受支持的声明编码，保留标题路径、原始 HTML 行号、元素序号及 id | 不执行脚本，不加载外部资源，不伪造提取文本在 HTML 中的字符位置 |
| DOCX | 正文、页眉页脚、脚注尾注、文本框、表格及合并范围；包部件与关系、XML 路径、原件及部件哈希 | 字段缓存、修订、隐藏内容、未知部件和图片保留待核验；不执行字段、不下载外部资源、不推测物理页 |
| DOC / WPF / WPD（可选工具） | 原始 OLE 流和 DOC 字符片段；离线转换 XML/HTML、表格、脚注和对象映射 | 原字符位置与转换 XPath 尚未逐字核验；所有当前样本保持全文不完整，不进入向量或法规检索 |
| XLS（BIFF8） | xlrd 2.0.2 读取单元格、原值与格式；工作表、行列、合并范围、原始 BIFF 记录及打印字段定位 | 不计算公式、宏或外部引用；缓存公式、错误值、未知格式及未映射图像等保留待核验；工作表不是物理页 |
| MDB（JET4，可选工具） | 原类型、NULL、空串、前导零、数值字节、表与真实内部行/Memo 存储定位 | 须配置受限只读工具；报表、查询、链接表、OLE 和未知对象阻止全文完整；内部存储页不是打印页 |
| PDF | pypdf 提取文字、物理页码及印尼法规章节；PDFium 核对文字对象可见性，已核验数字网格按坐标分单元格 | 隐藏、裁剪、覆盖及未知可见性进入 OCR；只有完整白色页图证明可以免除空白页识别；扫描、合并或歧义单元格仍须核对 |

上传和直接 bytes 解析保留单文件 20 MiB、PDF 300 页上限。受管采集可按来源将原件上限提高至 128 MiB；已保存的采集 PDF 采用下述文件模式，最多 10,000 页（共享物理页上限，每次仍只处理 64 页）。两种模式均限制提取文本最多 400 万字符、结构元素最多 20,000、子进程结果最多 40 MiB。DOCX 解压总量最多 50 MiB、正文 XML 最多 16 MiB、ZIP 条目最多 2,000。PDF 解压后的页面内容流限制 16 MiB；由于解压发生在检查之前，生产入口必须使用进程资源隔离。纯库的大小检查本身不是恶意文件沙箱。

上述 400 万字符与 40 MiB 限额继续适用于现有正文主流程；超过整书聚合上限的 PDF 可使用[独立原生页证据分片](ARCHIVE_PAGE_SHARDS.md)按有界窗口续取并保留旧检查点。该入口仅保存物理页证据，不生成正文分块或接入 OCR、向量与检索。

数字表格仅在完整、实际绘制的矩形网格可验证时本地提取：PDFium 提供字符与格线坐标，所有字符必须归入单元格或网格外，字符清单与 pypdf 原文一致；单元格边界、合并格或多张网格存在歧义则保留待 OCR。只在 PDFium `IsHyphen` 明确识别可见连字符、另一文字读取器也含相同字符时归一软连字符，不猜测税率、表头或空格内容。单元格结构、原文层、来源页码及处理版本同时保留。

DOCX 不再仅提取 `word/document.xml`。逐项检查 ZIP 本地头、中央目录、真实解压字节数、结束标记与 CRC，拒绝重复/重叠条目及各种已支持编码中的 DTD/实体声明。每个结构元素绑定原件 SHA、包部件 SHA 和带命名空间的 XML 路径；跨部件切片保留所有 `source_anchors`，不将首个部件位置冒充整段出处。图片关系、嵌入对象与外部引用均保存映射；可安全解码的内嵌图像保留原字节与哈希、等待图片识别，外链不自动加载。字段、修订、文本框次序、歧义表格、缺字或未知内容阻止全文完整。实际 WTO DOCX 取得 70 个段落（旧正文提取为 50 个），但六个 PAGE 字段、外部模板、未知 XML 和斜线表格仍保留待核验；附上的两份采集清单只用于定义范围，不作为法规正文入库。

DOC/WPF 由 `parse_bounded` 调用可选的项目内离线工具，配置、许可、构建和隔离见 [工具说明](../scripts/tools/legacy-doc/README.md)。DOC 保存 Word 97 字符 CP 至原始逻辑流字节范围与 OLE 对象原流；转换 artifact 单独保存完整字节、SHA、XPath、表格及脚注，不虚构二者已经逐字符对应。WPF 保存 HTML、原始转换事件和图像映射，事件位置只表示转换结果位置。工具无网络、不可派生子进程，父工作进程死亡时内核终止转换器；隔离不可用时失败。33 份真实原件在实际受限工作进程中均取得文本与映射，24 张表、1,284 格和 57 个脚注保留；布局、字段、对象与原字节对应未完成，全部保持 `quality.complete=false`。

XLS 原件保留原数值/字符串、XF 格式、日期模式和打印页眉页脚的原始记录哈希。只显示已验证的简单数值格式，未知格式不猜测；动态打印字段如页码、日期保留字段映射，不填入推测值。图像/图表/外部对象记录和公式缓存明确保留来源及待核验状态，单张表格文字提取成功不等于整份文件正文完整。

MDB 通过管理员配置的 `TEA_MDB_READER_PATH` 使用项目内只读工具，构建与许可见 [工具说明](../scripts/tools/mdb/README.md)。工具在独立 Linux user/network namespace 内运行，绑定父进程死亡信号，限制时间、输出与资源；无法隔离时失败。Python 再从原件逐行及逐段核对 Memo 哈希，不依赖有 NULL/空串歧义和固定缓冲的通用 CSV 导出。真实 WTO 样本的 24 个链接对应 12 份字节原件，10 份提取 17,503 行，另 2 份文件头不合法；实际 Access 报表/查询均未完成，整份正文仍待核验，不进入索引。

`app.archive_parsing.parse_archive_pdf_bounded` 对账号内已保存原件执行文件模式解析。先核验 SHA-256、大小和普通文件身份，再由可寻址文件流读取；主进程不载入整个大文件。通用调用每次最多处理 64 个物理页；持续采集队列使用 16 页窗口，以限制单次解析时间和进程间结果体积。每个窗口的 CPU 上限 35 秒、内存地址空间 768 MiB、墙钟 45 秒，并发受共享 `TEA_PARSE_WORKERS` 进程槽限制。检查点从首次处理起覆盖全文件页码，未处理页保留 `pending_parse`；后续任务推进窗口，复用完成的原生页和 OCR 页。旧表格检查点可随新版网格规则重处理，已完成 OCR 不被覆盖。`archive_pdf.complete` 仅表示原生解析窗口已结束，整体是否可索引仍由 `quality.complete` 判断。

切片复用 GEO 的章节与 token 预算逻辑，并保持原文连续片段的空白。正文、检索上下文与原文定位分开；印尼法规的正文 Pasal 和 PENJELASAN 分节，裁判中引用的条文不作为裁判自身的条号。引用携带文档 ID、不可变版本、chunk ID、chunk 内容哈希及 locator；标题或路径不能作为引用唯一标识。

## 逐页识别与质量门禁

`parse_bounded` 只执行本地解析；图片渲染也在受限子进程中完成。图片识别默认关闭，优先使用可校验的本地文本和既有识别结果；必要时显式设置 `VISION_OCR_ENABLED=true`，`ocr_bounded` 复用后端 `LLM_BASE_URL/API_KEY/MODEL` 调用支持图片的模型。每次处理默认最多 4 个待识别页；扫描页、原生图片和局部补读共用本服务进程的 `VISION_OCR_WORKERS` 个槽，通用模型默认 2，允许 1–64；DeepSeek 图片识别严格限制为同一数据根跨进程并发 1，示例配置也设为 1。单个 PDF 文档的识别线程最多为该配置与本批页数的较小值；渲染最多 600 万像素、PNG 最大 8 MB，响应最大 2 MB。模型需返回完整、可校验的 JSON，截断、缺字段、可疑空页和不完整表格留下失败或待核对状态，不把模型转录等同于人工校勘。

原件先保存，再解析，再逐页识别。调用模型前，渲染页图已保存到与原件相同的账号 CAS；页记录绑定原件哈希、物理页码、印刷页码、图片哈希、模型和提示版本。每页成功即提交检查点。恢复时跳过已识别页，最后一页已保存但切片未更新时也会重新组装正文。工作槽忙时保留待处理状态并延后领取，不算识别失败、不消耗失败重试次数。图片服务的网络错误、408／429／5xx 每页或独立裁图读取最多尝试 3 次，失败后至少延后 5 秒；认证错误、无效 JSON 或裁图复核仍不一致的页面终止自动重试。显式重试保留完成的页面和复核证据。

全页 OCR 的无效 JSON、截断或超限响应可通过 `on_response_error` 保存最多 256 KiB 的原响应字节及诊断元数据。应用把这份 JSON 证据包写入原账号 CAS，页内只保存 `ocr.error_response` 的摘要和引用，绑定原件、物理页、请求 ID、尝试次数、图像、模型与提示版本，并再次检查当前任务租约和原件版本。响应字节摘要与证据包 CAS 摘要分别保存，空响应也可作为诊断包保留；`response_complete` 仅表示消息是否收完，不能表示正文完整。错误内容不参与分块或检索，不触发自动格式修补或再次付费请求。非成功 HTTP 的响应全文、授权头以及回显当前密钥的响应不保存。正常成功转录不额外保存一份大响应包。

整页识别使用 200 DPI，附带最多 20,000 字符的不可信原始文本层用于对照，并记录该输入的哈希。原生可见性需要核验的页面把实际提示置空，记录 `masked-unverified-native-hint-v1`，避免裁剪区外旧文字引导识别；原始文本层及可见性证据仍完整保存，独立疑点不自动清除。印尼法规编号与年份、日期、条号和千分位金额按 `legal-numbers-v3` 与原文层交叉校验；冲突进入 `ocr_uncertain`，不凭模型的 `complete=true` 放行。

`pdf-pages-v5`／`archive-pdf-pages-v3` 在既有受限工作进程内检查物理页文字对象的边界、矩阵、启用状态、颜色、绘制顺序和裁剪范围，保存 `native_visibility` 与对象证据。缺对象、Form／复杂裁剪、旋转／透明／可选内容、两种文字读取器不一致及超限保持待核验；检查未发现问题也不声称完整实现了 PDF 的全部可见性规则。待核验的原生层保留在原件证据中，整份正文门禁阻止索引。旧版本正文不在启动时全库重写；显式推进归档原生窗口时，未识别、缺少新版可见性证据的原生页有界重验，完成 OCR 及其历史保持不变。实现参考 [PDFium 页面对象接口](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdf_edit.h)、[裁剪路径实现](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/fpdfsdk/fpdf_transformpage.cpp) 及 [pypdfium2 对象与渲染接口](https://pypdfium2.readthedocs.io/en/stable/python_api.html)，并用项目锁定版本的实际 PDF 回归验证。

原生空白页仅在无可见性疑点、无文字对象、无注释，而且已有受限渲染器的完整 PNG 每个像素均为不透明白色时，保存 `native_blank` 后计为原生完成；证明绑定原件哈希、物理页、像素哈希、尺寸、DPI 和渲染版本，读取门禁重新核验。文字层为空的有色页面或扫描图仍待 OCR。格式 5 来源映射可导出可见性对象定位与白页像素证明的引用，不导出隐藏文字或图像字节。

已由大型光栅证据要求整页 OCR 的扫描页，保存原生文本哈希与明确 `not_inspected_raster_page_already_pending_ocr` 摘要，不展开庞大的原生绘制对象证据；该摘要仍要求视觉核验并屏蔽原生提示，不能放行原生正文。这样避免大税表的审计证据挤占既有 40 MiB 结果上限，原件、页数、OCR 范围和处理上限均保留。

整页请求前同时持久化 PNG、实际提供者／模型／提示配方指纹和尝试次数；检查点写入失败则不请求模型，重启后已达三次的请求不发送第四次。`same-owner-pdf-page-reuse-v1` 只复用同账号、同原件 SHA／版本／来源 URL、同物理页原生证据和当前实际配方的完整转录；还需当前本地受限渲染与账号 CAS 图像字节一致、无独立疑点、恢复历史或旧目标尝试。检索最多八个候选，复用证明保留来源文档版本和页检查点哈希，目标模型调用为 0。旧转录缺配方指纹、其他账号、普通附件或失败／待核页继续原处理流程；复用不创建法律关系或审核结论。

运维显式运行 `scripts/import_collected_resources.py` 时，可迁移上述已有页复用记录：所选资料必须同时包含供体和目标，原件、物理页、PNG、保存的提供者配方及完整转录逐项匹配，并在预检中通过受限本地重渲染。导入先保存双方原页及旧证明的不可变 CAS 归档，再绑定新归属与新文档身份，增加 `cross-owner-pdf-page-reuse-import-v1` 收据。旧证明缺少“复用前目标页”的事实原样保留，不补造历史。备份与系统库迁移重新检查供体、归档和当前页的派生关系；仅重新计算自洽哈希不能替代旧检查点核验。这是本地运维导入能力，未增加跨账号查询或自动 OCR 复用权限。

该离线导入对符合当前模型、输入、维度和有限值校验的已有一级向量保留原始 float32 BLOB；独立二级资料仍只迁移文本及映射。关系同时绑定两端原件哈希与目标版本，原关系标识和原始定位另存不可变证据。已有正文、识别尝试与审核状态不因导入变成新识别或已审核。ACFTA 的精确官方来源准入及历史核验范围见 [ACFTA_SOURCE_ADMISSION.md](ACFTA_SOURCE_ADMISSION.md)。

旧批次若已有不带这份固定证据的关系，导入重放会明确要求单独迁移，不能暗中新增第二条关系或改写旧定位。旧向量曾经重新归一化、导致已保存导入摘要与原始字节不同的批次，也可能触发既有的源检查点变化保护；应保留备份并核对差异，不把这种拒绝当作网络失败重复请求模型。

同账号、同来源 URL／SHA／版本的两个原件副本不同时领取 `parse` 作业，以便先保存的真实识别结果供另一国别副本核验复用；不同来源或向量阶段仍可填充另一个处理名额。规则依赖现有事务及有效任务租约，已失效租约不阻塞，不能将该调度约束解释为跨国家检索或跨账号读取授权。

有疑点的页面由同一持久队列执行 400 DPI 局部复核，仍受像素、大小和时间上限约束。两个不同取景的裁图分别进行盲读，不传入候选答案；只有两次读取一致、来源页和图片/读取哈希完整、待替换位置唯一时才精确修正。文字层仅帮助定位，扫描页可使用有界重叠裁图；无法定位、结果不同或结构仍不完整则保持待核对。裁图先存 CAS，图片引用与尝试次数在请求前提交，重启后复用已校验的成功读取；配方变化保留旧历史。原整页图、原文层及历次完整转录均保留，不覆盖旧证据。重新组装仍执行数字门禁。这不能发现所有错字或替代法律审核。

PDF 的 `quality.complete` 仅表示所有物理页已完成原生提取或模型转录，不代表法律效力、表格数值正确或全文人工审核。`pending_parse_pages` 与待 OCR 的 `pending_pages` 分开报告；任一仍有内容即不能进入检索或向量化。未完整处理的文档可查看原件和已取得的正文，原件及失败原因保留。没有配置 OCR 时扫描页明确显示待识别，超过文件模式、文本或结构上限的原件仍是待处理缺口。

## Embedding 配置

同时设置 `EMBEDDING_BASE_URL`（例如服务的 `/v1` 根地址）、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`。密钥仅来自服务环境。远程服务必须 HTTPS，本地开发只允许 localhost/回环地址使用 HTTP。不跟随重定向，不读取代理环境。`EMBEDDING_BATCH_SIZE` 默认 64，允许 1–64；慢速服务可调小批量，例如 4，成功批次立即保存，正文切片和向量指纹不变。单次响应读取上限 16 MB，连接超时 10 秒、读写超时 30 秒。

可选设置 `RERANK_BASE_URL`、`RERANK_API_KEY`、`RERANK_MODEL`，调用兼容的 `/rerank` 接口。先完成账号、业务、国家、版本与法规有效性过滤，再从词项／混合检索选出最多 `min(limit × 3, 60)` 个候选。仅发送查询和候选正文，服务返回的原始序号和有限分数必须通过数量、范围及重复检查；引用仍来自本地不可变版本，模型返回的正文或元数据不能替换证据。最多 4 个并发请求，连接超时 5 秒、读写超时 15 秒、读取预算 20 秒、响应上限 1 MB。未配置时不调用，失败时保留原排序并返回提示；更换重排配置会使分析与调试缓存失效。

使用 [Aerisun 接口指南](https://aerisun.top/sub2api/api-guide.html) 时，三个根地址均填写 `https://aerisun.top/sub2api`。2026-10-19 本机配置及当前密钥的 `/models` 核对结果为：生成及图片识别 `deepseek-v4.1-flash`、向量 `qwen3-embedding-4b`、重排 `qwen3-reranker-4b`；图片接口另通过真实单页识别。模型供应会变更，启动批处理前仍须核对实际可用模型和小请求，不沿用旧配置快照中的模型名。密钥只写入被 Git 忽略的根目录 `.env` 或部署方授权的私有配置文件。

单次 `/search` 响应中 `mode=hybrid` 的前提是当前文档已经具备与查询一致配置的实际向量，并且确实执行了向量与词项的融合检索。索引失败不能仅因为存在环境变量就将该次检索报告为 hybrid。`bootstrap` / `health` 的 `capabilities.retrieval_mode` 只表示接口配置具备的能力；具体检索是否成功使用向量，以 `/search` 的执行结果为准。

结构版本 10 将切片、FTS5 词项索引和 float32 向量保存到独立表，向量不再内嵌于文档 JSON。向量配置指纹包含接口、模型与检索上下文配方，另校验输入哈希、维度及有限数值。模型切换不会复用旧配置的向量；每批最多 64 段，成功即保存，失败从缺失批次恢复。历史 JSON 向量在索引同步时迁移，原件与法规版本不改变。

检索先应用账号、业务、国家、一级资格、审核及版本范围，再使用 FTS5 和分批向量评分。向量扫描每批 256 段，同时最多 2 次；候选最多 48 段，不再逐次加载整份文档的向量 JSON。旧库首次查询只在本次检索范围内推进有界回填；剩余待建索引会提示，不能把尚未回填的范围标为完整。

可选配置 `RERANK_BASE_URL/API_KEY/MODEL` 对授权候选重排，最多 48 段，响应最多 1 MB。不可用时保留融合检索顺序并提示，不允许模型补造候选。外部调用后再次核验命中资格及切片版本；索引修订、重排接口／模型／启用状态纳入分析缓存指纹。

当前接受的 PDF 文本含 U+FFFD 缺字标记时，原生页改为待识别，OCR 页改为待核对；完整的新 OCR 文本可以替换当前文本，旧原生层、图像及哈希继续保留。模型明确不完整和独立疑点不能因缺字已修复而解除。结构版本 13 仅将旧索引标记一次待校验，在原有账号和法律范围内有界回填；已发布旧缓存也须经过新完整性门禁，不改原文、审核记录或有效向量。`--resume --revalidate-pdf-decode` 可对冻结采集方案内的自有草稿显式重校验缓存，验证原件 CAS、版本与无运行租约，保存旧页证明后重新排队，已发布正文不被重写。

结构版本 14 同样只将派生索引标记一次待重校验；旧 `docx-basic` 版本 1 仅含正文段落，缺少完整包证据，不能继续作为全文完整资料检索或向量化。已保存正文、原件、审核和版本保持不变；重新提取必须使用真实原件和新包映射规则。普通文本、完整 PDF 和已符合新规则的 DOCX 保持原有资格，所有检索仍按账号、国家、一级资格、审核及有效期过滤。

结构版本 15 对旧 HTML 版本 2 和 PDF 缺图占位证据同样只标记派生索引待重校验。旧 HTML 没有正文图像的来源证明，不能继续依据其段落缓存放行全文。PDF 原生层或当前文字含明确的 `The linked image cannot be displayed` 占位时保留为 `source_incomplete`，要求补充完整来源；图片模型无法恢复原件中不存在的图像。升级不改原件、已存正文、审核、文书版本或有效向量；检查继续按账号及国家范围有界执行。

## 原生图片与 HTML 来源

`native_asset_ocr` 将 DOCX 内部图片与 WPF 已验证的内嵌光栅图接入现有处理队列。定位保留原件 SHA、DOCX 部件及关系、XML 路径，或 WPF 转换 artifact SHA 和 XPath；稳定图片标识绑定具体来源位置，相同图片字节在不同位置分别保存映射。每批默认四个资产，允许 1–20；与 PDF 识别共享进程内两个请求名额。受限子进程核对原件、图片字节、部件关系和像素，发送 PNG 不超过 8 MiB／六百万像素。多帧图像不能静默只处理首帧，外部引用不在解析时下载。

发送像素先写入账号 CAS，再在任务租约下保存来源、像素引用和尝试次数，随后请求图片模型；识别结果逐项保存检查点。已完成项恢复时不再次调用模型，失败自动重试最多三次，容量不足或暂时服务失败延后领取。显式重试只重置失败项，不创建新法规版本。正文重组通过受限子进程进行；图片文字是独立 `figure_transcription`，不虚构物理页号或完整文档阅读顺序。识别完成不能解除 Word 动态字段、对象、未知 XML、布局或法务审核门禁，模型不完整和疑点继续保留。

用户上传仍限 20 MiB。较大的已保存 DOCX 原件可经 `parse_archive_docx_bounded` 的文件模式处理，最大 64 MiB；父进程只传原件引用，子进程核对无符号链接普通文件、大小、前后 SHA 和文件身份。ZIP 实际展开仍限 50 MiB，XML、图片、进程时间、内存与输出限制保持独立。文件模式不修改或拆分原件，不执行宏，也不提高上传接口上限。

HTML 使用 `html-basic` 版本 3／`html-source-mapping-v3`。正文图像、picture/source、SVG 引用、canvas、object/embed 和正文 PDF iframe 保存到 `html_source.objects`，包括原件 SHA、DOM 路径、解码后 HTML 字符范围、原始引用属性及其 UTF-8 SHA；字符偏移和片段 SHA 不冒充原件字节偏移。导航与隐藏对象按正文范围过滤，alt 只作元数据，不代替识别文字。无图正文仍可通过原生门禁；图像或对象未核验、边界不完整、错误页面及空脚本壳不能放行全文。只有图像的页面可以保存映射和原件，正文及切片为空。

Next/Flight 中明确关联正文缩略图或正文组件层级的视频来源，以 `html-next-flight-video-source-v1` 保存原始 script 字符范围／SHA、解码记录及流 SHA、JSON 指针和视频网址证明，不执行脚本。脚本网址按 JSON 字符串解码，保留 `&amp;` 等字面量，不再次当作 HTML 属性实体解码。可唯一定位的原始网址另保留精确字符范围；转义或跨脚本内容只记录真实解码链，不编造视频 DOM 或字节位置。缩略图识别不能完成视频转录，正文视频继续阻止全文完整。普通旧 HTMLv3 映射保持兼容；存在新增视频对象或来源完整性变化的旧映射会被新图片预校验拒绝，须从真实原件重新受限解析。历史缓存尚未进行全库脚本扫描或迁移，不能据此宣称其视频内容完整。参考 [HTML 嵌入内容标准](https://html.spec.whatwg.org/multipage/embedded-content.html)。

已经显式采集并存入当前账号 CAS 的独立正文 `img/src`，可经 `bind_linked_image_bounded` 绑定至 `html_source.linked_images`，复核父 HTML、DOM、字符范围、原始 URL 属性与图片原字节 SHA。此入口只验证 URL 语法、不下载外链或解析 DNS；新增采集必须使用现有 HTTPS 公网、重定向、体积与时间限制。处理服务要求绑定父网址等于文档来源或该账号、该文档已保存的采集最终网址；含 `base/href` 的 HTML 继续待核验。受限工作进程验证全部图片帧及像素，HTML 图最多 12 MP，Word/WPF 仍为 6 MP，原图与请求 PNG 各最多 8 MiB；不缩放或丢弃帧，进程仍限制 768 MiB、35 秒 CPU 与 45 秒墙钟。原件 CAS、送模型的 PNG、尝试及结果检查点分别保留；已有处理服务负责租约及恢复。`picture/srcset`、SVG、canvas、未知边界和脚本图片继续待核验，不把某个候选图的成功识别当作完整页面。只有所有正文对象均通过图片识别且原生解析门禁完整，才恢复正文完整性；法规审核、一级索引条件与普通附件原件保存边界继续适用。格式 5 清单同时导出链接图片原件 CAS、原文引用、PNG 及转写文本定位。图片候选与替代文字的语义以 [HTML 图片标准](https://html.spec.whatwg.org/multipage/images.html) 为参考；完整光栅解码以项目锁定的 Pillow 版本和 [官方接口说明](https://pillow.readthedocs.io/en/stable/reference/Image.html) 为准。

全部已知对象核验完成后，当前提示只解除解析器自身的“尚未视觉核验”一条，移至 `quality.resolved_warnings` 保留记录；其他独立来源、版本或边界提示继续存在。检查点恢复按同一门禁重组派生状态，不重复调用图片模型，也不改变法规原件、版本、审核或有效向量。

网页图片的显式采集命令见[服务器采集](RESOURCE_COLLECTION.md)。它在下载前复核父原件，成功的原图、HTTP 元数据收据及像素验证结果加入来源映射；受限解析和识别仍通过既有处理链执行。每轮只读取最多四个待识别原图，32 MiB 是批次限制，已经完成的图片不累计占用后续批次。指定资料的处理作业有独立账号与草稿资格门禁，全局处理沿用既有权限规则。总处理名额保持原有限制；已有名额仅运行扫描或仅运行向量时，空闲名额优先推进另一阶段，以免长扫描持续挡住已完成文本。

PDF 表格提示采用 `painted-grid-ctm-v3`：在页坐标中合并实际绘制的直线和细矩形，应用 `cm`、`q/Q` 以及 Form XObject 自有 Matrix／Resources；仅填充的曲线图标不作为表格边线。非法、循环、缺资源或超界几何继续要求布局复核。该分类只决定是否需要表格核验，不证明扫描文字或法源完整；已经保存的原件、OCR 与历史疑点仍保留。实现参考 [Adobe PDF 标准的图形状态及 Form XObject 定义](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf)。

两份清单附件是范围和示范截图资料，不能因正文或图片识别完成而自动成为法规库资料。2026-10-13 的受限回放在原始印尼附件上保留了 48 个图片位置／47 个图片哈希；首两张真实截图的模型返回均不完整，保留待核对，未入业务数据库或向量库。普通 `role=secondary` 上传附件继续只存原件；独立二级法律资料仍可文本化，但不建立向量。

## 抓取约束

- 仅标准端口 HTTPS，无 URL 凭据或控制字符。
- DNS 全部解析结果必须为公网地址；连接固定到已检查 IP，同时使用原域名作 TLS 验证，防止 DNS 重新绑定。IPv4 优先，同一次检查所得地址可有界切换；单地址连接/TLS 最多 5 秒，仍受整次连接和下载截止约束。
- 最多 3 次重定向，每一跳重复 URL 和公网地址检查。
- `CollectionPlan.max_original_bytes` 默认 20 MiB，最高 128 MiB；上传限制不变。`download_timeout_seconds` 默认 90 秒、范围 30–900；目录和详情请求仍为 90 秒，Range 分段请求仍各有 90 秒截止。socket 超时 15 秒，超时关闭活动 socket。DNS 等待最多 10 秒、最多 8 个同时存活的守护解析线程，系统 DNS 异常不会无限占用应用工作线程。
- 默认忽略 `HTTP_PROXY`/`HTTPS_PROXY` 等环境代理，不向原网站发送 cookie 或登录凭据。运维可逐域显式配置受信 CONNECT 代理、可选公共 DoH 和固定普通浏览器请求头，仍验证公网 IP、TLS 原站身份、重定向、时间及体积；配置边界见 [服务器采集](RESOURCE_COLLECTION.md)。普通文件采用 identity 传输；目录适配可显式启用 HTML/JSON/XML 的 gzip，压缩前后均不超过 4 MB，并校验流结束和校验和。其他格式、异常压缩流或解压超限拒绝。
- 普通来源的附件发现只读取主 HTML 中同源、具有受支持文件扩展名的直接链接，最多尝试 5 个；附件重定向也必须同源。清单目录发现使用下述独立流程，不能由普通来源任意递归。超过 4 MB 的 HTML 不进行附件发现。
- 次级附件只返回原件，失败记录在 warnings 中；不得静默展示“所有附件已抓取”。

运维需要限制可配置来源的权限、并发任务和保留策略，核对来源使用条件。此模块不包含 JavaScript 网站浏览器、验证码绕过或全网爬虫。

## 流式采集与不可变版本

业务入口统一为 `CollectionService`（`app/collection.py`）。手动、定时及旧 `/fetch` 都提交持久任务，HTTP 返回 202。工作线程逐份下载、逐份落盘和提交记录，后续正文解析、向量化进入独立队列；慢文件或模型请求不会挡住其他下载完成项。每条记录保存来源计划快照、原始/最终 URL、尝试次数和原件版本 ID。

`app/blob_store.py` 边读边计算 SHA-256，原件位于 `data/files/blobs/<账号哈希>/<内容哈希前2位>/<后2位>/<完整哈希>`。文件名只作展示。临时文件在同一文件系统的 `.staging/`，内容 fsync 后通过原子硬链接发布，文件只读，随后事务写入引用。相同账号的相同原件复用字节；不同账号隔离。数据库失败不能 unlink 已发布对象，因为另一条记录可能已引用。旧平铺原件保留原路径，不启动时搬迁。

版本号属于法规家族，不是文件哈希：最新正文 A→B→A 会记录 v1→v2→v3，v1/v3 复用同一份字节。最新版本未变化时直接复用记录和已完成的解析；一级资格或向量配置变化时补索引。跨 URL 的版本须在任务 entries 中提供同一官方 `identity_key`；不凭相似标题自动合并法规。每份版本仍有自己的审核/有效期，新的内容不会继承“已审核”。列表、正文、下载、历史和引用都绑定文档 ID，不使用可变的“当前链接”代替旧引用。

## 按文档执行采集清单

当前预置两份方案：[`indonesia-20261003.json`](../config/collection-plans/indonesia-20261003.json) 版本 6，对应用户文档的 5 章 29 项：法规 10 项、司法解释性材料 4 项、判决 4 项、部门补强 7 项、条约 4 项；[`singapore-demo-20261009.json`](../config/collection-plans/singapore-demo-20261009.json) 版本 5，包含 16 项。各方案保留独立 `country`、版本及范围，由服务启动校验并加载。印尼章末检索规则不增加任务数，3 个示范详情网址保留参考用途，不作为种子。

每个条目保留入口角色、范围、排除项、字段、步骤、版本及映射规则、验收要求和完整原文，后台详情可折叠展开。配置条目会在当前账号下创建停用的受管来源并冻结版本快照，不自动启动清单全量下载。相同账号重复配置幂等；同版本内容发生变化须升版，不能覆盖旧绑定和任务。

目录发现与正文采集分两步。`ChecklistService` 将目录和详情交给已有受限下载队列，`discovery.py` 根据明确的站点规则识别分页、详情和可能的原件。取得的页面以账号隔离的内容寻址文件保存，目录证据表记录原始及最终 URL、内容哈希和提示；这些记录不创建法规正文，不进入解析或向量队列。发现的原件链接单独登记为候选，保留发现出处、状态和排除理由。路径匹配成功不表示材料内容或法律效力已审核。

一次发现最多处理 40 页，未处理入口保存在持久队列中；本批结束后再次发现继续剩余入口。每条目的目录队列及正文候选各有 20,000 项上限，深度最多 30 层，触顶会提示拆分或补充适配。单批结束不代表全目录完成。BPK、MA JDIH及普通链接规则仍受官方站点实际页面、403、动态加载和文件域约束；受信文件域只能由明确配置扩展，不能从任意页面链接自动放宽。

印尼方案版本 2 增补 Setneg 官方公开 JSON 目录、万隆地方目录及已核实的原件路径规则。Setneg 请求仅由冻结方案与明确的官方路径生成有界 POST 筛选体，不开放任意 POST 配置，不跟随 POST 重定向；目录请求、分页偏移和官方返回总数单独保存到结构版本 11 的证据表。详情只提取原件 `file`，不把摘要 `v` 当正文。官方库总数仅作为该站点、该类型分母；万隆是地方补充，不代表全国地方条例覆盖率。

版本 3 增补最高法院秘书处公开目录、RCEP/ACFTA 官方镜像及 WTO 印尼承诺原件适配；按明确条目和官方路径约束候选，不以别国文件或摘要替代原件。大税表条目显式提高原件大小上限，慢原件来源可设置较长有界截止；HTTP 200 的拒绝页仍判失败。历史方案副本位于 `config/collection-plans/versions/`，旧绑定和任务快照继续保留。可用入口与覆盖情况见真实样本报告，不将镜像恢复等同于全清单完成。

版本 4 增加 BKPM 投资主题公开 JSON 目录及官方原件存储域，逐页核对主题、分页行数和文书标识，只提取正式原件字段。来源状态和站点数量作为目录证据保存，不代替法律审核或法源覆盖判断；版本 3 副本保留在历史方案目录。

操作者按条目要求筛选候选，再选择一级或二级发起原件采集。二级必须明确选择同账号、同国的一级版本。只有取得符合原件类型的内容后才建法规版本，原件、解析与审核状态分别记录；返回目录或验证页的候选会失败。新资料以 `review_status=draft` 保存，法规性质、适用日期、效力及范围须审核后才能成为有效检索依据。相同原件按既有规则去重，新正文追加版本，旧条文和旧关系保留。

清单中的人工筛选和验收要求不会自动变成代码规则。例如 3.4 的涉企语义、最高法院身份和按裁判日滚动五年仍需核验，当前不自动识别正文中的裁判年份；3.1 PUU、3.3 HUM及官方精选判例不套用此窗口。条约接受、生效、批准及实施关系也须回查原件。29 项配置完成、目录已发现、正文已取得、已解析、已审核及已索引是不同进度；拒绝页、空框架、适配不足或缺附件必须留下缺口，不能显示全量成功。

## 分级、标签与映射

用户指定的“一级/二级”指主法规与其引用/相关法规，与普通文件附件分开建模。一级和二级法规都解析正文及需要识别的页面；正文完整的一级版本可提前向量化，进入 RAG 时另外核验国家、业务、审核和适用版本。文件附件继续原件留存。

国家分类使用保留命名空间 `country:<ISO2>`，如 `country:ID`；`document_countries` 保存文档的不可变国别，同一法规家族的版本不得跨国混用。自由标签、法域说明或另建采集组不能改变该边界。标签保存在分类中，修改检查 revision 并追加历史；预置标签如 `country:ID`、`checklist:ID-3.3`、`kind:case`、`topic:MA HUM`。章号和材料类别不代表法源等级、一级／二级、适用期或法律审核。

两份清单的服务器采集可使用显式原件选择文件，分别记录 URL、用途分级、一级关联键及官方页面出处。二级任务核验已有同国一级原件，关系在共享来源原件链接证据落盘后写入；两端版本、原件 SHA-256 和来源页面 SHA-256 固定保存。一级原件落盘后，二级下载与解析可和一级向量处理同时推进。PDF 图片页和恢复裁剪继续由受限工作进程处理，图像证据绑定原件版本、物理页码、图片哈希及裁剪范围。

两级法律资料的完整文本与定位导出到私有清单中的 `texts.jsonl`，关联和识别图片分别在 `relations.jsonl`、`ocr-pages.jsonl`、`ocr-regions.jsonl` 中。一级文本完整才建立真实向量，二级不建立向量；不完整或未审核的资料仍受 RAG 门禁限制。操作与缺口说明见 [服务器采集](RESOURCE_COLLECTION.md)。

首次归国会让整个法规家族重新进入审核，保留原审核历史。原先按普通业务文件上传的资料不会沿用默认的已通过状态；新版本也从草稿开始，重复采集相同的已审核版本则保留其审核结果。普通附件展示父资料的国家，继续仅存原件。

关联是独立多对多表：`source_document_id → target_document_id`，带 `cites/related`、采集组及 locator，两端固定版本且国家一致。显式选取的二级来源计划会为每份正文关联所选一级版本；默认类型是 related，不把未核实的关系写成“已抽取引用”。新版本不会重写旧关系。普通来源的额外网址仍是明确种子，同源直接附件每个主 HTML 最多 5 个；清单目录使用独立的有界发现队列。

`Search.country` 可显式指定大写两位国家代码或 `unassigned`。业务快照目的国可明确解析时，以业务国家为准，冲突的国家或国别采集组返回 422；没有业务时使用显式国家或 `country:<ISO2>` 采集组，冲突同样拒绝。两者均未指定时只检索未分国资料，不混入国家法规；未知目的国名称不靠模型推断。审核、适用期、一级资格及版本选择继续生效，国家筛选不能绕过这些门禁。

## 并发、背压与恢复

显式设置 `VISION_OCR_ADAPTIVE=true` 时，图片识别共享槽默认从 `min(VISION_OCR_WORKERS,16)` 起步，可通过固定范围批量入口指定较低起点，最低降至 1；每次升额至少间隔 30 秒且收到至少 `max(16,当前目标)` 个完整 HTTP 2xx 响应，随后增加 8，最高不超过启动配置。429、5xx、连接或读取超时立即将目标减半至下限，并重新开始至少 30 秒冷却。下降只限制新领取，已持有的识别槽自然结束并归还；短时实际占用可以高于下降后的目标，但始终不超过固定最大值。此控制不新增请求或重试，也不改变采集队列单次最多 20 页、模型截止、源图映射、正文校验及索引门禁。HTTP 成功仅衡量传输健康，无效 JSON 或正文不完整仍按原有规则处理，不能当作识别准确性的证据。

OCR 共享槽通过条件变量维护当前占用与目标，原生解析继续使用固定信号量；运行中改变 `VISION_OCR_WORKERS` 或 `VISION_OCR_ADAPTIVE` 均拒绝新领取，需重启所属 worker。`app.vision.vision_ocr_capacity_state()` 只读返回最大值、当前目标、占用及峰值、成功响应和容量失败数、升降次数及冷却剩余秒数；读取不初始化额度、不读取密钥。默认 `VISION_OCR_ADAPTIVE=false` 保持固定额度，不进行健康升降。

DeepSeek 图片识别仅作为必要的补读，默认不开启，不对完整原生正文或成功识别缓存重复调用。其图片请求额外通过 canonical `TEA_DATA_DIR/.runtime/deepseek-vision-XX.lock` 的线程锁与文件锁共享 `VISION_OCR_REQUEST_WORKERS` 并发额度，所有进程必须使用相同数据根；通用模型请求还受各服务进程的模型请求槽限制。PDF、原生图及直接区域补读在登记请求意图前领取，等待超过 5 秒按容量延后，不消耗模型尝试次数；直接图片调用也经过同一可重入入口。进程退出由操作系统释放文件锁，不能删除或替换运行中的锁文件。运行配置修改后须重启所属 worker；既有未知结果保留人工核验状态。此限制不修改普通文本 LLM 或独立的 embedding 并发 64。当前能力及请求格式参照 [DeepSeek 官方图像文档](https://api-docs.deepseek.com/guides/vision/)，网关别名能力仍需实际验证，不能根据名称认定识别成功。

SQLite `BEGIN IMMEDIATE` 保护领取和状态转移；下载/解析/模型调用不持有写事务。租约 token 加有效期在提交前复核，旧工作线程不能覆盖重新领取、取消或重试后的结果。网络连接另有数据库名额，每一重定向目的域都取得名额；取消领取并不提前释放仍活跃的物理连接。长截止原件领取时延长本次租约，协调器继续心跳。进程强制终止后，旧租约到期再恢复。

共享库独立续跑期间，主站显式设置 `TEA_SHARED_LIBRARY_WORKERS=external`。该配置在主站创建时校验并固定，只注入主站 `CollectionWorkers` 与 `ScheduledCollector`：下载、解析/向量候选、过期租约、失败收养、到期恢复及定时来源均在 SQL 的 `LIMIT` 前排除固定系统账号；下载/处理/向量持久租约额度、阶段优先级与恢复背压也按该范围计数。系统任务保持原状态、次数、收据和未知付费隔离，不会被标成完成。私有新账号和新上传无需重启即可被处理；共享资料读取和查询向量沿用原权限、效力与审核门禁。手工构造 `Service` 或明确指定系统账号的独立 runner 不读取这个环境变量，仍须自行绑定固定计划、缓存和请求收据。默认 `internal` 保留原有全库处理行为；无效值拒绝启动。健康接口 `collector.shared_library_workers` 显示配置，`collector.status` 仍表示实际 worker 状态。

主站与独立向量 runner 必须使用相同的 `EMBEDDING_ADMISSION_PATH`、模型配置及 `EMBEDDING_HTTP_WORKERS`，共享请求额度保持全局，不因私有后台范围增加。下载同域物理连接和冷却、手工提交/附件发现的全库磁盘队列上限也保持原规则；私有文件上传不受系统正文待处理数量阻塞。外部模式只选择工作归属，不授予未知请求重发权限，也不把独立 runner 的缓存接入通用处理器。切换模式应先排空原主站 worker 后重启；同时保留其他 `internal` 全库 worker 仍会竞争系统任务。

本机资源充足时，可在启动所属 worker 前明确设置 `TEA_PROCESS_WORKERS=32 TEA_PARSE_WORKERS=32`；应以实际工作负载测量选择并发数，最高配置不保证最快。解析额度在本服务进程首次使用后固定，运行中改变配置会拒绝新解析，需重启所属 worker。普通解析保持默认 45 秒截止，归档 PDF 保持固定 45 秒截止；各自的单次内存、CPU 和 40 MB 结果限制不变，Docling 保持其原有 4 GiB/110 秒 CPU 边界；并发增加会累加资源占用。32 个普通解析子进程的地址空间限额合计最高 24 GiB，Docling 合计最高 128 GiB，另有父进程及结果缓冲开销，这些限额不是实测 RSS。两个配置各自限制持久任务与本进程物理解析，多个服务 PID 的解析额度分别计算，不能称为跨进程全局解析上限；默认全库模式的多个 worker 应采用一致的处理任务配置；外部托管模式的主站只按私有范围计算任务额度，独立 runner 继续遵循自己的显式范围与额度。同账号、来源 URL、原件 SHA 与版本相同的有效 parse 租约继续串行，避免同原件两国副本同时识别；另一阶段待处理时继续优先填补阶段，OCR 和 embedding 请求仍有独立的原有名额，增加本机解析并发不增加这些外部请求上限。

原生解析共享槽使用线程安全的 [BoundedSemaphore](https://docs.python.org/3/library/threading.html#threading.BoundedSemaphore)，实际解析继续使用独立的 [spawn 子进程](https://docs.python.org/3/library/multiprocessing.html#contexts-and-start-methods)。本管线全部受限子进程的启动与回收共用生命周期锁，避免当前 [CPython 的 waitpid 轮询](https://github.com/python/cpython/blob/v3.14.7/Lib/multiprocessing/popen_fork.py)在多线程 start/cleanup 与 join/close 之间竞争；正文计算和管道等待位于锁外。该锁不保证第三方另行创建的子进程封装或 `multiprocessing.active_children()` 线程安全。超时或进程中断只清理本次创建的子进程，确认回收后才归还槽；无法确认退出时保留所占额度，防止超发。暂时满额沿用 `ProcessingDeferred` 与 5 秒后重试。

单次限定账号及文档的处理范围仍最多 20 个文档 ID；32 的本机容量不扩大这一授权边界。默认全库模式下，同库任务可共享额度；新空位优先缺失的 parse/embed 阶段，满额时仍等待，并无抢占或严格阶段比例。32 个任务可能同时持有各自的结果和 manifest，40 MiB 单结果上限不是父进程结果总量上限。OCR 页面槽最高 128、模型请求单独最高 32 时，采集管线每份 PDF 最多并行处理 20 页；至少 7 份资料同时具有待识别页，且 `TEA_PROCESS_WORKERS` 与 `TEA_PARSE_WORKERS` 允许并行时，页面处理槽才可能达到 128，模型调用仍不会超过 32。现有图片模型容量以服务端请求额度和实测错误率为准；未知传输结果保留人工核验状态，不自动重放。识别最大额度与自适应开关首次使用后固定，运行中变更或无效值会拒绝新工作，释放已取得的槽不重读配置；满额仍延后且不消耗模型尝试次数。此额度覆盖渲染、模型请求和结果校验整个识别步骤；更高上限不保证实际占满或吞吐线性增加，embedding 使用独立的 HTTP 额度，默认 2、可显式配置为 1–64；实际容量与续跑操作见 [向量处理](EMBEDDING_OPERATIONS.md)。

2026-10-14 的本机对照复用同 32 份原件的 499 页原生窗口：8、16、32 并发分别用时 3.295、1.982、2.198 秒，实际子进程峰值分别为 8、16、32，正文、chunks 和完整 manifest 哈希均一致。该组单次测量以 16 最快，32 比 16 慢约 10.9%；父进程及所属解析子进程的 RSS 采样峰值约 462、808、1307 MiB。96 个解析子进程均保持 768 MiB/35 秒 CPU 限制且完成回收。该结果只覆盖所测原生 PDF 窗口，不代表 OCR、模型服务或所有格式的吞吐。

HTTP ETag/Last-Modified 保存在账号内缓存，304 仅复用匹配最终地址且通过哈希校验的原件；转向不同 URL 不转发条件头。Retry-After 按秒数或 HTTP 日期解析，保留服务器要求的最短等待时间，不能将 900 秒提前截为 300 秒；字段仍限制 128 字符并拒绝控制字符。自身指数退避最多 300 秒，服务器较长等待通过持久队列时间戳落实到实际响应域；向量服务的同进程、同配置请求也共享等待，不占工作线程睡眠。依据 [RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3) 和 [RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)。安全检查失败、非法地址、超限、确定性解析失败不自动反复重试。

慢大原件仅在具备强 ETag、明确总长度和 Range 支持时切换分段检查点：观察至少 5 秒、速率低于 32 KiB/s、文件至少 1 MiB，默认每段 64 KiB，每次领取最多并行两段并遵守已有真实连接名额。每段校验最终 URL、ETag、总长度、偏移和长度，再提交 CAS 引用；恢复时复核账号路径、大小和 SHA-256。版本改变建立独立下载记录，旧分段不混入新原件。服务器不支持 Range 时退回有界普通流；快文件仍一次流式保存。只有全部分段连续且完整校验、原子组装后才创建法规版本。进度推进不耗失败次数，真实错误仍受重试上限约束，页面百分比与“已存原件”分别显示。

正文解析独立提交；向量每个 HTTP 请求最多 64 段，默认串行，显式双请求模式的一次持久领取最多 128 段，成功后保存检查点。所有调用共享进程内可配置的 1–64 个请求名额，默认 2；文档任务额度可配置为 1–32，仍受解析与向量总领取额度限制。失败有界缩小请求批量，冷却、永久错误和中断各自处理；正式批量入口保存每个成功 HTTP 批次并暂停结果不明的重发，详情见 [向量处理](EMBEDDING_OPERATIONS.md) 与 [服务器采集](RESOURCE_COLLECTION.md)。中断后从缺失向量继续，已完成解析不重跑。模型失败保留正文与原件并展示错误；没有 embedding 配置时如实使用词项检索。把已解析二级版本加入一级采集组会补索引，解析途中修改分级也在提交事务内重新核对。任务 revision 只由取消/重试递增，进度使用 updated_at，避免正常处理进度导致无法取消；旧控制命令仍返回冲突。API 返回的 completed 仅表示当前任务范围处理结束，不能当作 29 项采集清单或网站全量完整的证明。

## 运行与恢复操作

新加坡 eGazette 的立法目录也包含参考出版物。采集入库对官方完整标题 `The Statutes of the Republic of Singapore - Subject Index to Acts` 和 `Pre-Publication Notice - Re-issue of Subject Index to Acts` 作大小写无关的精确匹配，同时核对相应官方目录类别；这些独立索引和再版通知保存为二级指引，仍提取正文，但不生成一级法规向量。规则不匹配普通标题中的 `Index` 子串，也不因为真实法案内有索引页而降级整份法案。原官方目录证据及分类依据保留在采集清单中，未知出版物仍需审核。旧库已有不同分级时，重新入库返回分类冲突，须依据原件、官方记录、当前版本与修订号显式修正；不在续跑时覆盖人工分类。已生成的数值可保留为历史，但二级资格会阻止其参与法规检索，不能把向量表总行数当作当前可用法规向量数。

同账号的同一原件可以复用已保存的向量数值。候选按来源 URL、原件 SHA 与版本从既有索引最多查八份资料，再按文档及分块标识精确查找；当前模型标识、完整正文、最新版本、一级分类、索引状态、分块正文及实际向量输入必须一致。账号 CAS 原件在写事务外校验一次哈希，提交事务内再次核对租约、原件身份、元数据及分类修订、索引修订、输入和来源向量摘要；损坏原件或向量拒绝整批提交。仅缺失部分在事务外调用已有向量服务，全命中批次不调用服务；并发冷缓存仍可能分别请求，不能把此机制称为冷请求去重。

复用数值继续经过 `store_vectors` 的维度、有限值和归一化校验，末位舍入可能变化。`manifest.embedding_reuse` 保存当前分块的来源与目标文档版本、输入摘要、模型标识、来源及目标实际向量摘要和最近成功批次的复用／服务输入计数；不把一次 `embed_texts` 调用当成实际 HTTP 调用次数。记录最多四千零九十六条及 4 MiB，超限拒绝本批并保留此前检查点。目标保留自己的定位、国家、审核与适用期，独立二级资料不取向量；此复用不改变正式 RAG 的审核、国家及现行版本门禁。

服务器上的批量发现、原件抽样、续跑及扩量入口见 [服务器并发资源采集](RESOURCE_COLLECTION.md)。入口复用本节的同一持久队列及安全边界。

数据根布局和按账号、国家、版本导出的文件目录见 [资料存储与盘点](STORAGE.md)。原件与目录证据集中保存；目录快照不复制原件，也不代替备份。

1. 通过 `make dev` 启动本工作树的服务，来源页提交任务并查看逐项进度。`GET /api/tea/health` 的 collector 应为 running；recovering 表示协调循环出错后自动重试，last_error_at 用于定位日志。HTTP 存活不等于队列正在工作。
2. 失败任务按条目查看错误，修正来源/模型后点重试；范围上限导致未发现完整附件时，补充明确种子并创建新任务。不清空队列表来“恢复”。
3. 正常停止不再领取新工作，尽量完成已领取的受限调用；强制中断的任务在租约到期后恢复。已保存原件不丢失。
4. 备份 SQLite（使用 SQLite 在线备份接口或停止服务后备份，不能只复制运行中的主数据库文件）及对应 files 目录，并保留后端 .env 配置；还原必须来自同一备份点。数据库/文件的保留期由业务另行确定。
5. 强制终止可能留下 `.staging` 或未引用 blob。当前不自动清理，以免误删在途任务或历史条文；离线核对引用后再制定保留策略。本地 POSIX 文件系统必须支持硬链接与目录 fsync，不把此布局直接部署到不具备同等语义的网络盘。

结构升级 4–6 增加家族/分级/关系、队列/条件缓存及网络租约，版本 7 增加清单与国别，版本 10 增加持久检索索引，版本 11 增加官方 API 请求证据，版本 12 增加版本绑定的下载分段检查点，版本 13 重新核验旧索引完整性。升级在事务中执行，保留既有原件路径，不凭旧标签猜测国别。所有进程需使用同一并发配置；当前仍是单机 SQLite 与文件系统实现。未实现全站 JS/验证码处理、任意站点分页适配或自动法律引文确认；不能把验证码/错误页面视为已完成法条。

数据库暂时返回 `SQLITE_BUSY`／`SQLITE_LOCKED`（包括扩展错误码）时，采集任务延后处理，不消耗解析或网络失败次数；其他数据库错误仍走失败路径。整页图片和识别结果的检查点只对本地受版本、授权与租约保护的事务最多重试 3 次，重试不重新渲染、请求模型或清除页级尝试历史。参考 [SQLite WAL 的并发限制](https://www.sqlite.org/wal.html)，这项处理不扩大写事务并发，也不保证其他进程不会占用数据库。

同一服务进程对同一数据库文件的写事务按等候顺序进入，多个 `Database`／`Service` 实例和路径别名共享队列；写事务结束、回滚或建立连接失败后释放名额。读取连接及不同数据库不等待该队列，渲染、下载和模型请求继续在写事务外并发。相同线程再次开启同库事务会立即拒绝，调用方应传入已有连接，不能用第二连接形成嵌套写入。队列在 fork 子进程中重新建立；它只协调本进程，其他进程仍由 SQLite 的 WAL、`BEGIN IMMEDIATE` 和原有 15 秒繁忙等待处理，外部占库时仍如实抛出数据库错误，不重放模型调用或降低持久化设置。
