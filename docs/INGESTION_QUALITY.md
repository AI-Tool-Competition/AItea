# 采集质量验证

验证使用独立工作树和新的数据目录，覆盖原件采集、正文与图片处理、一级／二级映射、向量索引和重启检索。真实模型只有显式启用后才调用，失败保留报告及原件。报告不能代替法律审核或全国采集完整性证明。

## 运行样例

仓库提供 [印尼范围的工程样例](../config/verification/indonesia-smoke.json)，通过官方 WTO 文件验证一级正文及二级关联。样例分级用于检验工程行为，关联类型为 `related`，不表示系统已自动判断引用或条约适用性。

```bash
uv run --project backend --locked python scripts/verify_ingestion.py \
  --plan config/verification/indonesia-smoke.json \
  --output data/verification/indonesia-smoke-01 \
  --time-budget 300
```

每次使用新的输出目录；工具拒绝非空目录，避免触碰已有资料库。普通运行清除继承的模型配置，仅验证采集、存储、词项索引和隔离。需要真实向量及图片识别时增加：

```bash
  --live-models --models-env /绝对路径/仅含模型配置的私有文件
```

该文件只读取 `LLM_*`、`EMBEDDING_*`、`RERANK_*` 和 `VISION_OCR_*`，不复制业务数据库或客户端配置。图片识别另外要求 `VISION_OCR_ENABLED=true`。密钥不能写入计划、版本库或报告。

计划允许 1–20 个样本，每个指定 `id`、`path` 或 `url`、`level`；本地路径相对计划文件，可附 `source_url` 记录来源。二级必须提供指向本计划一级的 `primary_sample_id`。本地已保存原件与本轮网络下载在报告中分别记录。最多 10 个查询，每个包含 `text` 与 `expected_sample_ids`，检查前 5 条结果；总时限最多 900 秒，超过时限终止本次验证的进程组并保留现有检查点。

## 验收依据

工具创建全新的演示账号，先验证草稿不可检索，再仅在这个账号中把测试记录标为演示资料。该步骤不向生产法规库授予法律审核资格。

- 原件重新计算 SHA-256，与版本记录一致；重复入库复用相同版本和内容文件，重复请求保持幂等。
- 页面完整性、OCR 页图哈希及来源版本／页码一致；任何识别失败或待核对页都不能算正文完整。
- 二级法规正文可解析、关系绑定指定一级版本，但二级没有检索向量，也不能被显式检索越过门禁。
- 真实模型模式要求每份一级的全部切片拥有匹配当前配置及输入哈希的向量；只有实际执行向量检索才能通过 hybrid 验收。
- 查询召回预设样本，重启服务后仍可召回；其他国家和未审核记录不泄漏。
- 导出资料、关系及 OCR 图片目录，保存页图和原件映射；退出码 0 才代表本次计划通过。

输出目录包括 `tea.sqlite3`、`files/`、`catalogs/`、`report.json` 和本次 `worker.log`。这些是忽略的运行数据，不提交 Git。报告保存检测范围和失败原因，旧报告不会被新一轮覆盖。文件布局与备份见 [资料存储与盘点](STORAGE.md)。

## 已核对的边界

本轮 `make check` 通过 686 项后端测试、140 项前端交互测试，以及静态和类型检查。回归覆盖旧库升级、原件版本保留、过期写入、跨账号／国家／分级隔离、OCR 中断和容量背压、向量批次恢复，以及外部模型调用期间审核／分级／版本变化。分析入口准备索引后才捕获运行快照；仍有待回填资料时返回 `409 index_preparing`，不先调用生成模型再丢弃结果。

真实查询使用了向量与词项融合，但这些完整候选的远程重排多次超时，返回了明确的降级提示；三条查询约 12.3–12.6 秒。短输入重排曾成功，尚不能称完整重排链路稳定。扫描件中模型未报告疑点的数字也可能错误，因此测试同时比较原始文本层、页图和转录，不只统计请求成功率。

本次默认 `make build` 在共享账号的内存限额下被系统终止；使用锁定版本的 `pnpm build --webpack` 并设置 `NODE_OPTIONS=--max-old-space-size=3072` 完成生产构建、类型检查与 164 页生成，耗时约 62 秒。未修改默认构建器或关闭检查。Webpack 构建选项见 [Next.js 官方命令说明](https://nextjs.org/docs/app/api-reference/cli/next#next-build-options)。

SQLite 检索容量基准使用 372 份合成文书、67,980 个切片和 2,560 维向量。2026-10-13 本工作树测得实际 `Service.search` 三次约 0.77 秒、峰值进程内存约 74.8 MiB；网络被禁止，模型被替代为确定性测试实现。它只说明此机器上的本地索引开销，不包含真实 embedding、重排或法律召回准确率。

印尼 29 项入口的有界实网诊断目前有 12 项部分验证、17 项受阻，没有任何一项据此宣称全量完成。Setneg 官方库的 UU／PERPU／PP／PERPRES 分母分别为 901／33／2610／2453，属于该来源当时的目录；UU 首页、次页和末页已核对。其他站点仍有挑战页、慢流及服务错误。20 MB／300 页的文件处理上限、人工法律审核和识别待核对项仍是显式边界，不通过提高成功计数来隐藏缺口。
