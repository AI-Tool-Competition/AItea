# 法律证据与人工研究

在线普通问答由一个主 Agent 读取法律证据，解释规则、对应用户事实并直接写答复。证据服务仅负责搜索候选、读取相关完整条文、返回已知版本关系，不调用法律子模型生成独立报告。工具、来源快照、预算和业务事务的权威约定见 [Agent 运行机制](AGENT_RUNTIME.md)。

法律方法存放于 `config/agent-skills/legal/SKILL.md` 等按需读取的短文档。区分义务主体与实际办理者、遵守用户明确假设、保留适用条件、处理版本与证据缺口，属于主模型分析要求；程序只能验证归属、版本、引用编号和输出完整性，法律解释须另行评测。

已有简化引擎和六阶段引擎保留历史报告、后台节点分析、法律预览及人工调试入口。本轮停止扩展这些引擎和其复杂结果结构；普通会话不调用它们，不创建 `legal_analyses` 报告，也不将报告转换成第二份正文。下述配置继续适用于这些保留入口。

## 保留的六阶段配置

后台节点分析、法律预览和显式调试仍使用 QA-01 至 QA-06，保留规则卡、断点、检查点恢复与有限复核。普通对话使用主 Agent 与证据服务；节点研究入口继续使用其法律规则或模板快照。发布规则只影响使用新版本的新业务。

| 模块 | 职责 |
| --- | --- |
| QA-01 | 识别问题类型、领域及争点 |
| QA-02 | 收集必要事实，区分提取、确认、证据和冲突 |
| QA-03 | 区分监管范围、法院或仲裁及准据法，确定检索范围 |
| QA-04 | 检索候选，保留原文定位、版本和未覆盖事项 |
| QA-05 | 对照适用条件、例外与抗辩，在参数充分时核算期限 |
| QA-06 | 展示结论、解释、依据和行动，保留人工复核要求 |

六阶段模式每批默认最多追问三项，可配置一至五项；复核默认两轮，可配置一至三轮。最多 60 张规则卡，附加法域最多 20 个。结构或引用校验仅有限重试。规则卡不能关闭服务端证据、权限、适用期和人工复核要求。
