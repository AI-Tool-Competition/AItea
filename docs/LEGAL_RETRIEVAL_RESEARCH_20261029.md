# 法律检索研究与改进记录

本记录对应 2026-10-29 的研究及本地修改，使用现有 `refactor/evidence-first-runtime` 工作树。研究只扩展证据服务、原文上下文和诊断，不新增法律子模型、独立报告、审核门禁或常规二次润色。当前主模型设置保持 Nemotron-3.5/high。下述开发诊断与自动检查不代表法律服务质量已经验收。

## 取得的论文和作者项目

四篇论文的 PDF、文本提取结果、三个作者仓库的代码与说明均已下载到本工作树 `.dev/research/legal-retrieval-20261029/`。`manifest.json` 保存仓库提交、论文 SHA-256 和页数。稀疏检出不包含大规模数据集和模型权重，未运行上游安装脚本，未将旧版依赖装入茶渡，也未复制上游程序代码进入运行服务。

## 本次定位的故障

前序真实货款题先调用了《民法典》第二百六十条，该条实际涉及集体所有财产，属于模型选条错误，不能通过“成功取得原文”判为正确。之后生成超时是另一项故障，来源已取得与答复已交付应分开记录。原始记录见[咨询实测](CONSULTATION_CARDS_20261029.md)。

本轮增加选条诊断后，日常货款问法在前六个直接命中中未覆盖核对用的第 577、579、626、628 条，法律概念问法覆盖两条。精确指定第 579 条能排在第一位。四条是开发诊断中的候选规范集合，答复无需机械引用全部四条；具体结论是否充分仍按问题评阅。

源代码检查发现，条款索引 `partial` 时 `ClauseSemantic.search` 会直接跳过全部完成向量。当前已提交的中国法条款分段为 8,326/28,133；印尼为 30,533/101,848；新加坡为 7,023/23,150。这些进度尚未完成，文件级向量能识别法规文件，不能独立确定长法规中的具体条文。另有三处交接问题：原文所属编章信息只参与本地排序，未随条文交给主 Agent；相邻、援引条文会插入直接命中之间；补读完整原文会丢失原先的召回信息。

## 已接入的改动

`country_clauses.py` 允许模型、来源及分段规则均匹配的部分索引参与候选召回，仅读取已提交非空向量，保持 `partial`。来源或模型不匹配仍拒绝使用，不向量化的新条款不能被视为不相关。

`country_packs.py` 将原件中实际存在的编、章、节附到 `locator.headings`，每个标题保留同一原件版本内的记录编号。重排序输入包含相同上下文。该信息只表示原文位置，不自动推断义务主体或适用结果。

`agent_tools.py` 先返回直接命中的完整原文，再返回有限的援引及相邻单元，保留检索顺序。完成原文读取时保留实际语义匹配、精确匹配等召回信息，不覆盖原件中的效力、日期或来源字段。

试验曾让部分索引的排名直接参与全库融合，法律概念问法的四条覆盖率由 2/4 降为 0/4。此方案未采用：索引不完整时只补充候选，保持原有词项及文件级排序；全量完成后沿用现有融合。紧凑失败记录为 `.dev/research/legal-retrieval-20261029/partial-full-fusion-rejected.json`，完整控制台结果保留于执行记录。词语扩展、章节加权及扩大章节召回的开发试验也未改善当前样例，未将这些参数试验写入运行服务。

本轮没有修改法律结论或自动修补法律含义。法律解释需要主 Agent 核对原文中的主体、条件和效果，将其与用户事实对应；涉及流程的条文、相邻原文和检索高分本身不能证明某项强制义务。

## 诊断与复现

新增 `scripts/evaluate_legal_retrieval.py` 和 `backend/tests/fixtures/legal_retrieval_diagnostics.json`，使用现有搜索和不可变原文，记录条文 Recall、Precision、首个相关条文倒数排名、未覆盖条文、原文字符量及召回结果。字符占比按整条原文计算，与 LegalBench-RAG 的最小金标准字符范围不同，不能宣称已复现该论文分数。指标实现为本项目独立实现。

默认命令禁用所有外部向量及排序请求，只测本地词项基线：

```sh
uv run --project backend --locked python scripts/evaluate_legal_retrieval.py \
  --data-dir .dev/real-user/data \
  --cases backend/tests/fixtures/legal_retrieval_diagnostics.json \
  --report .dev/research/legal-retrieval-20261029/retrieval-lexical.json
```

显式传入 `--with-providers` 才加载当前实例环境并允许调用已配置的向量、排序服务。实例选择仍通过现有 `TEA_ENV_FILE`、`TEA_DATA_DIR` 完成；报告不保存密钥。真实 MCP 工具的调整前结果为 `live-retrieval.json`，调整后为 `live-retrieval-after.json`，同处上述独立参考目录。该实例未配置独立重排序服务，查询实际使用文件级、部分条款级语义与词项候选。

本轮三个查询的预期条款覆盖率，调整前与最终实现均为 0/4、2/4、1/1。最终实现的 MCP 检索耗时分别为 10.086、8.075、8.586 秒；调整前为 3.219、1.804、2.896 秒。这是单次开发样例，不能据此判断总体速度或准确率。部分索引现在可以被实际使用，但本题的日常问法仍未改善；索引覆盖、排序和模型选条仍待解决。

取得完整原文后的分析与自行检索分开测量：`interpretation-cases.json` 的 F01 提供四条原文并固定事实，U01 使用原货款问题。测试经当前 HTTP/SSE 会话、真实主模型与实际工具执行，报告为 `live-interpretation.json`。引用可追踪、条件保留、不得补造违约金比例和不反复索要已给定事实分别人工检查。结果在运行完成后记录于下文。

| 真实问答 | 耗时与调用 | 实际表现 | 评阅 |
| --- | --- | --- | --- |
| F01：完整事实及四条原文已提供 | 19.020 秒，1 次主模型，无工具调用 | 付款与违约的基本判断能够对应原文；没有要求重新证明已经给定的假设。但将违约金、利率约定情况未知写成“未约定”，另加“法定利率为 LPR”等原文未支持的内容；分段重复 | 请求完成、法律质量未通过；提供正确原文仍不足以避免事实增写和无依据的扩展 |
| U01：自行找法 | 29.016 秒，3 次主模型，2 次精确查询 | 实际取得第 580—585 条。正文将第 582 条概括用于不付款，遗漏第 577、579、628 条等直接付款与违约依据；第 580 条明确针对非金钱债务。输出未使用来源编号，引用关联为空 | 请求完成、选条与引用未通过；没有超时仍不能记为法律验收成功 |

两题均经当前统一会话出口保存，执行状态为 `answered`；该状态只代表本次交付程序完成。F01 的原文属于题目提供材料，工具证据数组为空符合预设；U01 取得六条工具证据却没有最终引用关联，属于引用使用缺陷。本轮重新访问最高人民法院原文链接时发生超时，不能据本次网络访问宣称已完成 2026 年现行版本核验。

本次影响范围检查共 128 项通过，覆盖部分向量检查点、空向量跳过、来源与模型不匹配、原件版本及法域隔离、标题上下文、命中顺序、来源保留和现有 Agent 调用。Ruff 格式与静态检查另行执行。前端、数据库结构、模型设置、用户业务状态和历史分析均未因本轮研究改动。

目前有依据的判断是：条款级索引的可用性与证据交接已修复，但本例的日常问法召回和模型解释尚未通过。继续改进应使用当前保留的输入、原文及答复分别检查检索和解释，优先提高对义务主体、付款请求、例外条件及已知事实的对应能力。不能将增加向量数量、引用编号存在或工程检查通过直接计为法律准确率提高。
