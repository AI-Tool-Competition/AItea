# 固定范围的识别与恢复

`scripts/process_frozen_parse.py` 只处理冻结清单中仍位于 `parse` 阶段的文档。
完成正文后停在 `embed` 队列；该入口禁止下载和调用 embedding。
共享库允许另一个工作进程同时处理不同 ID 的向量任务。

输入快照包含 `initial-report.json`、`initial-parse-ids.json` 和
`initial-parse-documents.json`。报告绑定两个清单的 SHA256、账号和数据库目录；
文档守卫绑定不可变版本、原件 hash、来源、metadata 和已成功页。
快照由操作者在首次领取前用只读事务保存，续跑使用同一快照，不能重新扫描扩大授权范围。

```bash
uv run --project backend python scripts/process_frozen_parse.py \
  --data-dir /path/to/library \
  --snapshot /path/to/frozen-parse-snapshot \
  --models-env /path/to/private-models.env \
  --run-id continuation-001 \
  --ocr-workers 4 --ocr-start-workers 1 \
  --document-workers 4 --claim-limit 60 --seconds 600
```

每次使用新的 `run-id`。`--document-ids` 可进一步限定最多 20 个冻结 ID。
`--ocr-workers` 支持 1–64，`--document-workers` 支持 1–32，默认均为 2。
`--ocr-start-workers` 可从 1 起步但不能超过 OCR 最大并发；未指定时沿用共享额度的自适应起点。
例如 `--ocr-workers 64 --ocr-start-workers 16 --document-workers 16` 允许跨文档填满 64 个识别槽，
仍保持单文档每批最多 4 页、共享处理任务额度、限流退避和原有页级质量门禁。
应按供应商成功率逐步提高实际并发；此上限不保证供应商持续吞吐，也不代表识别内容已经通过校验。
同一快照有进程锁；报告保存领取范围、实际 HTTP 状态、并发峰值、页完成数和未通过质量门禁的页数。
`metric_schema_version: 2` 的报告以本次运行每份文档首次领取前的状态为增量基线，
保存在原子写入的 `run-baseline.json`，同时绑定版本、原件与 manifest SHA256。
同一次运行重复领取不会重置基线；正文和识别页的增量不会重复计算以前运行的成果。
`new_request_pages_not_accepted` 只统计本次调用模型所涉及、当前仍失败或待核对的物理页，
同页多次局部请求只算一页；`request_started` 事件记录调用范围，旧失败无新请求时不计入该字段。
缺少该版本字段的旧报告使用初始冻结快照作为页统计基线，不能直接当作本轮增量相加。
轮转计数持久化，长文不会因短文优先被永久排除。运行中收到 SIGTERM/SIGINT 后停止新领取，
等待已有请求和受限解析结束，继续维护租约并保存检查点。
领取和心跳使用共用的本地事务重试：只重试已回滚的 SQLite 忙锁，最多 3 次，
各次沿用数据库 15 秒等待上限并记录等待。超过上限停止新领取并排空在途工作；
模型调用不在数据库重试范围内。
硬中断后，入口只在原冻结 ID 内发现已过期的 `parse` 租约，再由既有任务服务回收；
有效租约、其他账号、向量任务和失败任务不因此重置。未保存结果的付费请求仍停止自动重发。

在同一命令追加 `--supervise` 可无人值守地衔接这些有界窗口。此时 `--run-id`
是本次监督的固定前缀，监督器为每个子进程生成新的序号和随机后缀；`--seconds`、
`--claim-limit` 仍是单窗口上限，窗口结束后须先排空、核对终态报告和整个冻结范围，
再启动下一轮。短文和长文沿用同一份持久轮转计数，已完成正文不会被领取去做向量。
同一快照的监督锁防止双开；每个子进程在启动前已继承原有的识别运行锁，
因此父进程在启动与写入 PID 之间被杀掉，重新启动也会等待旧子进程释放锁。
SIGTERM/SIGINT 停止新窗口并请求已核实身份的子进程排空；不会按进程名停止其他任务。

监督状态写入快照下的 `supervisor-state.json`，状态转换另存
`supervisor-events.jsonl`。`supervisor-binding.json` 绑定账号、数据目录、冻结清单、
选择范围、运行参数，以及模型配置文件和两个运行脚本的 SHA256，不保存密钥内容。
`supervisor-success-pages.json` 累积保存每轮已接受页的摘要，后续窗口和重启都继续校验；
每轮还重新核验原件字节、来源元数据和初始成功页。上述文件、`runs/`、
`dispatch-counts.json` 和 `provider-cooldown.json` 应随恢复账本一同备份。
正常重启使用原命令和原快照；配置、代码或范围变化会停止运行，需要先核验并显式交接，
不能靠删除状态文件或重新扫描清单解除守卫。
若状态文件本身损坏，原文件保持不动，诊断另写 `supervisor-startup-error.json`，不会创建空白运行账本。

| 状态 | 含义与后续行为 |
| --- | --- |
| `running` / `waiting_child` / `draining` | 当前窗口仍持有识别锁，等待排空，不启动第二个窗口。 |
| `cooldown` | 尊重供应商等待时间、任务 `available_at` 和未过期租约；本地忙锁或空窗口有退避。 |
| `completed` | 整个冻结范围的正文均通过现有质量门禁；不表示向量、法律审核或全量采集已完成。 |
| `blocked_unknown` | 请求结果未知，或某个已启动窗口缺少可信终态回执；保留意图，不自动重发。 |
| `blocked_quality` | 结果已保存，但正文完整性、数字或来源质量仍未通过；不自动反复识别同一页。 |
| `blocked_inputs` | 剩余任务需要显式恢复、来源补齐或重试预算复核；不重置失败任务。 |
| `failed_configuration` | 配置、快照、原件或成功页守卫不成立；停止付费处理并保留失败状态。 |
| `stopped` | 操作者要求的排空已完成，使用同一冻结命令可以继续。 |

已知质量问题和已知结果未知的文档会被保留，范围内其他安全的排队文档仍可完成。
当没有安全任务可续跑时，待核验状态以非零退出码返回。若整个窗口没有终态报告，
则暂停所有后续窗口；页数变化或进程消失都不足以证明上一轮已排空并保存全部回执。
模型返回 HTTP 200 但 `complete=false`、地图没有可验证文字等情况属于质量待处理，
不计为正文完成，也不自动启用无限区域重试。429 只沿用原处理队列的有界重试，
到期失败或预算耗尽后保持待恢复状态。

监督回归使用隔离 SQLite、真实子进程和本地假响应，覆盖跨窗口、强制中断、
启动与 PID 持久化间隙、冷却、质量/未知结果保持，以及不同向量任务范围保全。
实际解析链测试还经过受限 PDF 渲染、CAS 图像和页级检查点；这些本地检查不证明供应商吞吐。

429/5xx 的 `Retry-After` 使用秒数或 HTTP 日期；页/区域检查点及运行目录同时保留等待时间。
并发可以降到 1；续跑用 `--ocr-start-workers` 延续观察到的容量。
文档领取数量随实际识别容量收缩，避免等待容量的任务反复空转。

已成功页不会重新请求。完整页和局部裁剪在外部调用前保存原件、物理页、像素 hash 和 request ID；
错误响应使用账号 CAS 保存有界原始字节，重试追加旧检查点，保留旧失败和裁剪历史。
连接建立失败可以有界重试。读/写/协议异常以及中断后只剩请求意图的状态可能已经计费，
会停止自动重发并标记结果未知。它们需要核验后另行显式恢复。
普通采集任务的“重试”也不会清零结果未知的页、裁剪区域或原生图片检查点。
明确失败的页或图片在人工重试前追加完整旧尝试，成功页不变；有界历史已满则停止重置。
即使旧版普通重试曾清零尝试数，页级入口仍按未知结果标记拒绝发起新请求。
正式批量入口对 408/5xx 也采用结果未知的保守边界，保留响应及等待时间并停止该页自动重发；
429 仍按明确拒绝和 `Retry-After` 有界重试。通用识别服务的默认重试行为保持兼容。
旧 408/5xx 待重试页追加暂停检查点，原响应 CAS、请求号、尝试数与完整旧页保留，其他页继续处理。

`app.contexts.documents.infrastructure.recovery.ocr_response_reparse.apply_saved_response_reparse` 可离线重解析已完整保存的错误响应。
仅接受当前提示版本、完整未截断正文以及仍匹配账号、原件、版本、manifest、请求和像素的证据。
合法格式包装只允许外层恰好为 `type: "json_object"` 和对象类型 `content`；
内层仍执行严格字段、类型、数字、表格和完整性检查。
函数默认 dry run，apply 保留原 request ID、attempts、原始错误 CAS 和完整旧失败页，
不创建新的模型请求；旧 manifest 重放会冲突。未通过质量门禁的内容继续待审。

金额比较只可排除与原件 hash、物理页、native 全文 hash 和既有可见性审计一致的唯一页外对象。
对象须完整离开页面、无裁切或遮挡等其他风险；页内也出现相同金额时仍保留比较门禁。
原生文本、可见性证据、OCR 原文和旧请求保持，局部恢复复用同一规则，避免请求不存在于页内的金额。
其他数字、姓名、表格及模型自身的不确定内容仍需原有校验；该规则不把原生文字整体判为可见。

这套恢复只改变派生文本与处理队列，不审核法律效力，不改原件、来源版本或法律关系。
HTML 中尚未绑定的外部图片仍需要独立采集与映射，不能用页面截图代替缺失原件。
