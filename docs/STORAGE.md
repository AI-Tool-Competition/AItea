# 资料存储与盘点

一个运行实例使用一个 `TEA_DATA_DIR`，默认是本工作树的 `data/`。抓取原件、上传文件、解析结果、版本、关系和采集记录均归入这个数据根。开发工作树使用自己的数据目录；生产资料应固定在正式实例的数据根，不混入临时工作树。

已有数据的部署在后端环境设置 `TEA_REQUIRE_EXISTING_DATA=true`。启动前检查已有数据库、结构标记与原件目录，缺失或未初始化时拒绝启动，不创建目录或空库；首次建立全新实例才使用默认的 `false`。这个设置不会跳过正常的版本升级，也不替代完整备份校验。

运行中的数据库连接只打开已有文件，并检查数据库及原件目录的文件系统身份。数据目录丢失、数据库文件被清空或路径被另一份副本替换时，后续连接拒绝工作，健康接口返回 HTTP 503 `database_unavailable`。恢复到另一份已验证副本后需要重启所属服务，不能让旧进程继续持有原路径身份。健康检查仅核对存储及基本结构，不扫描全部原件，也不证明采集、向量或法律审核已完成。

正常连接采用 SQLite 的 [`mode=rw`](https://www.sqlite.org/uri.html)，只有显式初始化可创建新库。保护检查不授权移动正在使用的数据库；[SQLite 官方说明](https://www.sqlite.org/howtocorrupt.html#unlinking_or_renaming_a_database_file_while_in_use)要求避免运行中删除或重命名数据库，正式路径切换仍先停止所属实例并使用完整备份恢复。

项目所在磁盘不足时，经部署方授权可使用另一块可写磁盘上的独立目录。明确记录数据根、用途、所有权、权限和项目指针，区分活动采集、恢复、备份与可清理缓存；不要通过随意移动单个哈希文件改变引用。2026-10-19 的两国采集与正式实例的数据位置、切换及存储异常见 [本轮验证与存储交接](COMPLETE_INGESTION_VALIDATION.md)。系统临时目录中的溢出数据需要保留期安排，不能作为唯一长期备份。

```text
data/
├── tea.sqlite3                      # 资料、正文、向量、版本、国别、关系和任务
├── files/
│   ├── blobs/<账号哈希>/<哈希分片>/<内容哈希>  # 只读原件、目录证据、分段及 OCR 图片
│   └── .staging/                    # 正在下载的临时文件
└── catalogs/<快照标识>/
    ├── summary.json                 # 盘点范围、数量和异常统计
    ├── COMPLETE                     # 整份目录已生成
    └── <账号哈希>/<国家代码或unassigned>/
        ├── documents.jsonl          # 每个资料版本一条记录
        ├── relations.jsonl          # 一二级关系，两端固定版本
        ├── discovery-pages.jsonl    # 目录页及官方 API 请求、分页证据
        ├── ocr-pages.jsonl          # OCR 整页图到原件版本、页码的映射
        └── ocr-regions.jsonl        # 复核裁图到原件版本、页码、区域的映射
```

原件按内容哈希寻址，同账号的相同字节只保存一份；不同账号独立保存。法规名称、来源、国别、采集条目和版本保存在数据库，不能靠移动或改名哈希文件来调整分类。旧平铺原件保留已有路径，不在启动时搬迁。

国别是资料及版本家族的不可变属性。资料库按国家查找，采集清单按国家、章节和条目管理；一二级关系指向同国的确切版本。相同原件可被多个来源记录引用，但国家、审核、分级和历史关系分别核验。解析正文、页状态与来源定位保存在版本 manifest；切片、FTS5 和 float32 向量位于独立索引表，通过文档 ID、切片 ID、输入哈希与模型指纹关联。目录页证据不会进入正文检索。

OCR 整页图及复核裁图与原件使用同一内容寻址存储，不分散到临时图片目录。每个页面记录源文件哈希、页码、图片哈希及相对数据根的路径；裁图另记原 PDF 坐标、区域标识、读取轮次及模型/配方版本。模型调用前先保存图片引用和尝试检查点，成功后保存页面或区域结果。整页图、原文层、完整转录历史及区域复核证据不被覆盖；可校验的成功区域读取可用于恢复。解析结果可重建，法规原件及历史版本不被覆盖。向量不内嵌在 JSON，也不在接口中返回。

结构版本 12 的慢原件下载检查点保存在 `collection_transfers`/`collection_transfer_parts`，分段字节也集中进入账号 CAS。记录固定最终 URL、强 ETag、总长度、偏移、大小和哈希；旧下载版本及分段保留，不与新版本拼接。分段是恢复缓存，不能当作完整法规或产生文档引用；连续完整、逐段校验并原子组装后才发布原件。普通上传仍限 20 MiB/300 页，来源可配置原件至 128 MiB；大采集 PDF 在原件位置按最多 64 页窗口读取，保存完整物理页检查点，无须另存重复的大文件。

## 导出可读目录

在仓库根目录运行：

```bash
make archive-inventory COUNTRY=ID
make archive-inventory COUNTRY=ID OWNER=实际账号ID
make archive-inventory
```

最后一条导出全部账号和国家，适用于有本地数据访问权限的运维人员。指定其他正式数据根时，使用 `TEA_DATA_DIR=/绝对路径 make archive-inventory COUNTRY=ID`。此命令以目录格式版本 4 读取结构版本 7–19 的数据库，清单记录实际版本；不启动服务、不升级结构、不触发抓取、解析或模型调用。

导出使用同一个数据库只读快照，并逐批写入清单。完成后原子发布一个新的快照目录；不会覆盖以前的盘点，也不会修改或复制原件。目录按账号、国家分开，每份版本列出名称、来源网址与清单条目、法规家族、版本号、分级、标签、解析完整性及审核状态、内容哈希、原件相对路径和文件异常。固定版本关系逐条写入独立清单；普通附件继承父资料国家。`ocr-pages.jsonl` 记录整页来源映射，`ocr-regions.jsonl` 记录复核裁图的来源版本、页码、坐标、轮次、图片/读取哈希与模型信息，均不含转录正文。发现页另列来源计划、版本和条目；结构版本 11 还保存受限的官方 API 方法、筛选参数与分页分母，不能当作已取得的法规。

格式 4 另导出 `catalog-documents.jsonl`，逐页保留 TreatyRoom 的条约身份、经过白名单筛选的原始元数据、四个文件槽、候选用途及缺失字段。每条绑定账号、国家、冻结方案、来源页 ID、URL、内容哈希和原始页相对路径，不进入正文解析或检索。每页最多 40 条，单行至多 32 KiB；无效或过大的记录写明缺口并保留原始页定位。通用目录证据仍受 16 KiB 上限，只有经过方案、条目、主机和请求校验的 TreatyRoom 公开目录可读取至多 4 MiB 的来源证据；请求和分页标量不会因条约数组较大而被整体丢弃。来源页的重复条约身份按原样保留，导出行数不能替代全目录去重与完整性核对。

WTO 同一出口仅接收新冻结方案中经过成员、目录、公开请求和 CAS 哈希核验的两项，逐条保留商品程序、文书符号、认证/修订/语种、原件 URL、别名及父页指针。坏记录写显式缺口；成员压缩包仅作来源审计，文件格式和条约生效状态不由目录推断。

默认盘点不包含正文；采集任务可以显式使用 `include_text=True` 追加私有 `texts.jsonl`，记录两级法律用途的已保存文本、完整性与定位，不含向量。普通关联附件仍仅存原件。

需要正文和来源映射时，从 `backend/` 执行 `uv run --locked python -m app.archive_inventory --data-dir /受控数据根 --include-text --include-source-mapping`。开启来源映射时使用目录格式 5，额外生成 `source-mapping.jsonl`，将原件版本、页、区域、表格/单元格、正文块及保存的证据指针投影为可检查记录；映射缺口单独统计，不推断缺失内容。目录写到该数据根的 `catalogs/`，不修改数据库；需要冻结活动库时，先使用已验证备份恢复一个独占快照再导出，并保留其原件根，不能删除快照后留下失效路径。

用编辑器或数据工具打开 JSONL 即可定位原件，无须辨认哈希文件名。默认清单不包含正文，显式文本导出也不含向量或模型凭据。导出目录权限为 `700`，文件为 `600`；它包含私有资料的名称与来源，只交给有权限的人员。

盘点数量代表数据库已有记录，不代表某国家或官方站点已采集完整。原件缺失、越界路径等会留在异常统计中；内容哈希引用数据库记录，不表示重新扫描并校验了全部原件字节。目录快照不能代替原件和数据库备份。

## 备份与维护

- 一起备份 `tea.sqlite3` 和 `files/`。停止该实例后备份，或使用 SQLite 在线备份接口取得数据库快照，再保留其引用的不可变原件；不要只复制运行中的 SQLite 主文件。
- 保留法规旧版本、固定版本关系和审核历史。原件被多个版本复用时，不能按某一条记录的状态删除文件。
- `.staging/` 或未引用文件可能来自中断任务。分段和 OCR 区域对象还可能被下载检查点或转录历史引用。当前不自动删除；先停止所属实例并核对全部引用及任务状态，再制定清理范围。
- 完整实例备份、校验与迁移使用 [DATA_BACKUP.md](DATA_BACKUP.md) 的运维工具；恢复到新目录时重定位明确的数据库路径字段，保留原件、向量和证据字节，并验证数据库引用、国家范围和版本关系。运行状态与日志位于 `.dev/`，不能把清理日志等同于重置 `data/`。

共享法规与私有上传的权限、数据分层及升级边界见 [数据体系](DATA_PLATFORM.md)。队列、大小、并发和重试边界见 [采集说明](INGESTION.md)。结构 19 的长期退避、失败历史、未知付费结果与迁移限制见 [持久恢复](COLLECTION_RECOVERY.md)。
