# 资料存储与盘点

一个运行实例使用一个 `TEA_DATA_DIR`，默认是本工作树的 `data/`。抓取原件、上传文件、解析结果、版本、关系和采集记录均归入这个数据根。开发工作树使用自己的数据目录；生产资料应固定在正式实例的数据根，不混入临时工作树。

```text
data/
├── tea.sqlite3                      # 资料、正文、向量、版本、国别、关系和任务
├── files/
│   ├── blobs/<账号哈希>/<哈希分片>/<内容哈希>  # 只读原件及目录页证据
│   └── .staging/                    # 正在下载的临时文件
└── catalogs/<快照标识>/
    ├── summary.json                 # 盘点范围、数量和异常统计
    ├── COMPLETE                     # 整份目录已生成
    └── <账号哈希>/<国家代码或unassigned>/
        ├── documents.jsonl          # 每个资料版本一条记录
        ├── relations.jsonl          # 一二级关系，两端固定版本
        └── discovery-pages.jsonl    # 目录页证据，单独记录
```

原件按内容哈希寻址，同账号的相同字节只保存一份；不同账号独立保存。法规名称、来源、国别、采集条目和版本保存在数据库，不能靠移动或改名哈希文件来调整分类。旧平铺原件保留已有路径，不在启动时搬迁。

国别是资料及版本家族的不可变属性。资料库按国家查找，采集清单按国家、章节和条目管理；一二级关系指向同国的确切版本。相同原件可被多个来源记录引用，但国家、审核、分级和历史关系分别核验。解析正文和向量保存在对应版本的结构记录中；目录页证据不会进入正文检索。

## 导出可读目录

在仓库根目录运行：

```bash
make archive-inventory COUNTRY=ID
make archive-inventory COUNTRY=ID OWNER=实际账号ID
make archive-inventory
```

最后一条导出全部账号和国家，适用于有本地数据访问权限的运维人员。指定其他正式数据根时，使用 `TEA_DATA_DIR=/绝对路径 make archive-inventory COUNTRY=ID`。此命令读取结构版本 7、8 或 9 的数据库，清单记录实际版本；不启动服务、不升级结构、不触发抓取、解析或模型调用。

导出使用同一个数据库只读快照，并逐批写入清单。完成后原子发布一个新的快照目录；不会覆盖以前的盘点，也不会修改或复制原件。目录按账号、国家分开，每份版本列出名称、来源网址与清单条目、法规家族、版本号、分级、标签、解析及审核状态、内容哈希、原件相对路径和文件异常。固定版本关系逐条写入独立的关系清单；普通附件继承父资料国家。发现页另列来源计划、版本和条目，不能当作已取得的法规。

用编辑器或数据工具打开 JSONL 即可定位原件，无须辨认哈希文件名。清单不包含正文、向量或模型凭据。导出目录权限为 `700`，文件为 `600`；它包含私有资料的名称与来源，只交给有权限的人员。

盘点数量代表数据库已有记录，不代表某国家或官方站点已采集完整。原件缺失、越界路径等会留在异常统计中；内容哈希引用数据库记录，不表示重新扫描并校验了全部原件字节。目录快照不能代替原件和数据库备份。

## 备份与维护

- 一起备份 `tea.sqlite3` 和 `files/`。停止该实例后备份，或使用 SQLite 在线备份接口取得数据库快照，再保留其引用的不可变原件；不要只复制运行中的 SQLite 主文件。
- 保留法规旧版本、固定版本关系和审核历史。原件被多个版本复用时，不能按某一条记录的状态删除文件。
- `.staging/` 或未引用文件可能来自中断任务。当前不自动删除；先停止所属实例并核对数据库引用及任务状态，再制定清理范围。
- 恢复时保留原数据根路径，并验证原件与数据库引用、国家范围和版本关系。运行状态与日志位于 `.dev/`，不能把清理日志等同于重置 `data/`。

队列、大小、并发和重试边界见 [采集说明](INGESTION.md)。
