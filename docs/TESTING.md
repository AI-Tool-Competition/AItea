# 测试范围与维护

[文档中心](README.md) · [开发环境](DEVELOPMENT.md) · [工程规范](../AGENTS.md)

后端默认检查是 `make backend-check`，运行现有业务测试和 Python 静态检查；`make check` 同时运行前端类型与茶业务交互检查，集成前再执行 `make build`。所有测试使用隔离目录和模拟供应商，不能读取真实凭据或消费模型额度。

测试收集阶段使用 `tests/fixtures/environment.env` 的空配置；每个用例明确覆盖供应商凭据与队列容量，避免本机调优参数影响远端结果。代理测试同时覆盖没有代理和显式代理的环境，不假定 CI 存在 `HTTP_PROXY`。`test_instance_storage.py` 验证私有配置归集、完整备份校验、恢复路径重定位，以及历史资料、采集退避和向量冷却的保留；新实例释放旧机器进程租约。

现行云端流程由 `test_mineru_ragflow.py` 覆盖，不把网络服务缺失解释为检索成功。当前用例数量以相应提交的测试输出为准。

## 保留的验证范围

保留的主要风险边界：

| 范围       | 验证内容                                                             |
| ---------- | -------------------------------------------------------------------- |
| 账号与业务 | 归属隔离、登录/管理员权限、任务门禁、修订冲突、消息幂等              |
| 法律与历史 | 审核/适用期、冻结流程、不可变资料/文稿版本、旧证据保存               |
| 解析与索引 | MinerU 原件/页码绑定、表格与图片证据、RAGFlow 回执恢复及二次权限核对 |
| 采集       | 公网/重定向/代理边界、来源关系、配额、并发、取消恢复、清单动态更新   |
| 存储       | 空库和旧库升级、事务回滚、原件完整性、备份/恢复                      |
| 架构       | 领域层依赖、HTTP 不访问持久化、顶层只保留装配入口                    |

`tests/support` 保存仍被迁移、预览或历史版本测试使用的样本构造器，以及显式的 RAGFlow 内存 HTTP 模拟器。业务权限测试通过真实索引写入和查询链路消费模拟回执；供应商超时、未知结果和配额由独立云端契约测试覆盖。历史向量与解析证据的持久化测试应直接准备历史快照，不能借新上传入口触发已经退出主流程的处理方式。增加测试应围绕新的风险或用户行为；一个表驱动场景能表达的边界不再拆成多个重复文件。并发参数覆盖最小值、默认值、代表值、上限和非法输入，不逐整数重复；真实多进程组合只保留一组容量，完整手册路线只跑最长的一条，其余路线保留配置与门禁检查。

本地全绿不代表真实 MinerU/RAGFlow 服务、全部来源网站或付费模型吞吐已验收。部署后需单独观察真实回执、来源健康与任务状态，不能通过重置请求账本加速验证。

`verify_ingestion.py` 在未显式启用真实供应商时只验收原件、去重、持久化和权限门禁，报告 `validation_scope=ingestion_only`、`retrieval_verified=false`；不会把无检索结果写成召回验收成功。
